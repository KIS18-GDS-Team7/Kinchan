# ドキュメントでは人間的な表現を使わない

## ステータス
決定

## 背景
- 2026/10/08 の講師レビューにて、要件定義書のユースケース名・機能要件に「〜を確認する」などの表現が混在している点を指摘された
- 「確認する」「把握する」「チェックする」はアクター(人間)の認知行動であり、システムが提供する振る舞いではない
- ユースケース・機能要件はシステムの振る舞いを定義するものなので、主語をシステム側に揃えないと実装・テストの対象が曖昧になる

## 決定
- ユースケース名・機能要件・画面仕様などシステムの振る舞いを記述する箇所では、人間の認知・判断を表す表現を使わず、システムの動作で記述する
- 例: `docs/requirements/requirements.md` では「〜を確認する」を「〜を表示する」に揃える
  - UC-206 「シフト希望を確認する」 → 「シフト希望を表示する」
  - UC-213 「勤務実態を確認する」 → 「勤務実態を表示する」
  - FR-008 「シフト希望を確認・承認・却下」 → 「シフト希望を表示・承認・却下」
- 他の言い換え例
  - 「〜を把握する」 → 「〜を表示する」「〜を集計する」
  - 「〜を判断する」 → 「〜を判定する」「〜を検証する」
  - 「〜に気づく」 → 「〜を通知する」
- 既存ドキュメントの修正は本ADRの適用対象とし、別PRで実施する
