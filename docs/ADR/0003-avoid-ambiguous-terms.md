# ドキュメントでは解釈が分かれる語彙を使わない

## ステータス
提案

## 背景
- [#61](https://github.com/KIS18-GDS-Team7/Kinchan/issues/61) にて、UC-303 / FR-012「マイページを表示する」の「マイページ」が何を指すのか、メンバー間で認識が揃っていないことがわかった
  - ログイン後に遷移するページ(打刻ページ)と捉える人
  - 個人の勤務実態やシフトを表示するページと捉える人
- 「マイページ」のように、一般的なWebサービスで使われていても指す対象がサービスごとに異なる語は、読み手ごとに想像するものが変わる
- 要件定義書・UCドキュメントは実装・テストの根拠になるため、語が指す対象が一意に決まらないと各自の解釈で作業が進んでしまう
- 関連: [ADR-0002](./0002-avoid-human-centric-expressions.md)(人間の認知・判断を表す動詞を使わない)。ADR-0002 は動詞の選び方、本ADRは名詞(画面名・機能名など)の選び方を扱う

## 決定
- 要件定義書・UCドキュメント・画面仕様などでは、読み手によって指す対象が変わる語彙を使わない
- 画面名・機能名など、ドキュメント間で共通して使う語は 4章 用語集 で定義し、定義した語だけを使う
- 例: `docs/requirements/requirements.md` の「マイページ」は使わない
  - UC-303 「マイページを表示する」 → TBD(#61 で表示内容を決めてから命名する)
  - FR-012 「マイページを表示」 → TBD(同上)
- 既存ドキュメントの修正は本ADRの適用対象とし、別PRで実施する
