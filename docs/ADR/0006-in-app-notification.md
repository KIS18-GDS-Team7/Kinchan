# 通知はアプリ内だけで提示し、勤怠管理者にも申請の送信を通知する

## ステータス

決定

## 背景

- 通知の届け方は、各 UC の備考で「アプリ内通知、メールなど」として TBD だった。検討した案は (a) アプリ内の通知欄だけ、(b) 通知欄に加えて PWA と Web Push で端末にも届ける、(c) メール の 3 つ ([#80](https://github.com/KIS18-GDS-Team7/Kinchan/issues/80))。
- 要件定義書で通知が出てくるのは、従業員に承認・却下の結果を通知する UC だけだった。通知を受け取って表示する UC はなく、勤怠管理者に新しい申請を知らせる記述もなかった ([#81](https://github.com/KIS18-GDS-Team7/Kinchan/issues/81))。
- モックの案A は、従業員にはヘッダーのベルと通知一覧で通知し、勤怠管理者には通知せずに未処理の件数を表示していた (判断ログ A-3・A-4)。勤怠管理者を含めて通知欄に通知する案も出ていた。
- [#83](https://github.com/KIS18-GDS-Team7/Kinchan/issues/83) で、すべてのユーザーが従業員として振る舞えることになった ([#97](https://github.com/KIS18-GDS-Team7/Kinchan/issues/97))。
- データベースの設計 ([#100](https://github.com/KIS18-GDS-Team7/Kinchan/issues/100)) は、通知の宛先と内容を前提にする。

## 決定

- 通知はアプリ内だけで提示する。PWA と Web Push による端末への通知、メールによる通知は行わない (#80 の (a)、#81、2026/10/21)。
- 画面に通知の件数を提示する。#81 では案A と同じく画面右上のベルとしたが、配置は画面設計で扱う。
- 従業員と勤怠管理者の両方に同じ仕組みを用意する。通知を表示する UC として UC-317「通知を表示する」を新設する (#81、#97)。
- 勤怠管理者には、管理先の従業員が勤怠修正申請・シフト希望・シフト日時変更申請を送信したことを通知する ([#96](https://github.com/KIS18-GDS-Team7/Kinchan/issues/96)、2026/10/22)。
- 従業員が申請・シフト希望を取り下げたことは、勤怠管理者に通知しない (2026/10/22 の会話)。
- 通知する内容の一覧は UC-317 の備考に書く。
- 通知に既読の状態を持たせるか、件数を未読の件数にするかは、この ADR では決めない (#100 の [3])。
