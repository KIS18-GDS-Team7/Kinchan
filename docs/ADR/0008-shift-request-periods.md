# シフト希望の対象期間と受付期間は勤怠管理者が登録する

## ステータス

決定

## 背景

- シフト希望を送信する UC-307 は、対象期間 (翌月など) の分をまとめて送信する書き方だった。一方で、受付期間・締切と、それを登録する UC がなかった ([#88](https://github.com/KIS18-GDS-Team7/Kinchan/issues/88))。
- 検討した案。
  - モックの案A。翌月分を当月 1〜20 日に受け付ける固定の期間にする (判断ログ A-39)。
  - 当日から 2 週間以上先を常に受け付け、2 週間未満は締め切る案。従業員の融通が利く。
- 月単位で固定すると、2 週間ごとなど月以外の単位でシフトを組む場合に対応できない。日ごとに受付期間がずれる形にすると、勤怠管理者がシフト希望を処理する負担が大きくなる。
- データベースの設計 ([#100](https://github.com/KIS18-GDS-Team7/Kinchan/issues/100)) は、対象期間と受付期間の持ち方を前提にする。

## 決定

- 勤怠管理者が、シフト希望の対象期間と受付期間を対で登録する (#88、2026/10/21)。対象期間はシフト希望が対象とする勤務日の範囲、受付期間はその対象期間のシフト希望を送信できる期間である。
- 登録する UC として UC-215「シフト希望の対象期間・受付期間を登録する」を新設する (#88)。
- シフトの登録・変更とシフト日時変更申請で扱う勤務日は、対象の従業員の所属に登録された対象期間に含まれる日に限る (2026/10/22 の会話)。
- 登録の単位や期間の重なりの扱いなどの詳細は UC-215 の備考に書く。
- 対象期間・受付期間の変更・削除と、所属や期間を変えた後の既存のシフト・申請の扱いは、この ADR では決めない (#100 の [6])。
