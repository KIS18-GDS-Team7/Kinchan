# 勤怠修正申請に送信の期限を設け、勤怠管理者による修正は止めない

## ステータス

決定

## 背景

- 勤怠の締め (勤怠を確定し、以後の修正を止めること) を設けるかが決まっていなかった。勤怠修正申請を承認する UC と勤怠を直接修正する UC の備考では、給与計算の締め処理が終わった月の修正の扱いが TBD で、締め処理そのものの UC もなかった ([#85](https://github.com/KIS18-GDS-Team7/Kinchan/issues/85))。
- 勤怠修正申請をいつの分まで送信できるかも TBD で、締めの時期と関係していた (#85)。
- 検討した案。
  - 月初めの 10 日後に締め、前月分の勤怠修正申請は翌月 10 日まで送信できる案。月末の修正ができなくなることを避ける。
  - モックの案A。締め処理は作らず、全期間を修正できる (判断ログ A-7)。勤怠修正申請は前月 1 日〜当日を対象にする (判断ログ A-50)。
- データベースの設計 ([#100](https://github.com/KIS18-GDS-Team7/Kinchan/issues/100)) は、勤怠修正申請の期限の判定に使う値を前提にする。

## 決定

- 勤怠修正申請を送信する (UC-306) の期限を次のとおりとする (#85、2026/10/21)。
  - 当月分はいつでも送信できる。
  - 前月分は当月 N 日まで送信できる。
  - 前々月以前の分は送信できない。
- 期限は従業員の勤怠修正申請だけに設ける。期限を過ぎても、勤怠管理者は従業員の勤怠を修正する (UC-210) で勤怠記録を修正できる (#85)。勤怠記録の修正を止める締め処理は設けない。
- N の値は、この ADR では決めない (#100 の [9])。
