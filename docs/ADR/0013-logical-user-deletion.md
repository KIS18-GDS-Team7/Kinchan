# ユーザーの削除は論理削除とする

## ステータス

決定

## 背景

- ユーザーの削除を物理削除にするか論理削除にするかが決まっていなかった。削除したユーザーの勤怠記録・申請・今後のシフトの扱いも定義されていなかった ([#86](https://github.com/KIS18-GDS-Team7/Kinchan/issues/86))。
- 出ていた案は、どちらも論理削除だった。
  - 論理削除にする案。
  - モックの案A。論理削除とする。削除したユーザーはログインできなくし、一覧から除く (「削除済みを含める」で参照できる)。勤怠記録・申請・履歴は残し、申請中の申請は勤怠管理者が処理できる。翌日以降のシフトは削除する (判断ログ A-19)。A-19 は根拠に労働基準法 109 条 (記録の保存) を挙げている。
- データベースの設計 ([#100](https://github.com/KIS18-GDS-Team7/Kinchan/issues/100)) は、削除したユーザーのデータの持ち方を前提にする。

## 決定

- ユーザーを削除する (UC-103) は論理削除とする (#86、2026/10/21)。
- 削除に伴う扱いは、案A の A-19 に沿って UC に書く。
  - 削除済みユーザーはログインできない。ユーザー一覧を表示する (UC-107) では通常は除き、指定したときに提示する。
  - 削除済みユーザーの勤怠記録・申請は残す。「未処理」の申請の扱いは、申請の種類ごとに UC の備考に書く。
  - 削除するユーザーの勤務日が翌日以降のシフトは、削除時に削除して削除履歴に残す。
- 削除したシフトを物理削除にするか、削除済みの印を付けて残すかは、この ADR では決めない (#100 の [12])。
