# 勤務可能時間と必要人数は持たない

## ステータス

決定

## 背景

- 振り直し前の UC-112・113 で、管理者がユーザーごとに勤務可能時間を設定・変更し、範囲外のシフトは登録できないことになっていた。勤務可能時間が本人の都合 (この時間なら働ける) か、契約上の制約 (この時間しか働かせてはいけない) かは定義されていなかった ([#77](https://github.com/KIS18-GDS-Team7/Kinchan/issues/77))。
- 検討した案 (#77)。
  - (a) 本人の都合とし、従業員が設定する。範囲外のシフトも登録できる。この場合は、日ごとのシフト希望との違いも定義が必要になる。
  - (b) 契約上の制約とし、管理者が設定する。範囲外のシフトは登録できない。当時の UC の形。
  - 従業員が設定し、管理者は閲覧だけでよいという意見。範囲外を登録できないと代わりの人が入れなくなるので、制御は要検討という意見。
  - モックの案A。曜日ごとに可否と時刻を持ち、範囲外は登録できない (判断ログ A-25)。
- シフトを扱う UC の一部が人員不足を判定していたが、基準は「時間帯ごとの必要人数」とあるだけで TBD だった。必要人数を設定する UC もなかった ([#79](https://github.com/KIS18-GDS-Team7/Kinchan/issues/79))。
- 検討した案 (#79)。
  - 必要人数を設定する画面を作る案。
  - 時間帯ごとに持つ案。
  - モックの案A。店舗ごとに平日・土日祝の人数を固定し、日単位で判定する。設定画面は作らない (判断ログ A-8)。

## 決定

- 勤務可能時間は持たない。振り直し前の UC-112・113 と FR-005 を削除する (#77、2026/10/21)。v1.0 の機能に挙げていた「勤務可能時間によるシフト制限」も外す ([#6](https://github.com/KIS18-GDS-Team7/Kinchan/issues/6))。
- 必要人数と、必要人数に応じてシフトを組むときに出す警告は持たない (#79、2026/10/21)。
