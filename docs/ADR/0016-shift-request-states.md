# シフト希望は各日の希望時間帯で送信し、5 つの処理状態で扱う

## ステータス

決定

## 背景

- シフト希望の希望条件には、時刻を入れない「出勤可能」の希望があった。これを承認したときにシフトの時刻をどう決めるかが書かれていなかった ([#89](https://github.com/KIS18-GDS-Team7/Kinchan/issues/89))。
- 検討した案 (#89)。
  - 時刻の指定は必要ではないかという意見。
  - モックの案A。承認するときに勤怠管理者が時刻を入力する。初期値はその曜日の勤務可能時間、未設定なら店舗の営業時間とする (判断ログ A-42)。勤務可能時間は [ADR-0015](./0015-drop-availability-and-staffing.md) でなくした。
- シフト希望の処理状態として取りうる値が定義されていなかった (モックの案B の判断ログ B-50)。承認・却下の UC の代替フローは、シフト希望が取り下げられた状態を前提にしていたが、取り下げる UC がなかった ([#87](https://github.com/KIS18-GDS-Team7/Kinchan/issues/87))。

## 決定

- 「出勤可能」の希望はなくす。シフト希望は、希望時間帯まであわせて送信する (#89、2026/10/21)。
- シフト希望は希望日・希望開始時刻・希望終了時刻からなり、1 件は 1 日分とする。対象期間の各日の希望をそれぞれ 1 件のシフト希望とし、勤怠管理者は 1 件ずつ承認・却下する (2026/10/22 の会話)。
- シフト希望の処理状態は次の 5 つとする (#87、2026/10/21 の会話)。
  - 「下書き」: 一時的に保存したもの。勤怠管理者に提示しない。
  - 「未処理」: 送信したもの。勤怠管理者がシフトを組むときに参照する。
  - 「承認済」: 承認され、シフトとして登録されたもの。
  - 「却下」: 却下理由とともに却下されたもの。
  - 「取り下げ」: 従業員が取り下げたもの。
- 取り下げる UC として UC-315「シフト希望を取り下げる」を新設する (#87、2026/10/21 の会話)。勤怠修正申請とシフト日時変更申請についても、取り下げる UC (UC-314・UC-316) を新設する (2026/10/21 の会話)。
- 取り下げられるのは「未処理」のシフト希望だけとする (2026/10/22 の会話)。取り下げたシフト希望は削除せず、処理状態を「取り下げ」にする (案A の A-6)。
