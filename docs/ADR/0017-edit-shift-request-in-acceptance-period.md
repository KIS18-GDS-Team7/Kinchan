# シフト希望の変更は、受付期間中にシフト希望を送信する UC で行う

## ステータス

決定

## 背景

- シフト希望を送信する UC だけでなく、送信したシフト希望を編集する UC もあってよいのではないかという意見が出た ([#63](https://github.com/KIS18-GDS-Team7/Kinchan/issues/63))。
- 議論で出た意見 (#63)。
  - 受付期間中は編集できるようにする案。
  - 任意のタイミングで修正できると、シフトが確定するタイミングがあいまいになる。提出の期限や撤回の仕組みも必要になる、という懸念。
  - 編集する頻度は低く、却下してもらって送信し直せばよいという意見。これに対し、「運用でカバーする」ことを開発側が求めるのは好ましくないという意見。
- その後、シフト希望の受付期間を勤怠管理者が登録することになった ([ADR-0008](./0008-shift-request-periods.md))。

## 決定

- シフト希望を編集する UC は作らない。変更は UC-307「シフト希望を送信する」の代替フローで行う (#63、2026/11/05)。
  - 処理状態が「下書き」「未処理」のシフト希望は、内容を上書きできる。
  - 処理状態が「承認済」「却下」のシフト希望は変更できない。
- 送信・変更できるのは、UC-215 で登録した受付期間中に限る (#63)。受付期間があるので、シフトが確定するタイミングがあいまいになる懸念はなくなる。
- 撤回は UC-315「シフト希望を取り下げる」で行う。取り下げた後も、受付期間中なら同じ希望日について送信し直せる (#63、[ADR-0016](./0016-shift-request-states.md))。
- 「未処理」のシフト希望がある日の希望を外せるかと、承認・却下の対象をどの時点の内容にするかは、この ADR では決めない。UC-307・UC-205・UC-206 の備考では暫定の扱いを書いている。
