# 勤怠修正申請は申請内容のまま承認し、勤怠管理者の直接修正とは別に扱う

## ステータス

決定

## 背景

- 勤怠修正申請の詳細では、対象日のシフトと修正後の内容の矛盾を調べて提示していた。矛盾があっても承認は止めない参考情報で、この機能は要るのかという指摘があった ([#90](https://github.com/KIS18-GDS-Team7/Kinchan/issues/90))。
- 勤怠修正申請を承認すると、申請内容をそのまま勤怠記録に反映する流れで、勤怠管理者が内容を調整する手順はなかった ([#91](https://github.com/KIS18-GDS-Team7/Kinchan/issues/91))。
  - 調整できるようにしたほうがよいという意見があった。
  - モックの案A は、承認か却下だけを行い、調整が必要なら却下するか直接修正するとしていた (判断ログ A-53)。
  - 調整を認めると、修正の記録には従業員の勤怠修正申請に基づくと残るのに、時刻は勤怠管理者が指定したものになる。これは不正を許しかねない。勤怠管理者は自身の権限で勤怠記録を直接修正できるので、承認で変更する必要はない (#91)。
- 「未処理」の勤怠修正申請がある日の勤怠を、勤怠管理者が直接修正したときの申請の扱いが、どの UC にもなかった ([#93](https://github.com/KIS18-GDS-Team7/Kinchan/issues/93))。
  - 申請を却下して扱うという意見があった。
  - モックの案A は、申請を申請中のまま残し、後から承認すると申請内容で上書きされるとしていた (判断ログ A-84)。

## 決定

- 対象日のシフトと修正後の内容の矛盾の判定は残す。提示できる情報は提示する (#90、2026/10/21)。矛盾があっても承認できる。判定の方法は UC-207 の備考に書く。
- 勤怠修正申請を承認する (UC-208) では、勤怠管理者は申請内容を調整できない (#91、2026/10/21)。調整が必要な場合は、勤怠修正申請を却下する (UC-209) か、従業員の勤怠を修正する (UC-210) で直接修正する。
- 「未処理」の勤怠修正申請がある日を UC-210 で直接修正しても、申請は「未処理」のまま残す。後から UC-208 で承認すると、申請内容で上書きされる (#93、案A の A-84、2026/10/21)。
- シフト希望の承認 (UC-205) とシフト日時変更申請の承認 (UC-213) でも、内容を調整する手順は設けない。これは #91 からの導出で、暫定とする。
