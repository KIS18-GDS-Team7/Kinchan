# UC と要件定義書には画面の形を書かない

## ステータス

決定

## 背景

- シフト希望を送信する UC は、手順の中で「テーブル形式のフォーム」と画面の形まで指定していた。シフトの一覧表示の UC もテーブル形式を前提にしていた。どちらも、カレンダーで表示したいという指摘と食い違っていた ([#75](https://github.com/KIS18-GDS-Team7/Kinchan/issues/75))。
- UI はフロントエンドの担当が考えて工夫すればよいので、特に指定しないという意見があった (#75)。
- 画面の形は画面遷移図 ([#40](https://github.com/KIS18-GDS-Team7/Kinchan/issues/40))、画面レイアウト ([#41](https://github.com/KIS18-GDS-Team7/Kinchan/issues/41))、画面項目定義 ([#46](https://github.com/KIS18-GDS-Team7/Kinchan/issues/46)) で扱う予定である。
- 振り直し後の UC-303「ホームを表示する」は、ホーム画面に何を置くかを扱う UC だった。

## 決定

- UC と要件定義書には、画面の形 (表かカレンダーか、ボタンの配置など) を書かない。画面の形は画面設計で扱う (#75、2026/10/21)。
- 画面の構成だけを扱う UC は作らない。UC-303「ホームを表示する」は削除する (2026/10/22 の会話)。
- [AGENTS.md](../../AGENTS.md) の「画面の構成やボタン配置は画面設計で扱う」は、この ADR に基づく。
