# UC の ID はアクターごとの連番とし、UC 記述は docs/usecase/ の直下に UC-XXX.md として置く

## ステータス

決定

## 背景

- UC 記述と UC 図の置き方として、次の案が出た ([#20](https://github.com/KIS18-GDS-Team7/Kinchan/issues/20))。
  - UC ごとにディレクトリを作り、UC 記述と図をペアで置く案。対応するファイルをすぐに見つけられる。
  - ファイルの種類ごとにディレクトリを分ける案。
  - `docs/usecase/` の直下に、番号を振ったファイルを並べる案。
- 番号を振ってソートできるようにしているので、ディレクトリを作らなくても、ソートすれば対応するファイルがまとまって並ぶ。UC 図は 1 つしかないので、番号を振るのは UC 記述だけでよい (#20)。
- UC 記述のファイル名は `UC-XXX-hoge.md` のように番号と説明語の形だった。説明語を付けると、UC の名称を変えるたびにファイル名を変える必要があり、参照元のリンクが切れやすい。UC の番号は要件定義書や ADR からも参照されるので、番号だけで特定できる名前のほうが追いやすい ([#58](https://github.com/KIS18-GDS-Team7/Kinchan/issues/58))。
- #58 で、この決定を ADR にすることになったが、main には入っていなかった。
- UC の ID は、要件定義書の最初の版からアクター別の百番台としていた。後から変えると UC 図と UC 記述に影響するので、この体系でよいかをレビューで問うた ([#50](https://github.com/KIS18-GDS-Team7/Kinchan/pull/50))。ログイン・ログアウトは、そのレビューで UC-001・002 にまとめていた (#50)。その後、UC の追加・削除・統合を重ねた ([#98](https://github.com/KIS18-GDS-Team7/Kinchan/pull/98))。

## 決定

- UC の ID は、アクターごとに百番台を分け (マスタ管理者は 1xx、勤怠管理者は 2xx、従業員は 3xx)、X01 から連番にする。2026/10/22 に振り直し、ログイン・ログアウトは従業員の UC-301・302 にした (#98)。
- 振り直した後に新設した UC の ID は仮とする。削除した UC の番号を再び使うかは、この ADR では決めない。

- UC 記述と UC 図は `docs/usecase/` の直下に置き、サブディレクトリは作らない (#20、2026/10/06)。
- UC 記述のファイル名は `UC-XXX.md` とし、説明語は付けない。UC の名称はファイルの見出しに書く (#58、2026/10/08)。
- 構成は [docs/usecase/README.md](../usecase/README.md) に書く。
