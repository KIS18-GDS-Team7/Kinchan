# 画面遷移図には画面と遷移だけを描く

## ステータス

決定

## 背景

- 画面遷移図の書き方として、次の案が出た ([#40](https://github.com/KIS18-GDS-Team7/Kinchan/issues/40))。
  - 各画面の中身は描かない。
  - 申請を扱う画面の遷移では、エラーのときの遷移も描く。
  - 画面に対応する UC をノートに書く。
- 画面遷移図にボタンまで描くかが問われた ([#111](https://github.com/KIS18-GDS-Team7/Kinchan/issues/111))。
- どのボタンで遷移するかは、遷移線のラベル (「〜ボタンが押されたら」) で分かる。各画面のボタンや項目は画面レイアウト ([#41](https://github.com/KIS18-GDS-Team7/Kinchan/issues/41)) と画面項目定義 ([#46](https://github.com/KIS18-GDS-Team7/Kinchan/issues/46)) で扱うので、画面遷移図にも描くと二重に管理することになる (#111)。

## 決定

- 画面遷移図には、画面と遷移線だけを描く。各画面のボタンや項目は描かない (#40、2026/10/22、#111、2026/10/28)。
- 申請を扱う画面の遷移では、エラーのときの遷移も描く。画面に対応する UC はノートに書く (#40)。
- 遷移線のラベルに書くボタンの名前は、画面項目定義で決める名前にそろえる (#111)。
