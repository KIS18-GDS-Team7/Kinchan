# 公開済みのシフトが無い日も出勤打刻を止めない

## ステータス

決定

## 背景

- 出退勤を打刻する (UC-304) は、当日を勤務日とする公開済みのシフトが無い従業員の出勤打刻を受け付けず、打刻できないことを提示して終了していた。
  - この規則は UC の全件書き直しで入った暫定の規則で、Issue にも判断ログにも根拠が残っていなかった。
- 勤怠修正申請では、対象日にシフトが無いのに修正後の打刻の一覧に勤務がある場合を「矛盾」として提示するが、承認は止めない ([#90](https://github.com/KIS18-GDS-Team7/Kinchan/issues/90))。
  - #90 では、この矛盾の判定は要るのかという指摘に対し、提示できる情報は提示するという理由で残すと決めた。矛盾は参考情報であり、承認を止める条件ではない。
- このため、シフトが無い日の勤務は、勤怠修正申請なら記録できるのに、打刻では記録できなかった。
  - シフトの登録や公開が間に合わない日に勤務した従業員は、出勤打刻ができず、後から勤怠修正申請を送ることになる。
  - 出勤打刻ができないと勤務ステータスが「出勤中」にならないので、退勤と休憩の打刻もできない。
- 検討した案。
  - 案1: 変更しない。シフトが無い日は出勤打刻を受け付けない。
  - 案2: シフトが無いことを提示して打刻の確認を求め、打刻は止めない。

## 決定

- 案2 を採る (2026/11/11 のチーム内合意)。当日を勤務日とする公開済みのシフトが無い場合、システムはシフトが無いことをアクターに提示して打刻の確認を求め、アクターが打刻を指示したら打刻を記録する。
- シフトが無いことは、#90 の「矛盾」と同じく提示する情報として扱い、打刻を止める条件にしない。
- 確認の時点で、アクターは打刻のキャンセルを要求できる。この場合、打刻は記録せず、勤務ステータスも変えない。
- 判定の対象は公開済みのシフトだけであり、下書きのシフトは見ない。判定するのは出勤打刻だけで、シフトの時刻は照合しない。退勤と休憩の打刻はシフトと照合しない。これらは変更前の UC-304 の規則のままで、暫定とする。
- 確認の提示の形は UC では決めず、画面設計で扱う。
- この ADR では次を決めない。
  - シフトが無い日の勤務を、勤務実態を一覧表示する (UC-211) でどう提示するか。遅刻・早退・欠勤はシフトとの比較で判定するため、シフトが無い日の勤務は判定の対象にならない。
  - 日をまたぐシフトについて、勤務日の前日に出勤打刻する場合の扱い (UC-304 の備考で TBD)。
