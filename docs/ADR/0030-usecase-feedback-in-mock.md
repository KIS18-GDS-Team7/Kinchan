# モックの要件照合で見つかった表示を補う

## ステータス

決定

## 背景

- 依頼に従い、main の要件・ユースケースと公開モックを照合した。重複するシフト、申請一覧の項目、却下理由の定型文、時刻差、キャンセル完了の表示に不足があった。
- これらを既存の要件に合わせ、TBD や記載のない業務機能は追加しないよう依頼された。

## 決定

- UC-201・202・205・212・213・309 に従い、重複するシフトの従業員名・勤務日・開始時刻・終了時刻を表示する。従業員には自分の公開済みシフトだけ、勤怠管理者には管理先のシフトだけを表示する。登録・変更・承認を止める条件と、重複があっても変更申請を送信できる条件は維持する。
- UC-204 の一覧に所属単位、UC-207・212 の一覧に申請理由を表示する。UC-207 の修正後の打刻には日付と秒も表示する。
- UC-206・209・214 の定型文選択には、[参照モックの定義済み文面](https://github.com/KIS18-GDS-Team7/Kinchan/blob/fc15979a4ad222ae3c15399a6f2b9526a6c6514a/mock/js/store.js#L996) のうち「申請内容とシフト・打刻記録が一致しないため」を使用する。選択後の自由記述は維持する。削除された勤務可能時間・人員不足の規則や、TBD の期限に依存する文面は使用しない。文面に基づく自動判定は追加しない。
- UC-207 の時刻差は、公開済みの各シフトと修正後の各勤務の組を明示して、開始・終了の差を分で表示する。勤務時間が重ならない組も表示する。シフトと勤務の対応関係は推測せず、比較で申請内容や承認可能条件を変更しない。
- 各操作の例外フローに従い、キャンセル時は入力を破棄し、完了を表示する。内容を表示するだけの画面を閉じる操作では、キャンセルの完了は表示しない。
- キャンセルボタンを表示しない入力画面も、別画面へ遷移した時点で入力中の内容を破棄する。画面遷移による破棄は他の入力画面と同じ動作とし、専用のキャンセル完了表示は出さない。
- ログイン直後の打刻画面、従業員の月カレンダーと全員の日別勤務時間、管理者の従業員別シフト表は維持する。未決の締切日・打刻漏れの判定時点・通知の既読などは追加しない。
