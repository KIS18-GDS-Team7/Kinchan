# シーケンス図は UC 記述 1 本につき 1 枚描き、ライフラインを4種類に分ける

## ステータス

決定

## 背景

- 概要設計の成果物としてシーケンス図を作ることになった ([#42](https://github.com/KIS18-GDS-Team7/Kinchan/issues/42))。対象は全 UC (41 本)、期限は 2026/11/24 (#42、2026/11/11)。
- 書き方が決まっていなかったため、UC-304 出退勤を打刻する で 1 枚試作し、粒度と書き方を確認した (#42、2026/11/11)。
- UC 記述にはメインフローのほかに代替フロー (Alt-N) と例外フロー (Ex-N) があり、終わり方が 3 通りある。「このユースケースを終了する」「中断する」で終わるもの、元のステップに戻るもの、条件つきで実行されるものである。これらを図でどう書き分けるかを決める必要があった。
- 画面の名前は画面遷移図 ([#107](https://github.com/KIS18-GDS-Team7/Kinchan/pull/107))、クラスの名前は概念クラス図 ([#112](https://github.com/KIS18-GDS-Team7/Kinchan/pull/112)) で決まっている。シーケンス図で別の名前を使うと、同じものに名前が 2 つできる。
- 概念クラス図とは別のファイルにすることになった (#42、2026/11/11)。astah のファイルが別になるため、クラスの参照ではなく名前で合わせることになる。

## 決定

- シーケンス図は UC 記述 1 本につき 1 枚描き、図の名前は「UC-xxx (UC 名)」とする (#42、2026/11/11)。
- ライフラインは左から アクター / 画面 (Boundary) / 制御 (Control) / エンティティ の 4 種類とする。画面の名前は画面遷移図、エンティティの名前は概念クラス図に合わせる (#42、2026/11/11)。
- メインフローの 1 ステップを 1〜2 本のメッセージで表す。戻りメッセージ (破線) は、データを受け取るところだけに書く。
- アクターへの結果の提示は、制御 → 画面「〜を表示する」、画面 → アクター「〜を提示する」の 2 本で表す。成功も失敗も同じ形とする。
- 代替フロー・例外フローは、終わり方で複合フラグメントを使い分ける。
  - UC を終了する、中断するもの: `break`
  - 条件つきで実行されるステップ: `opt`
  - 元のステップに戻るもの: `alt` と、戻り先を書いたノート
  - 日ごと・人ごとに繰り返すステップ: `loop`
- 代替フローが 10 ステップ以上の別経路になる場合は、別の図にして本編のノートから参照する。勤怠修正申請を送信する (UC-306) とシフト希望を送信する (UC-307) の Alt-1 がこれに当たる。
- 判断の出典 (ADR・Issue 番号) と、UC の事後条件から決まること (まとめて保存する、など) はノートに書く ([ADR-0024](./0024-cite-sources-in-usecase-notes.md) と同じ考え方)。
- シーケンス図は `docs/sequence-diagram/` に置き、astah のファイルと、レビュー用に書き出した画像を入れる。概念クラス図とは別のファイルとする (#42、2026/11/11)。
- 画面・クラスの名前が変わった場合は、シーケンス図もあわせて直す。
- この ADR では、図の生成元 (UC ごとのテキストと astah API のスクリプト) をリポジトリに置くかどうかは決めない。
