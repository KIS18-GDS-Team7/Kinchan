# シーケンス図は UC 記述 1 本につき 1 枚、テキストの定義から SVG を書き出して作る

## ステータス

決定

## 背景

- 概要設計の成果物としてシーケンス図を作ることになった ([#42](https://github.com/KIS18-GDS-Team7/Kinchan/issues/42))。対象は全 UC (41 本)、期限は 2026/11/24 (#42、2026/11/11)。
- 書き方が決まっていなかったため、UC-304 出退勤を打刻する で 1 枚試作し、粒度と書き方を確認した (#42、2026/11/11)。
- UC 記述にはメインフローのほかに代替フロー (Alt-N) と例外フロー (Ex-N) があり、終わり方が 3 通りある。「このユースケースを終了する」「中断する」で終わるもの、元のステップに戻るもの、条件つきで実行されるものである。これらを図でどう書き分けるかを決める必要があった。
- 画面の名前は画面遷移図 ([#107](https://github.com/KIS18-GDS-Team7/Kinchan/pull/107))、クラスの名前は概念クラス図 ([#112](https://github.com/KIS18-GDS-Team7/Kinchan/pull/112)) で決まっている。シーケンス図で別の名前を使うと、同じものに名前が 2 つできる。
- 最初は astah で描き、SVG に書き出した ([#125](https://github.com/KIS18-GDS-Team7/Kinchan/pull/125))。生成元 (UC ごとのテキストと astah API のスクリプト) がリポジトリになく、担当者しか図を直せなかった。書き出した SVG は文字がグリフのパスになっていて、検索・diff・自動レビューで読めず、43 枚で約 46MB あった。
- #125 のレビューで、元のステップに戻るフローを区画 1 つの `alt` で描くと、図のとおりに読んだときにエラーの後も処理が続いてしまうこと、`opt` の中の `break` では UC の終了を表せないことが分かった。
- 制御 → 画面を「〜を表示する」と書くと、表示するのが制御のように読める。表示するのは画面である。
- DB アクセスをカプセル化する DataManager を、制御とエンティティの間に置くことになった。

## 決定

- シーケンス図は UC 記述 1 本につき 1 枚描き、図の名前は「UC-xxx (UC 名)」とする (#42、2026/11/11)。
- 図はテキストの定義 (`docs/sequence-diagram/src/UC-xxx.txt`) から、スクリプト (`docs/sequence-diagram/seqsvg.py`) で SVG (`docs/sequence-diagram/images/UC-xxx.svg`) を書き出して作る。生成元をリポジトリに置き、SVG の文字は `<text>` 要素のまま出力する。astah のファイルは置かない。概念クラス図とは別のファイルとする (#42、2026/11/11)。
- ライフラインは左から アクター / 画面 (Boundary) / 制御 (Control) / DataManager / エンティティ とする。画面の名前は画面遷移図、エンティティの名前は概念クラス図に合わせる (#42、2026/11/11)。
- 制御はエンティティに直接アクセスせず、DataManager に取得・保存を頼む。戻り値は DataManager を通って制御に返る。
- メインフローの 1 ステップを 1〜2 本のメッセージで表す。戻りメッセージ (破線) は、データを受け取るところだけに書く。
- アクターへの提示は、制御 → 画面「〜を渡す」、画面 → アクター「〜を提示する」の 2 本で表す。成功・失敗・キャンセルの完了も同じ形とする。画面 → アクターは「〜を提示し、〜を求める」の形で何を提示するかを書き、提示する前に取得するメッセージを書く。
- 代替フロー・例外フローは、終わり方で複合フラグメントを使い分ける。
  - UC を終了する、中断するもの: `break`。最上位に置く
  - 条件つきで実行されるステップ: `opt`
  - 入力をやり直すために元のステップに戻るもの: 戻り先から検証までを囲む `loop`
  - 保存の失敗で元のステップに戻るもの: `[保存に失敗した]` と `[保存に成功した]` の 2 区画の `alt`
  - 日ごと・人ごとに繰り返すステップ: `loop`
- 代替フローが 10 ステップ以上の別経路になる場合は、別の図にして本編のノートから参照する。勤怠修正申請を送信する (UC-306) とシフト希望を送信する (UC-307) の Alt-1 がこれに当たる。
- 判断の出典 (ADR・Issue 番号) と、UC の事後条件から決まること (まとめて保存する、など) はノートに書く ([ADR-0024](./0024-cite-sources-in-usecase-notes.md) と同じ考え方)。画面遷移図・概念クラス図にない名前を使うときは、ノートに「暫定」と書く。
- 画面・クラスの名前が変わった場合は、シーケンス図もあわせて直す。
