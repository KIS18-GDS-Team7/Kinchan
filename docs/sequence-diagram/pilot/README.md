# シーケンス図をテキストから SVG に書き出す

PR #125 のシーケンス図 43 枚を、テキストの定義から SVG を直接書き出す形で作り直したもの。PR #125 のレビュー (PR 上のコメントを含む) で出た指摘を直してある。

## 何が変わるか

| | PR #125 (astah から書き出し) | この作り方 |
| --- | --- | --- |
| 生成元 | 手元のテキストと astah API のスクリプト (リポジトリに無い) | `src/UC-xxx.txt` と `seqsvg.py` (リポジトリに入れる) |
| SVG の文字 | グリフのパス。検索・diff で読めない | `<text>` 要素。検索・diff・自動レビューで読める |
| SVG の大きさ | 1 枚 約 1MB (43 枚で約 46MB) | 43 枚で約 1MB |
| 直す人 | 担当者だけ | 誰でも。`src/` を直して `seqsvg.py` を実行する |

## 使い方

```sh
cd docs/sequence-diagram/pilot
python3 seqsvg.py                 # src/ の全ファイルを svg/ に書き出す
python3 seqsvg.py src/UC-302.txt  # 1 ファイルだけ書き出す
```

Python 3 の標準ライブラリだけで動く。`src/` を直したら、書き出した `svg/` も同じコミットに入れる。

## 定義の書式

```text
title UC-302 ログアウトする           # 図の名前
scope メインフロー、Ex-1               # 右上のノートに出す、この図で描いたフロー

actor A 従業員                         # ライフライン: 種類 ID 名前
boundary H 従業員ホーム画面             # 種類は actor / boundary / control / entity
control C ログイン制御                  # 左から書いた順に並ぶ

A -> H : ログアウトボタンを押す          # メッセージ (番号は自動で振る)
C --> H : 戻り値                        # 戻りメッセージ (破線、番号なし)
C -> C : ログアウトした状態にする        # 自己メッセージ
note : 出典など                         # 直前のメッセージ (または直前の end の断片) に付くノート

break ガード条件                        # break / opt / loop / alt
  ...
end
alt 保存に失敗した
  ...
else 保存に成功した                     # alt の 2 つめ以降の区画
  ...
end
# から始まる行はコメント
```

## 描き方 (ADR-0034 からの変更点)

ADR-0034 (PR #125) の決まりに従い、レビューで食い違いが見つかった所だけ次のように変えた。ADR-0034 に取り込むかは #42 で相談したい。

- **元のステップに戻るフロー**: ADR-0034 は「alt と、戻り先を書いたノート」としている。しかし alt に区画が 1 つしかないと、正常の続きが alt の外に出る。そのため図のとおりに読むと、エラーを提示した後も処理が続いてしまう。そこで次のように描き分ける。
  - 入力のやり直し (例: UC-306 Alt-4) は、戻り先から検証までを `loop` で囲む。
  - 保存の失敗 (例: UC-205 Ex-2) は、`alt [保存に失敗した]` と `[保存に成功した]` の 2 区画にする。
- **break は最上位に置く**: UML の break は、それを囲む断片だけを抜ける。opt の中に break を入れると UC の終了を表せないので、条件をまとめて最上位の break にする (例: UC-304 Alt-2)。
- **制御 → 画面は「〜を渡す」にする**: ADR-0034 は制御 → 画面を「〜を表示する」としている。しかし表示するのは画面で、制御は画面にデータを渡すだけなので、「〜を渡す」とする (例: 「ユーザーの一覧を渡す」「保存に失敗したことを渡す」)。画面 → アクターは「〜を提示する」のまま。
- **キャンセルの提示も 2 本にする**: 画面 → 制御「キャンセルを要求する」、制御 → 画面「キャンセルの完了を渡す」、画面 → アクター「キャンセルが完了したことを提示する」とする。ADR-0034 の「成功も失敗も同じ形」に合わせた。
- **条件つきの提示は opt にする**: 「アクター自身のシフト希望なら、その旨を提示する」(UC-205 Alt-3) などを、ノートではなく opt で描く。
- **ボタンは、そのボタンがある画面に送る**: 1 本目のメッセージは、画面遷移図でそのボタンがある画面に送る (例: UC-306 は勤怠記録一覧表示画面)。結果は遷移先の画面から提示する。
- **入力確認ダイアログを独立したライフラインにする**: 画面遷移図で独立した画面になっているため。
- **権限は従業員の属性 (権限のリスト) として扱う**: 概念クラス図では権限は従業員と関連する別のクラスだが、従業員が権限のリスト (マスタ管理者権限・勤怠管理者権限) を持つものとして描き、権限のライフラインは置かない (UC-104・107・109)。概念クラス図との違いはノートに「暫定」と書いた。
- **UC 記述・画面遷移図・概念クラス図は origin/main に合わせる**: 他の成果物にない名前を使うときは、ノートに「暫定」と書く。

## PR #125 のコメントへの対応

PR #125 に付いたコメントは、UC 記述 (origin/main) と照らして正しいかを確かめてから反映した。

| UC | コメント | 対応 |
| --- | --- | --- |
| UC-102 | 「変更を指示する」は何の変更か | 「ユーザー情報の変更を指示する」にした |
| UC-102 | 更新の後に取得し直して画面を更新していない | UC-102 の MF10 は完了の提示だけなので、更新後の取得は描かない。MF4 の前に対象のユーザーを取得する抜けを直した |
| UC-103 | MF2・MF4 の扱いが違う | 制御が表示した内容 (ユーザーの一覧、削除の確認内容) を、画面がアクターに提示していなかった。「〜を提示し、〜を求める」にした |
| UC-105 | 登録されている所属単位を提示するのが正しい | UC の MF4 どおりにした |
| UC-106 | 現在の所属と所属単位をそれぞれ提示するのが正しい | UC の MF4 どおりにした |
| UC-205 | MF1〜2 の間でシフト希望を取得していない | 内容を提示する前に、シフト希望を取得するようにした |
| UC-109 | 勤怠管理者権限の取得 (#8〜10) はいらない | 権限はユーザーの一覧と一緒に取得し、個別の取得をなくした。UC-109 の Alt-1 があるため、判定と提示は残した |

## 描き方のルールから外れた所

UC のステップの順序を守るため、次の図は上のルールから外れている。ノートに理由を書いてある。

- UC-206・209・214・307-alt1: 戻り先と検証の間にキャンセル (Ex-1) がある、または戻り先がキャンセルより前にある。そのため、loop ではなく alt の入れ子で描いた
- UC-307: Alt-4 (下書きを保存して終了) の break の中に、保存に失敗したら MF5 に戻る経路がある

## 残っている点

- 画面遷移図にない画面・ボタン、概念クラス図にない属性 (勤務ステータス、削除済み、操作者・修正者・根拠 など) は、各図のノートに「暫定」と書いた。
- 活性区間 (ライフライン上の細長い四角) は描いていない。
