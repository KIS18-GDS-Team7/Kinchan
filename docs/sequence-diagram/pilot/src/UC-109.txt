title UC-109 勤怠管理者に管理先を割り当てる
scope メインフロー、Alt-1、Alt-2、Ex-1、Ex-2

actor A マスタ管理者
boundary F ユーザ権限変更画面
control C 管理先制御
entity U 従業員
entity OU 所属単位

# メインフロー 1
A -> F : 管理先の割り当てを要求する
note : 管理先の割り当てを要求する画面は画面遷移図にない。ユーザ権限変更画面を流用する(暫定)
F -> C : ユーザーの一覧を要求する
C -> U : 削除済みでないユーザーの一覧を取得する
U --> C : ユーザーの一覧(氏名, ユーザーID, 権限のリスト)
note : 権限はユーザーの一覧と一緒に取得する(#125 のレビュー)。権限は従業員が持つ権限のリスト(マスタ管理者権限・勤怠管理者権限)。概念クラス図では権限は別のクラス(暫定)

# メインフロー 2〜3 と Alt-1
loop 勤怠管理者権限を持つユーザーが指定されるまで繰り返す
C -> F : ユーザーの一覧を渡す
F -> A : ユーザーの一覧を提示し、対象のユーザー(勤怠管理者権限を持つユーザー)の指定を求める
A -> F : 対象のユーザーを指定する
F -> C : 管理先の入力を要求する(ユーザー)
C -> C : 対象のユーザーが勤怠管理者権限を持つかを判定する
opt 対象のユーザーが勤怠管理者権限を持たない
C -> F : 管理先を割り当てられないことを渡す
F -> A : 対象のユーザーが勤怠管理者権限を持たないため管理先を割り当てられないことを提示する
note : Alt-1。メインフロー2に戻る。勤怠管理者権限は UC-104 で付ける(備考4)
end
end

# メインフロー 4〜6 と Alt-2
C -> OU : 対象のユーザーの現在の管理先と、登録されている所属単位を取得する
OU --> C : 管理先の一覧, 所属単位の一覧
loop 誤りが無くなるまで繰り返す
C -> F : 現在の管理先と登録されている所属単位を渡す
F -> A : 対象のユーザーの現在の管理先と登録されている所属単位を提示し、変更後の管理先とする所属単位の指定を求める
A -> F : 変更後の管理先とする所属単位を1つ以上指定する
F -> C : 指定された管理先の検証を要求する(所属単位の一覧)
C -> C : 所属単位が1つ以上指定されているかを検証する
opt 所属単位が1つも指定されていない
C -> F : 1つ以上の指定が必要であることを渡す
F -> A : 管理先とする所属単位を1つ以上指定する必要があることを提示する
note : Alt-2。メインフロー4に戻る
end
end

# メインフロー 7
C -> F : 変更前と変更後の管理先を渡す
F -> A : 対象のユーザーの変更前と変更後の管理先を提示し、割り当ての確認を求める

# Ex-1
break 割り当てのキャンセルを要求した
A -> F : キャンセルボタンを押す
F -> C : キャンセルを要求する
C -> C : 入力された内容を破棄する
C -> F : キャンセルの完了を渡す
F -> A : キャンセルが完了したことを提示する
note : Ex-1。待機状態に戻る。管理先は変更されない
end

# メインフロー 8〜9
A -> F : 管理先の割り当てを指示する
F -> C : 管理先の割り当てを要求する(ユーザー, 所属単位の一覧)
C -> OU : 対象のユーザーの管理先を指定された所属単位に更新する
note : 管理先は従業員としての所属とは別のデータ(備考1、ADR-0007)。初回の割り当ても変更もここで行う(備考2)。1つの所属単位に複数の勤怠管理者を置けるかは TBD(備考5)

# Ex-2 とメインフロー 10
alt 保存に失敗した
C -> F : 保存に失敗したことを渡す
F -> A : 保存に失敗したことを提示する
note : Ex-2。入力された内容を保持したまま、メインフロー7に戻る
else 保存に成功した
C -> F : 管理先の割り当ての完了を渡す
F -> A : 管理先の割り当てが完了したことを提示する
end
