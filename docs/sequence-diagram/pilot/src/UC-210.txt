title UC-210 従業員の勤怠を修正する
scope メインフロー、Alt-1〜5、Ex-1、Ex-2

actor A 勤怠管理者
boundary RL 勤怠実態一覧表示画面
boundary F 勤務修正画面
boundary FC 勤務修正確認画面
boundary AL 勤怠修正申請一覧表示画面
control C 勤怠修正制御
entity OU 所属単位
entity R 勤怠記録
entity H 勤怠修正履歴
entity AR 勤怠修正申請
entity U 従業員
entity N 通知

# メインフロー 1〜3
A -> RL : 勤怠修正申請ボタンを押す(勤怠の修正を要求する)
note : 勤怠実態一覧表示画面の勤怠修正申請ボタンから勤務修正画面に移る(画面遷移図)
RL -> C : 管理先の従業員を要求する
C -> OU : アクターの管理先の従業員を取得する
OU --> C : 従業員の一覧
C -> F : 管理先の従業員を渡す
F -> A : 管理先の従業員の一覧を提示し、対象の従業員と対象日の指定を求める
A -> F : 対象の従業員と対象日を指定する
F -> C : 勤怠記録を要求する(従業員, 対象日)

# メインフロー 4 で提示する内容の取得
C -> R : 対象日の勤怠記録を取得する
R --> C : 打刻の一覧(種類, 打刻日時)
C -> H : 対象日の修正履歴を取得する
H --> C : 修正履歴の一覧
C -> AR : 対象日の「未処理」の勤怠修正申請を探す
AR --> C : 申請の内容

# メインフロー 4〜6、Alt-1〜5
loop 修正後の打刻の一覧と修正理由に誤りが無くなるまで繰り返す
alt 対象日に勤怠記録が無い
C -> F : 対象日に勤怠記録が無いことを渡す
F -> A : 対象日に勤怠記録が無いことを提示し、勤怠記録を新しく登録することの確認を求める
A -> F : 勤怠記録の登録を指示する
F -> A : 修正後の打刻の一覧と修正理由の入力を求める
note : Alt-1。メインフロー5に進む
else 対象日に勤怠記録がある
C -> F : 勤怠記録と修正履歴を渡す
F -> A : 対象日の勤怠記録(打刻の一覧: 種類・打刻日時)と修正履歴を提示し、修正後の打刻の一覧と修正理由の入力を求める
note : 打刻日時は秒まで提示する(備考4)
end
opt 対象日に「未処理」の勤怠修正申請がある
C -> F : 「未処理」の勤怠修正申請があることと、その申請の内容を渡す
F -> A : 対象日に「未処理」の勤怠修正申請があることと、その申請の内容を提示する
note : Alt-2。メインフロー5に進む。申請は「未処理」のまま残り、後から UC-208 で承認すると申請内容で上書きされる(備考6、#93)
end
opt 対象がアクター自身の勤怠記録
C -> F : アクター自身の勤怠記録であることを渡す
F -> A : 対象がアクター自身の勤怠記録であることを提示する
note : Alt-5。メインフロー5に進む。自身の勤怠記録も修正できる(備考8、A-55)
end
A -> F : 修正後の打刻の一覧と修正理由を入力する
A -> F : 確認ボタンを押す
F -> C : 入力内容の検証を要求する(修正後の打刻の一覧, 修正理由)
C -> C : 打刻の一覧の整合と修正理由の有無を検証する
note : 出勤、0回以上の(休憩開始, 休憩終了)、退勤の順で、打刻日時が昇順(備考3)。修正理由は必須(備考1)
opt 打刻の一覧が整合していない、または修正理由が入力されていない
C -> F : 誤りの内容を渡す
F -> A : 修正後の打刻の一覧に誤りがあること、または修正理由の入力が必要であることを提示する
note : Alt-3・Alt-4。メインフロー4に戻る
end
end

# メインフロー 7
C -> FC : 修正前と修正後の勤怠記録を渡す
note : 勤務修正画面の確認ボタンから勤務修正確認画面に移る(画面遷移図)
FC -> A : 修正前と修正後の勤怠記録を提示し、修正の確認を求める

# Ex-1
break 修正のキャンセルを要求した
A -> FC : キャンセルボタンを押す
FC -> C : キャンセルを要求する
C -> C : 入力された内容を破棄する
C -> FC : キャンセルの完了を渡す
FC -> A : キャンセルが完了したことを提示する
note : Ex-1。待機状態に戻る。勤怠記録は修正されない
end

# メインフロー 8〜10
A -> FC : 変更ボタンを押す(修正を指示する)
FC -> C : 修正を要求する(従業員, 対象日, 修正後の打刻の一覧, 修正理由)
note : この修正に期限は無い(備考5)
C -> H : 修正履歴を記録する(修正前内容, 修正者, 修正日時, 修正理由, 根拠=勤怠管理者の直接修正)
note : 修正者・根拠は概念クラス図にない(UC-210 事後条件、暫定)。根拠は備考1。勤怠記録が無かった場合は修正前の勤怠記録が無いことを記録する(備考7)
C -> R : 勤怠記録を修正後の打刻の一覧に更新する(勤怠記録が無ければ登録する)
note : まとめて保存する(Ex-2 の事後条件)

# Ex-2 とメインフロー 11〜12
alt 保存に失敗した
C -> FC : 保存に失敗したことを渡す
FC -> A : 保存に失敗したことを提示する
note : Ex-2。入力された内容を保持したまま、メインフロー7に戻る
else 保存に成功した
C -> U : 対象の従業員が削除済みかを取得する
U --> C : 削除済みかどうか
note : 削除済みを表す属性は概念クラス図にない(ADR-0013、暫定)
opt 対象の従業員が削除済みユーザーでない
C -> N : 通知を登録する(対象の従業員, 勤怠記録が修正された)
note : 削除済みユーザーには通知しない(備考9)
end
C -> AL : 修正の完了を渡す
note : 勤務修正確認画面の変更ボタンから勤怠修正申請一覧表示画面に移る(画面遷移図)
AL -> A : 修正が完了したことを提示する
end
