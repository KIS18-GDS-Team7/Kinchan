title UC-208 勤怠修正申請を承認する
scope メインフロー、Alt-1〜3、Ex-1、Ex-2

actor A 勤怠管理者
boundary L 勤怠修正申請一覧表示画面
control C 勤怠修正承認制御
participant DM DataManager
entity AR 勤怠修正申請
entity R 勤怠記録
entity CH 勤怠修正履歴
entity U 従業員
entity N 通知

# メインフロー 1〜2
A -> L : 「未処理」の勤怠修正申請を指定して承認を要求する(UC-207 から)
note : 承認の確認を求める画面は画面遷移図にない(暫定)
L -> C : 承認する勤怠修正申請の内容を要求する(勤怠修正申請)
C -> DM : 勤怠修正申請を取得する
DM -> AR : 勤怠修正申請を取得する
AR --> DM : 従業員, 対象日, 修正後の打刻の一覧, 申請理由, 処理状態
DM --> C : 従業員, 対象日, 修正後の打刻の一覧, 申請理由, 処理状態
C -> L : 承認する勤怠修正申請の内容を渡す
L -> A : 承認する勤怠修正申請の内容を提示し、承認の確認を求める

# Alt-3
opt 対象がアクター自身の勤怠修正申請
C -> L : アクター自身の勤怠修正申請であることを渡す
L -> A : 対象がアクター自身の勤怠修正申請であることを提示する
note : Alt-3。メインフロー3に進む。自身の勤怠修正申請も承認できる(備考8、A-55)
end

# Ex-1
break 承認のキャンセルを要求した
A -> L : キャンセルボタンを押す
L -> C : キャンセルを要求する
C -> L : キャンセルの完了を渡す
L -> A : キャンセルが完了したことを提示する
note : Ex-1。待機状態に戻る。処理状態は変わらず、勤怠記録は修正されない
end

# メインフロー 3〜4
A -> L : 勤怠修正申請の承認を指示する
L -> C : 承認を要求する(勤怠修正申請)
C -> DM : 勤怠修正申請を取得する
DM -> AR : 勤怠修正申請を取得する
AR --> DM : 従業員, 対象日, 修正後の打刻の一覧, 申請理由, 処理状態
DM --> C : 従業員, 対象日, 修正後の打刻の一覧, 申請理由, 処理状態
note : 承認を指示した時点の内容で判定する(備考11)
C -> C : 処理状態が「未処理」であること、修正後の打刻の一覧が整合していることを検証する
note : 整合とは、出勤、0回以上の(休憩開始, 休憩終了)、退勤の順で、打刻日時が昇順であること。同じ日に2回以上の勤務があってよい(備考2、#78)

# Alt-1・Alt-2
break 「未処理」でなくなっている、または整合していない
C -> L : 承認できない理由を渡す
L -> A : 承認できないことと、その理由を提示する
note : Alt-1・Alt-2。UC-207 に戻る。他の勤怠管理者が処理した、または従業員が取り下げた場合を含む(備考11)
end

# メインフロー 5〜7
C -> DM : 処理状態を「承認済」に更新する
DM -> AR : 処理状態を「承認済」に更新する
note : 申請内容は調整しない(備考1、ADR-0019)
C -> DM : 対象日の勤怠記録を取得する
DM -> R : 対象日の勤怠記録を取得する
R --> DM : 修正前の勤怠記録(打刻の一覧)
DM --> C : 修正前の勤怠記録(打刻の一覧)
note : 勤怠記録が無ければ、反映するときに登録する(備考4)
C -> DM : 修正前の勤怠記録を修正履歴として記録する(修正前内容, 修正者, 修正日時, 修正理由=申請理由, 根拠=勤怠修正申請に基づく)
DM -> CH : 修正前の勤怠記録を修正履歴として記録する(修正前内容, 修正者, 修正日時, 修正理由=申請理由, 根拠=勤怠修正申請に基づく)
note : 修正履歴は削除できない(備考3)。修正者・根拠は概念クラス図にない(備考3、暫定)
C -> DM : 申請内容を対象日の勤怠記録に反映する(修正後の打刻の一覧)
DM -> R : 申請内容を対象日の勤怠記録に反映する(修正後の打刻の一覧)
note : まとめて保存する(Ex-2 の事後条件)

# Ex-2 とメインフロー 8〜9
alt 保存に失敗した
C -> L : 保存に失敗したことを渡す
L -> A : 保存に失敗したことを提示する
note : Ex-2。メインフロー2に戻る
else 保存に成功した
C -> DM : 申請した従業員が削除済みかを取得する
DM -> U : 申請した従業員が削除済みかを取得する
U --> DM : 削除済みかどうか
DM --> C : 削除済みかどうか
note : 削除済みを表す属性は概念クラス図にない(ADR-0013、暫定)
opt 申請した従業員が削除済みユーザーでない
C -> DM : 通知を登録する(申請した従業員, 承認結果)
DM -> N : 通知を登録する(申請した従業員, 承認結果)
note : 削除済みユーザーには通知しない(備考7)
end
C -> L : 承認の完了を渡す
L -> A : 承認が完了したことを提示する
end
