# UC-207 シフト希望を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を承認する(UC-207) |
| 目的（ゴール） | シフト希望を承認し、シフトとして登録する |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者がシフト希望の承認要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの担当する店舗の従業員から送信された未処理のシフト希望が存在すること |
| 事後条件 | ・シフト希望の処理状態が「承認済」になっていること<br>・承認されたシフト希望の内容がシフトとして登録されていること<br>・従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | シフト希望を確認する(UC-206) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の承認を要求する
2. システムはアクターに承認するシフト希望の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは希望日時が同じ従業員の登録済みシフトと重複していないか、従業員の勤務可能時間の範囲内か確認する
5. システムはシフト希望の処理状態を「承認済」に更新する
6. システムはシフト希望の内容をシフトとして登録する
7. システムは従業員に承認結果を通知する
8. システムはアクターに承認が完了したことを提示する

### 代替フロー

**Alt-1：希望日時が同じ従業員の登録済みシフトと重複していた場合**

1. システムは重複しているシフトをアクターに提示する
2. アクターはシステムに時間帯を調整した内容を入力する
3. メインフロー4に戻る

**Alt-2：対象のシフト希望がすでに処理済み、または従業員によって取り下げられていた場合**

1. システムは対象のシフト希望が承認できない状態であることをアクターに提示する
2. シフト希望を確認する(UC-206)に戻る

**Alt-3：希望の日時が従業員の勤務可能時間の範囲外だった場合**

1. システムは範囲外であることと、従業員の勤務可能時間をアクターに提示する
2. シフト希望を確認する(UC-206)に戻る

### 例外フロー

**Ex-1：メインフロー3より前にアクターが承認のキャンセルを要求した場合**

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト希望の処理状態が変わっていないこと
- システムが待機状態に戻っていること
