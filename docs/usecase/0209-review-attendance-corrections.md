# UC-209 勤怠修正申請を確認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を確認する(UC-209) |
| 目的（ゴール） | 従業員から送信された勤怠修正申請(打刻漏れ・打刻ミスなどの修正依頼)を一覧で確認し、承認・却下を判断するための情報を得る |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者が勤怠修正申請の確認要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001) |
| 事後条件 | ・アクターに勤怠修正申請の一覧と、指定した勤怠修正申請の詳細が提示されていること |
| 拡張点 | 勤怠修正申請への対応<br>(メインフロー6の部分) |
| 関連ユースケース | 勤怠修正申請を承認する(UC-210) ≪extend≫<br>勤怠修正申請を却下する(UC-211) ≪extend≫ |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の確認を要求する
2. システムはアクターに担当する店舗の従業員から送信された未処理の勤怠修正申請の一覧(従業員名、対象日、修正内容、申請理由、申請日時)を提示する
3. アクターはシステムに詳細を確認する勤怠修正申請を指定する
4. システムはアクターに指定された勤怠修正申請の詳細を提示する
5. システムは対象日のシフトと修正後の内容に矛盾がないか確認し、結果をアクターに提示する
6. アクターは必要に応じて勤怠修正申請を承認する(UC-210)、または却下する(UC-211)
7. アクターはすべての勤怠修正申請を確認するまでメインフロー3〜6を繰り返す

### 代替フロー

**Alt-1：未処理の勤怠修正申請が存在しなかった場合**

1. システムは未処理の勤怠修正申請が存在しないことをアクターに提示する
2. このユースケースを終了する

**Alt-2：アクターが条件(期間、従業員、処理状態)を指定して勤怠修正申請を探す場合**

1. アクターはシステムに条件を指定する
2. システムは条件に合う勤怠修正申請の一覧をアクターに提示する
3. メインフロー3に戻る

**Alt-3：修正後の内容がシフトと矛盾していた場合(シフトのない日の出勤など)**

1. システムは矛盾している点をアクターに提示する
2. メインフロー6に進む

### 例外フロー

なし
