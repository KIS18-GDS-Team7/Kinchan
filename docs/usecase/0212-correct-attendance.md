# UC-212 勤怠を修正する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠を修正する(UC-212) |
| 目的（ゴール） | 従業員からの申請によらず、勤怠管理者が勤怠記録を直接修正し、正しい勤務実績にする |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者が勤怠修正要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・対象の従業員がアクターの担当する店舗に所属していること |
| 事後条件 | ・勤怠記録が修正後の内容に更新されていること<br>・修正前の内容、修正者、修正日時、修正理由が修正履歴として記録されていること<br>・対象の従業員に勤怠記録が修正されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | なし |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠の修正を要求する
2. システムはアクターに担当する店舗の従業員の中から対象となる従業員と日付の指定を求める
3. アクターはシステムに対象となる従業員と日付を指定する
4. システムはアクターに指定された日の勤怠記録(出勤時刻、退勤時刻、休憩時間)を提示する
5. アクターはシステムに修正後の勤怠情報と修正理由を入力する
6. システムは入力された勤怠情報が有効なものか確認する
7. システムはアクターに修正前と修正後の内容を提示し、修正の確認を求める
8. アクターはシステムに修正を指示する
9. システムは修正前の内容、修正者、修正日時、修正理由を修正履歴として記録する
10. システムは勤怠記録を修正後の内容に更新する
11. システムは対象の従業員に勤怠記録が修正されたことを通知する
12. システムはアクターに修正が完了したことを提示する

### 代替フロー

**Alt-1：指定された日に勤怠記録が存在しなかった場合(打刻忘れなど)**

1. システムは勤怠記録が存在しないことをアクターに提示し、勤怠記録を新しく作成するか確認を求める
2. アクターはシステムに勤怠記録の作成を指示する
3. メインフロー5に戻る

**Alt-2：入力された勤怠情報が誤っていた場合(退勤時刻が出勤時刻より前など)**

1. システムは入力された勤怠情報に誤りがあることをアクターに提示する
2. メインフロー5に戻る

**Alt-3：修正理由が入力されていなかった場合**

1. システムは修正理由の入力が必要であることをアクターに提示する
2. メインフロー5に戻る

### 例外フロー

**Ex-1：メインフロー8より前にアクターが修正のキャンセルを要求した場合**

1. アクターはシステムに修正のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 勤怠記録が変更されていないこと
- システムが待機状態に戻っていること

## 備考

1. 不正防止のため、修正理由の入力を必須とし、修正履歴は削除できないものとする
2. 給与計算の締め処理が終わった月の勤怠を修正する場合の扱いはTBD
3. 勤怠の時刻は1分単位で記録し、15分単位などの丸めは行わない(労働基準法に基づく)
