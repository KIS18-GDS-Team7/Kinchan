# UC-001 ログインする

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ログインする(UC-001) |
| 目的 | 全ユーザーがユーザーIDとパスワードでシステムにログインし、権限に基づく操作を始められる状態にする |
| アクター | 全ユーザー |
| 開始条件 | 全ユーザーがログインを要求する |
| 事前条件 | ・アクターがユーザーとして登録されていること(UC-103)<br>・アクターが削除済みでないこと |
| 事後条件 | ・アクターがログインしていること<br>・アクターにホーム(UC-303)が提示されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーを登録する(UC-103)<br>・ホームを表示する(UC-303)<br>・ログアウトする(UC-002) |

## イベントフロー

### メインフロー

1. アクターはシステムにログインを要求する
2. システムはアクターにユーザーIDとパスワードの入力を求める
3. アクターはシステムにユーザーIDとパスワードを入力する
4. アクターはシステムにログインを指示する
5. システムは入力されたユーザーIDとパスワードを検証する
6. システムはアクターをログインした状態にする
7. システムはアクターにホーム(UC-303)を提示する

### 代替フロー

なし

### 例外フロー

#### Ex-1: 入力されたユーザーIDまたはパスワードが誤っていた場合

1. システムはユーザーIDまたはパスワードが誤っていることをアクターに提示する
2. システムはこのユースケースを中断する

事後条件

- アクターがログインしていないこと

## 備考

1. docx の UC-101(アクターは「管理者」)の流れを全ユーザーに適用した(B-17、A-11)。権限の有無を問わず、ログインの流れは同じ
2. 入力されたユーザーIDが登録されていない場合と、削除済みユーザーのユーザーIDだった場合も Ex-1 と同じ扱いとする(docx UC-101 の Ex-1・Ex-2 を統合。暫定)。削除済みユーザーはログインできない(#86、A-19)
3. ログインの試行回数の制限は設けない(A-14)
4. ログイン後は権限を問わずホーム(UC-303)を提示する(暫定)。権限別のホームは設けない(#83)
5. docx UC-101 の Alt-1「ログイン情報を変更する」は対応する UC が無いため書かない。ユーザー本人によるパスワードの変更はTBD(要起票)。ユーザー情報の変更はシステム管理者がユーザーを編集する(UC-104)で行う
