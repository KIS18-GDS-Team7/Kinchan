# UC-002 ログアウトする

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ログアウトする(UC-002) |
| 目的 | アクターがシステムからログアウトし、ログインが必要な操作を行えない状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがログアウトを要求する |
| 事前条件 | ・アクターがログインしていること(UC-001) |
| 事後条件 | ・アクターがログアウトしていること |
| 拡張点 | なし |
| 関連ユースケース | ・ログインする(UC-001) |

## イベントフロー

### メインフロー

1. アクターはシステムにログアウトを要求する
2. システムはアクターにログアウトの確認を求める
3. アクターはシステムにログアウトを指示する
4. システムはアクターをログアウトした状態にする
5. システムはアクターにログアウトが完了したことを提示する

### 代替フロー

なし

### 例外フロー

#### Ex-1: メインフロー3より前にアクターがログアウトのキャンセルを要求した場合

1. アクターはシステムにログアウトのキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- アクターがログインしたままであること
- システムが待機状態に戻っていること

## 備考

1. docxのUC-102(システム管理者向けの流れ)を従業員に適用した(B-17、A-15)。全ユーザーが従業員として振る舞うため(#83)、権限の有無を問わずログアウトの流れは同じで、アクターは従業員とする(2026-10-22の会話)
2. ログアウト後に再びログインするにはログインする(UC-001)を行う
