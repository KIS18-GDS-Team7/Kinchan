# UC-102 ユーザーを編集する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ユーザーを編集する(UC-102) |
| 目的 | アクターが登録済みのユーザーのユーザー情報(氏名、ユーザーID、パスワード)を変更し、変更後の内容でそのユーザーがシステムを利用できる状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターがユーザー情報の変更を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターがシステム管理者権限を持つこと<br>・対象のユーザーが登録されていること(UC-101)<br>・対象のユーザーが削除済みでないこと |
| 事後条件 | ・対象のユーザーのユーザー情報が変更後の内容に更新されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーを登録する(UC-101)<br>・ユーザーの権限を変更する(UC-104)<br>・ユーザーの所属を編集する(UC-106)<br>・ユーザー一覧を表示する(UC-107) |

## イベントフロー

### メインフロー

1. アクターはシステムにユーザー情報の変更を要求する
2. システムはアクターに対象のユーザーの指定を求める
3. アクターはシステムに対象のユーザーを指定する
4. システムはアクターに対象のユーザーの現在の氏名とユーザーIDを提示し、変更後のユーザー情報(氏名、ユーザーID、パスワード)の入力を求める
5. アクターはシステムに変更後のユーザー情報を入力する
6. システムは入力されたユーザー情報を検証する
7. システムはアクターに変更後のユーザー情報を提示し、変更の確認を求める
8. アクターはシステムに変更を指示する
9. システムは対象のユーザーのユーザー情報を変更後の内容に更新する
10. システムはアクターにユーザー情報の変更が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー6で、入力されたユーザー情報が無効だった場合

1. システムは入力されたユーザー情報が無効である理由をアクターに提示する
2. メインフロー4に戻る

#### Alt-2: メインフロー6で、入力されたユーザーIDが他のユーザー(削除済みユーザーを含む)のユーザーIDと重複していた場合

1. システムはユーザーIDが重複していることをアクターに提示する
2. メインフロー4に戻る

#### Alt-3: メインフロー5で、変更後のパスワードが入力されなかった場合

1. システムは対象のユーザーのパスワードを変更の対象から除く
2. メインフロー6に進む

### 例外フロー

#### Ex-1: メインフロー8より前にアクターが変更のキャンセルを要求した場合

1. アクターはシステムに変更のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 対象のユーザーのユーザー情報が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー7に戻る

事後条件

- 対象のユーザーのユーザー情報が変更されていないこと

## 備考

1. ユーザー情報の入力規則(A-17): ユーザーIDは半角英数字と `.` `_` `-` の4〜20文字で、他のユーザー(削除済みユーザーを含む)のユーザーIDと重複しないこと。パスワードは8文字以上で英字と数字を含むこと。氏名は1〜30文字であること
2. 変更後のパスワードが入力されていない場合、パスワードは変更しない(A-18)
3. 変更後のユーザーIDが他のユーザー(削除済みユーザーを含む)と重複する場合は、ユーザーを登録する(UC-101)と同じく変更できない(暫定)
4. UC名はrequirements.mdの「ユーザーを編集する」のまま。フロー本文では「変更する」と書く
5. アクター名はrequirements.mdと同じく「システム管理者」(#83。旧「管理者」)
6. 権限の変更はユーザーの権限を変更する(UC-104)、所属の変更はユーザーの所属を編集する(UC-106)で扱い、このユースケースでは扱わない
