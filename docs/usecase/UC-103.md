# UC-103 ユーザーを登録する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ユーザーを登録する(UC-103) |
| 目的 | アクターが新しいユーザーを登録し、そのユーザーがログインして従業員として振る舞える状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターがユーザーの登録を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターがシステム管理者権限を持つこと |
| 事後条件 | ・入力されたユーザー情報(氏名、ユーザーID、パスワード)でユーザーが登録されていること<br>・登録されたユーザーが権限を持たないこと<br>・登録されたユーザーの所属が設定されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーの権限を変更する(UC-106)<br>・ユーザーの所属を設定する(UC-110)<br>・ユーザー一覧を表示する(UC-116)<br>・ログインする(UC-001) |

## イベントフロー

### メインフロー

1. アクターはシステムにユーザーの登録を要求する
2. システムはアクターにユーザー情報(氏名、ユーザーID、パスワード)の入力を求める
3. アクターはシステムにユーザー情報を入力する
4. システムは入力されたユーザー情報を検証する
5. システムはアクターに入力されたユーザー情報を提示し、登録の確認を求める
6. アクターはシステムに登録を指示する
7. システムはユーザーを登録する
8. システムはアクターにユーザーの登録が完了したことを提示する

### 代替フロー

#### Alt-1: 入力されたユーザー情報が無効だった場合

1. システムは入力されたユーザー情報が無効である理由をアクターに提示する
2. メインフロー2に戻る

#### Alt-2: 入力されたユーザーIDが他のユーザー(削除済みユーザーを含む)のユーザーIDと重複していた場合

1. システムはユーザーIDが重複していることをアクターに提示する
2. メインフロー2に戻る

### 例外フロー

#### Ex-1: メインフロー6より前にアクターが登録のキャンセルを要求した場合

1. アクターはシステムに登録のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- ユーザーが登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー5に戻る

事後条件

- ユーザーが登録されていないこと

## 備考

1. ユーザー情報の入力規則(A-17): ユーザーIDは半角英数字と `.` `_` `-` の4〜20文字で、他のユーザー(削除済みユーザーを含む)のユーザーIDと重複しないこと。パスワードは8文字以上で英字と数字を含むこと。氏名は1〜30文字であること
2. 登録したユーザーは権限を持たず、従業員としてのみ振る舞える(#83)。権限はユーザーの権限を変更する(UC-106)で、所属はユーザーの所属を設定する(UC-110)で扱う(暫定)
3. 削除済みユーザーのユーザーIDと同じユーザーIDは登録できない(暫定)
4. requirements.mdではアクターは「管理者」。本書ではシステム管理者と書く(#83)。改名は別途
