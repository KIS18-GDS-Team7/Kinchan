# UC-105 ユーザーの所属を設定する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ユーザーの所属を設定する(UC-105) |
| 目的 | アクターが所属が未設定のユーザーに所属を設定し、そのユーザーがその所属単位の従業員として振る舞える状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターがユーザーの所属の設定を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターがシステム管理者権限を持つこと<br>・対象のユーザーが登録されていること(UC-101)<br>・対象のユーザーが削除済みでないこと<br>・所属単位が登録されていること(UC-108) |
| 事後条件 | ・対象のユーザーの所属が指定された所属単位に設定されていること |
| 拡張点 | なし |
| 関連ユースケース | ・所属単位を登録する(UC-108)<br>・ユーザーの所属を編集する(UC-106)<br>・ユーザーを登録する(UC-101)<br>・ユーザー一覧を表示する(UC-107) |

## イベントフロー

### メインフロー

1. アクターはシステムにユーザーの所属の設定を要求する
2. システムはアクターに対象のユーザーの指定を求める
3. アクターはシステムに対象のユーザーを指定する
4. システムはアクターに登録されている所属単位を提示し、所属とする所属単位の指定を求める
5. アクターはシステムに所属とする所属単位を1つ指定する
6. システムはアクターに対象のユーザーと指定された所属単位を提示し、設定の確認を求める
7. アクターはシステムに設定を指示する
8. システムは対象のユーザーの所属を指定された所属単位に設定する
9. システムはアクターに所属の設定が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー4で、対象のユーザーの所属がすでに設定されていた場合

1. システムは対象のユーザーの所属がすでに設定されていることをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー7より前にアクターが設定のキャンセルを要求した場合

1. アクターはシステムに設定のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 対象のユーザーの所属が設定されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー6に戻る

事後条件

- 対象のユーザーの所属が設定されていないこと

## 備考

1. 所属は登録されている所属単位から1つ指定する。1ユーザーにつき所属は1つ(2026-10-21の会話)。所属単位は所属単位を登録する(UC-108)で登録する(#84)
2. 所属が未設定のユーザーが対象。所属が設定済みのユーザーの所属はユーザーの所属を編集する(UC-106)で変更する(A-21)
3. 所属が未設定のユーザーは、シフト・打刻・シフト希望・申請を扱う従業員のユースケースを実行できない(暫定)
4. UC名は暫定名(旧「ユーザーの所属店舗を設定する」。requirements.mdも改名済み)
5. アクター名はrequirements.mdと同じく「システム管理者」(#83。旧「管理者」)
6. 勤怠管理者の管理先は所属とは別のデータであり、勤怠管理者に管理先を割り当てる(UC-109)で割り当てる
