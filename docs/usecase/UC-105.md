# UC-105 ユーザーを削除する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ユーザーを削除する(UC-105) |
| 目的 | アクターがユーザーを削除し、そのユーザーがログインできず、勤怠記録・申請・履歴は参照できる状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターがユーザーの削除を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターがシステム管理者権限を持つこと<br>・対象のユーザーが登録されていること(UC-103)<br>・対象のユーザーが削除済みでないこと |
| 事後条件 | ・対象のユーザーが削除済みユーザーになっていること<br>・対象のユーザーがログインできないこと<br>・対象のユーザーの勤務日が翌日以降のシフトが削除され、削除履歴が記録されていること<br>・対象のユーザーの勤怠記録・申請・履歴が残っていること<br>・対象のユーザーに管理先が割り当てられていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザー一覧を表示する(UC-116)<br>・ログインする(UC-001)<br>・勤怠管理者に管理先を割り当てる(UC-118) |

## イベントフロー

### メインフロー

1. アクターはシステムにユーザーの削除を要求する
2. システムはアクターに対象のユーザーの指定を求める
3. アクターはシステムに対象のユーザーを指定する
4. システムはアクターに対象のユーザーの氏名・ユーザーID、対象のユーザーの勤務日が翌日以降のシフトの件数、削除によって割り当てが外れる管理先を提示し、削除の確認を求める
5. アクターはシステムに削除を指示する
6. システムは対象のユーザーの勤務日が翌日以降のシフトを削除履歴に記録する
7. システムは対象のユーザーの勤務日が翌日以降のシフトを削除する
8. システムは対象のユーザーを削除する
9. システムは対象のユーザーに割り当てられた管理先を外す
10. システムはアクターにユーザーの削除が完了したことを提示する

### 代替フロー

#### Alt-1: 対象のユーザーがアクター自身だった場合

1. システムは対象のユーザーがアクター自身であるため削除できないことをアクターに提示する
2. メインフロー2に戻る

### 例外フロー

#### Ex-1: メインフロー5より前にアクターが削除のキャンセルを要求した場合

1. アクターはシステムに削除のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- 対象のユーザーが削除されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー4に戻る

事後条件

- 対象のユーザーが削除されていないこと
- 対象のユーザーのシフトが削除されていないこと
- 対象のユーザーの管理先の割り当てが変更されていないこと

## 備考

1. 削除は論理削除とする(#86、A-19)。削除済みユーザーはログインできない(ログインする(UC-001)のEx-1)。ユーザー一覧を表示する(UC-116)では通常は除外し、「削除済みを含める」指定で参照できる
2. 削除済みユーザーの勤怠記録・申請・履歴は残す。削除済みユーザーの「未処理」の申請は勤怠管理者が処理できる(A-19)
3. 削除時に、対象のユーザーの勤務日が翌日以降のシフトを状態が「下書き」か「公開」かを問わず削除し、削除履歴に残す(A-19)。削除済みユーザーには通知しない(暫定)。削除履歴は削除できない
4. アクター自身は削除できない(A-20)。アクターはシステム管理者権限を持つため、最後のシステム管理者を削除する操作はアクター自身の削除に当たり、Alt-1で防ぐ(requirements.md 3章「最低一人は存在する」)
5. 対象のユーザーが勤怠管理者だった場合に管理先の割り当てを外すことは暫定。対象のユーザーに管理先が無い場合、メインフロー9で外す管理先は無い
6. 削除済みユーザーのユーザーIDと同じユーザーIDは登録できない(暫定。ユーザーを登録する(UC-103)のAlt-2)
7. requirements.mdではアクターは「管理者」。本書ではシステム管理者と書く(#83)。改名は別途
