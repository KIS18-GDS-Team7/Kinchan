# UC-106 ユーザーの権限を変更する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ユーザーの権限を変更する(UC-106) |
| 目的 | アクターがユーザーのシステム管理者権限・勤怠管理者権限の有無を変更し、そのユーザーが変更後の権限に基づく操作を行える状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターがユーザーの権限の変更を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターがシステム管理者権限を持つこと<br>・対象のユーザーが登録されていること(UC-103)<br>・対象のユーザーが削除済みでないこと |
| 事後条件 | ・対象のユーザーの権限が変更後の内容に更新されていること<br>・変更後の権限に勤怠管理者権限が含まれない場合、対象のユーザーに管理先が割り当てられていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーを登録する(UC-103)<br>・勤怠管理者に管理先を割り当てる(UC-118)<br>・ユーザー一覧を表示する(UC-116) |

## イベントフロー

### メインフロー

1. アクターはシステムにユーザーの権限の変更を要求する
2. システムはアクターに対象のユーザーの指定を求める
3. アクターはシステムに対象のユーザーを指定する
4. システムはアクターに対象のユーザーの現在の権限を提示し、変更後の権限(システム管理者権限・勤怠管理者権限それぞれの有無)の入力を求める
5. アクターはシステムに変更後の権限を入力する
6. システムはアクターに対象のユーザーの変更前と変更後の権限、および変更後の権限に勤怠管理者権限が含まれない場合は管理先の割り当てが外れることを提示し、変更の確認を求める
7. アクターはシステムに変更を指示する
8. システムは対象のユーザーの権限を変更後の内容に更新する
9. 変更後の権限に勤怠管理者権限が含まれない場合、システムは対象のユーザーに割り当てられた管理先を外す
10. システムはアクターに権限の変更が完了したことを提示する

### 代替フロー

#### Alt-1: 対象のユーザーがアクター自身だった場合

1. システムは対象のユーザーがアクター自身であるため権限を変更できないことをアクターに提示する
2. メインフロー2に戻る

### 例外フロー

#### Ex-1: メインフロー7より前にアクターが変更のキャンセルを要求した場合

1. アクターはシステムに変更のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 対象のユーザーの権限が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー6に戻る

事後条件

- 対象のユーザーの権限が変更されていないこと
- 対象のユーザーの管理先の割り当てが変更されていないこと

## 備考

1. 権限は「システム管理者権限」「勤怠管理者権限」の2つで、ユーザーに0個以上付加する。「従業員」は権限ではなく、すべてのユーザーが従業員として振る舞える(#83)。1人のユーザーが両方の権限を持てる(暫定)
2. 権限の付与も解除もこのユースケースで扱う(2026-10-21の会話)
3. アクター自身の権限は変更できない(A-20)。アクターはシステム管理者権限を持つため、最後のシステム管理者からシステム管理者権限を外す操作はアクター自身の権限の変更に当たり、Alt-1で防ぐ(requirements.md 3章「最低一人は存在する」)
4. 勤怠管理者権限を外した場合に管理先の割り当てを外すことは暫定。対象のユーザーに管理先が無い場合、メインフロー9で外す管理先は無い
5. UC名は暫定名。requirements.mdではUC-106「ユーザーに権限を付与する」とUC-107「ユーザーの権限を変更する」であり、このユースケースはその2つを統合した(2026-10-21の会話)。統合の反映は別途
6. requirements.mdではアクターは「管理者」。本書ではシステム管理者と書く(#83)。改名は別途
7. 勤怠管理者権限を付加したユーザーには、勤怠管理者に管理先を割り当てる(UC-118)で管理先を割り当てる
