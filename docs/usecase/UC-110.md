# UC-110 未使用の所属単位を削除する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 未使用の所属単位を削除する(UC-110) |
| 目的 | 現在・過去の参照がない所属単位だけを削除し、関連データを維持する |
| アクター | マスタ管理者 |
| 開始条件 | アクターが所属単位の削除を要求する |
| 事前条件 | アクターがログインしており(UC-301)、マスタ管理者権限を持つこと。対象の所属単位が登録されていること(UC-108) |
| 事後条件 | 対象が未使用の場合に限り、登録済みの所属単位から除外され、所属・管理先の選択肢に表示されないこと。ユーザー・管理先・シフト・シフト希望と申請・対象期間と受付期間・勤怠記録と履歴が変更されていないこと |
| 拡張点 | なし |
| 関連ユースケース | UC-108 所属単位を登録する、UC-105 ユーザーの所属を設定する、UC-106 ユーザーの所属を編集する、UC-109 勤怠管理者に管理先を割り当てる |

## イベントフロー

### メインフロー

1. アクターはシステムに所属単位の削除を要求する
2. システムは登録済みの所属単位の名称と削除可否を提示する。使用中の所属単位には削除できない理由を提示する
3. アクターはシステムに削除する所属単位を指定する
4. システムは対象が未使用の所属単位であることを判定する
5. システムは対象の所属単位名を提示し、削除の確認を求める
6. アクターはシステムに削除を指示する
7. システムはアクターの権限・対象の存在・未使用であることを再判定し、対象だけを登録済みの所属単位から除外する
8. システムは削除完了と更新後の所属単位を提示する

### 代替フロー

#### Alt-1: メインフロー4または7で、対象が使用中だった場合

1. システムは削除を行わず、使用中である理由を提示する
2. メインフロー2に戻る。最終確認後に使用中になった場合も削除しない

#### Alt-2: 登録済みの所属単位が存在しない場合、または対象が既に削除されている場合

1. システムは対象が存在しないことを提示し、データを変更しない

#### Alt-3: 操作時にマスタ管理者権限がない場合

1. システムは操作に必要な権限がないことを提示し、データを変更しない

### 例外フロー

#### Ex-1: 削除を指示する前にキャンセルした場合

1. システムは対象の選択を破棄し、キャンセル完了を提示する
2. システムは所属単位と関連データを変更しない

#### Ex-2: 削除の保存に失敗した場合

1. システムは削除失敗を提示し、所属単位と関連データを変更しない
2. システムは対象名を保持したまま、再度削除の確認を求める。再試行時も権限・存在・未使用を再判定する

## 備考

1. 「未使用の所属単位」「所属単位の参照履歴」は要件定義書4章の定義を使用する。所属している人数が0人であることだけでは未使用としない
2. 削除済みユーザーの所属・管理先、非公開・下書き・過去のシフト、下書き・未処理・承認済み・却下・取り下げ等の状態を問わないシフト希望と申請、過去の対象期間と受付期間、勤怠記録とそれらの履歴も判定する
3. 所属変更や管理先の解除等で現在の参照が外れても、所属単位の参照履歴を残して削除を防ぐ。過去の参照が判定不能なデータを未使用とは扱わない
4. 関連データの連動削除、所属・管理先の自動解除、使用中の所属単位の閉鎖、所属単位名の変更、削除後の復元はこのユースケースに含めない
5. ユーザーが承認した「未使用の所属だけ削除」の方針をPR #120で記載し、その後モックに実装する。mainへの取り込み前の追加仕様であり、他のTBDを確定しない。IDは新設の暫定番号で、旧番号のUC-110(現UC-105)とは異なる
