# UC-117 所属単位を登録する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 所属単位を登録する(UC-117) |
| 目的 | アクターが所属単位を登録し、ユーザーの所属や勤怠管理者の管理先として指定できる状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターが所属単位の登録を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターがシステム管理者権限を持つこと |
| 事後条件 | ・入力された名称で所属単位が登録されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーの所属を設定する(UC-110)<br>・ユーザーの所属を編集する(UC-111)<br>・勤怠管理者に管理先を割り当てる(UC-118) |

## イベントフロー

### メインフロー

1. アクターはシステムに所属単位の登録を要求する
2. システムはアクターに所属単位の名称の入力を求める
3. アクターはシステムに所属単位の名称を入力する
4. システムは入力された名称を検証する
5. システムはアクターに入力された名称を提示し、登録の確認を求める
6. アクターはシステムに登録を指示する
7. システムは所属単位を登録する
8. システムはアクターに所属単位の登録が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー4で、名称が入力されていなかった場合

1. システムは名称の入力が必要であることをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: メインフロー4で、入力された名称が登録済みの所属単位の名称と重複していた場合

1. システムは名称が重複していることをアクターに提示する
2. メインフロー2に戻る

### 例外フロー

#### Ex-1: メインフロー6より前にアクターが登録のキャンセルを要求した場合

1. アクターはシステムに登録のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 所属単位が登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムが所属単位の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー5に戻る

事後条件

- 所属単位が登録されていないこと

## 備考

1. このユースケースは#84で新設した(#84の表現は「所属単位を作成する」)。所属単位は従業員が所属し、勤怠管理者が管理する単位で、名称を持つ。所属単位は入れ子にしない(#84)
2. 名称は必須で、同じ名称の所属単位は登録できない(暫定)
3. 所属単位の変更・削除はTBD(要起票)
4. 1つの所属単位に置ける勤怠管理者の人数はTBD(#39)
5. 新設のユースケースであり、IDは仮。requirements.mdには無く、追記は別途
6. 登録した所属単位は、ユーザーの所属を設定する(UC-110)・ユーザーの所属を編集する(UC-111)で所属として、勤怠管理者に管理先を割り当てる(UC-118)で管理先として指定する
