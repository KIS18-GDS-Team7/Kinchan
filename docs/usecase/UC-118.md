# UC-118 勤怠管理者に管理先を割り当てる

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠管理者に管理先を割り当てる(UC-118) |
| 目的 | アクターが勤怠管理者権限を持つユーザーに管理先を割り当て、そのユーザーが管理先の従業員の勤怠・シフト・申請を扱える状態にする |
| アクター | システム管理者 |
| 開始条件 | アクターが管理先の割り当てを要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターがシステム管理者権限を持つこと<br>・対象のユーザーが削除済みでないこと<br>・所属単位が登録されていること(UC-117) |
| 事後条件 | ・対象のユーザーの管理先が指定された所属単位(1つ以上)に更新されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーの権限を変更する(UC-106)<br>・所属単位を登録する(UC-117)<br>・ユーザー一覧を表示する(UC-116) |

## イベントフロー

### メインフロー

1. アクターはシステムに管理先の割り当てを要求する
2. システムはアクターに対象のユーザー(勤怠管理者権限を持つユーザー)の指定を求める
3. アクターはシステムに対象のユーザーを指定する
4. システムはアクターに対象のユーザーの現在の管理先と登録されている所属単位を提示し、変更後の管理先とする所属単位の指定を求める
5. アクターはシステムに変更後の管理先とする所属単位を1つ以上指定する
6. システムは指定された管理先を検証する
7. システムはアクターに対象のユーザーの変更前と変更後の管理先を提示し、割り当ての確認を求める
8. アクターはシステムに割り当てを指示する
9. システムは対象のユーザーの管理先を指定された所属単位に更新する
10. システムはアクターに管理先の割り当てが完了したことを提示する

### 代替フロー

#### Alt-1: 対象のユーザーが勤怠管理者権限を持っていなかった場合

1. システムは対象のユーザーが勤怠管理者権限を持たないため管理先を割り当てられないことをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: 管理先とする所属単位が1つも指定されていなかった場合

1. システムは管理先とする所属単位を1つ以上指定する必要があることをアクターに提示する
2. メインフロー4に戻る

### 例外フロー

#### Ex-1: メインフロー8より前にアクターが割り当てのキャンセルを要求した場合

1. アクターはシステムに割り当てのキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 対象のユーザーの管理先が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがユーザーの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー7に戻る

事後条件

- 対象のユーザーの管理先が変更されていないこと

## 備考

1. このユースケースは2026-10-21の会話で新設した。管理先は勤怠管理者が従業員の勤怠・シフト・申請を扱う所属単位で、1人の勤怠管理者は1つ以上の所属単位を管理先に持てる(#84)。管理先は従業員としての所属とは別のデータであり、所属はユーザーの所属を設定する(UC-110)・ユーザーの所属を編集する(UC-111)で扱う(2026-10-21の会話)
2. 初回の割り当ても、割り当て後の変更もこのユースケースで行う
3. アクターをシステム管理者とすることは暫定
4. ユーザーの権限を変更する(UC-106)で勤怠管理者権限を付けてから、このユースケースで管理先を割り当てるまでの間、管理先が無い勤怠管理者がいることを許す(暫定)。#84の「1..*」は割り当て後の多重度と読む
5. 1つの所属単位に複数の勤怠管理者を置けるかはTBD(#39)
6. 所属単位を管理先に持つ勤怠管理者がいなくなる場合の扱いはTBD(要起票)
7. 新設のユースケースであり、IDは仮。requirements.mdには無く、追記は別途
8. 対象のユーザーから勤怠管理者権限を外したとき(ユーザーの権限を変更する(UC-106))と、対象のユーザーを削除したとき(ユーザーを削除する(UC-105))は、管理先の割り当てを外す(暫定)
