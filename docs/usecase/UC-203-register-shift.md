# UC-203 シフトを登録する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフトを登録する(UC-203) |
| 目的（ゴール） | 従業員の勤務予定(シフト)を登録し、従業員の登録シフトとして提示できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者がシフト登録要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・対象となる従業員が登録されていること<br>・対象の従業員がアクターの担当する店舗に所属していること |
| 事後条件 | ・指定した従業員のシフトが登録されていること<br>・対象の従業員にシフトが登録されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | なし |

## イベントフロー

### メインフロー

1. アクターはシステムにシフトの登録を要求する
2. システムはアクターに担当する店舗の従業員の中から対象となる従業員の指定を求める
3. アクターはシステムに対象となる従業員を指定する
4. システムはアクターにシフト情報(勤務日、開始時刻、終了時刻)の入力を求める
5. アクターはシステムにシフト情報を入力する
6. システムは入力されたシフト情報が有効なものか、従業員の勤務可能時間の範囲内か確認する
7. システムはアクターに入力されたシフト情報を提示し、登録の確認を求める
8. アクターはシステムに登録を指示する
9. システムはシフトを登録する
10. システムは対象の従業員にシフトが登録されたことを通知する
11. システムはアクターに登録が完了したことを提示する

### 代替フロー

**Alt-1：入力されたシフト情報が誤っていた場合(終了時刻が開始時刻より前など)**

1. システムは入力されたシフト情報に誤りがあることをアクターに提示する
2. メインフロー4に戻る

**Alt-2：同じ従業員の登録済みシフトと日時が重複していた場合**

1. システムは重複しているシフトをアクターに提示する
2. メインフロー4に戻る

**Alt-3：入力されたシフトが従業員の勤務可能時間の範囲外だった場合**

1. システムは範囲外であることと、従業員の勤務可能時間をアクターに提示する
2. メインフロー4に戻る

### 例外フロー

**Ex-1：メインフロー8より前にアクターが登録のキャンセルを要求した場合**

1. アクターはシステムに登録のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフトが登録されていないこと
- システムが待機状態に戻っていること

## 備考

1. 休憩時間は管理者が設定したもの(UC-114)を適用する
2. 勤務可能時間は管理者が設定したもの(UC-112)を使う
3. 従業員への通知方法(アプリ内通知、メールなど)はTBD。登録したシフトは従業員側の「登録シフトを確認する(UC-308)」で表示される
