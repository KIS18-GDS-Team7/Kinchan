# UC-203 シフトを削除する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフトを削除する(UC-203) |
| 目的 | アクターが不要になったシフトを削除し、そのシフトが従業員に表示されない状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフトの削除を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109)<br>・対象のシフトが登録されていること<br>・対象の従業員が管理先の従業員であること |
| 事後条件 | ・対象のシフトが削除されていること<br>・削除したシフトの内容が削除履歴として記録されていること<br>・対象のシフトが公開済みだった場合、(対象の従業員が削除済みユーザーでなければ)対象の従業員にシフトが削除されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフトを登録する(UC-201)<br>・シフトを公開する(UC-216)<br>・ユーザーを削除する(UC-103) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフトの削除を要求する
2. システムはアクターに削除するシフトの指定を求める
3. アクターはシステムに削除するシフトを指定する
4. システムはアクターに指定されたシフトの内容(従業員、勤務日、開始時刻、終了時刻、状態)を提示し、削除の確認を求める
5. アクターはシステムに削除を指示する
6. システムは削除するシフトの内容を削除履歴として記録する
7. システムはシフトを削除する
8. システムは、対象の従業員が削除済みユーザーでなければ、対象の従業員にシフトが削除されたことを通知する
9. システムはアクターに削除が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー4で、指定されたシフトがすでに勤務済み、または勤務中だった場合

1. システムは勤務済み・勤務中のシフトは削除できないことをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: メインフロー8で、対象のシフトの状態が「下書き」だった場合

1. システムは対象の従業員に通知しない
2. メインフロー9に進む

### 例外フロー

#### Ex-1: メインフロー5より前にアクターが削除のキャンセルを要求した場合

1. アクターはシステムに削除のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフトが削除されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフトの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー4に戻る

事後条件

- シフトが削除されていないこと
- 削除履歴が記録されていないこと

## 備考

1. 公開済みのシフトを削除したときだけ対象の従業員に通知し、下書きのシフトの削除は通知しない(#87の再起票からの導出、暫定)。削除済みユーザーには通知しない(#86、A-19からの導出、暫定)
2. 勤務済み・勤務中のシフトは削除できない(A-35)。勤務済み・勤務中の判定はシフトを変更する(UC-202)と同じ(暫定)。勤務済みの記録を直す場合は勤怠を修正する(UC-210)を使う
3. 削除したシフトを元に戻す操作は無い(A-37)。削除した内容は削除履歴に残る
4. 削除履歴は、削除した内容・操作者・操作日時を記録したもので、削除できない。削除履歴を提示するユースケースは無く、扱いはTBD(要起票)
5. 対象の従業員に削除済みユーザーを指定できるかはTBD(要起票)
6. ユーザーを削除する(UC-103)では、削除するユーザーの勤務日が翌日以降のシフト(下書き・公開とも)をシステムが削除して削除履歴に残す(#86、A-19)。そのときは削除済みユーザーに通知しない(#86、A-19からの導出、暫定)
