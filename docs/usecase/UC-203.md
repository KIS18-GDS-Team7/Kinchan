# UC-203 シフトを登録する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフトを登録する(UC-203) |
| 目的 | アクターが管理先の従業員のシフトを下書きとして登録し、シフトを公開する(UC-218)で公開できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフトの登録を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること |
| 事後条件 | ・対象の従業員のシフトが状態「下書き」で登録されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフトを公開する(UC-218)<br>・シフトを変更する(UC-204)<br>・シフトを削除する(UC-205)<br>・シフト希望の対象期間・受付期間を登録する(UC-217) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフトの登録を要求する
2. システムはアクターに管理先の従業員の中から対象の従業員の指定を求める
3. アクターはシステムに対象の従業員を指定する
4. システムはアクターにシフトの内容(勤務日、開始時刻、終了時刻)の入力を求める
5. アクターはシステムにシフトの内容を入力する
6. システムは入力されたシフトの内容を検証する
7. システムは入力されたシフトが同じ従業員の他のシフトと重複するかを判定する
8. システムはアクターに入力されたシフトの内容を提示し、登録の確認を求める
9. アクターはシステムに登録を指示する
10. システムはシフトを状態「下書き」で登録する
11. システムはアクターに登録が完了したことを提示する

### 代替フロー

#### Alt-1: 入力されたシフトの内容に誤りがあった場合

1. システムは入力されたシフトの内容に誤りがあることをアクターに提示する
2. メインフロー4に戻る

#### Alt-2: 入力された勤務日が過去日だった場合

1. システムは過去日にシフトを登録できないことをアクターに提示する
2. メインフロー4に戻る

#### Alt-3: 入力されたシフトが同じ従業員の他のシフトと重複していた場合

1. システムは重複しているシフトをアクターに提示する
2. メインフロー4に戻る

#### Alt-4: 入力された勤務日が対象の従業員の所属に登録された対象期間に含まれなかった場合

1. システムは対象期間に含まれない勤務日にシフトを登録できないことをアクターに提示する
2. メインフロー4に戻る

### 例外フロー

#### Ex-1: メインフロー9より前にアクターが登録のキャンセルを要求した場合

1. アクターはシステムに登録のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフトが登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフトの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー8に戻る

事後条件

- シフトが登録されていないこと

## 備考

1. 登録したシフトは下書きであり、シフトを公開する(UC-218)で公開するまで従業員に提示されない(#87の再起票、2026-10-21の会話)。このユースケースでは従業員に通知しない。通知はシフトを公開する(UC-218)で出す(#87の再起票からの導出、暫定)
2. 勤務日は当日以降とする(A-77)。過去の勤務の記録は勤怠を修正する(UC-212)で扱う
3. 勤務日は、対象の従業員の所属(アクターの管理先)にシフト希望の対象期間・受付期間を登録する(UC-217)で登録された対象期間に含まれる日に限る(2026-10-22の会話)
4. 1日に同じ従業員のシフトを複数登録できる。重複は時刻の重なりで判定する(A-33)
5. 日をまたぐシフトは、終了時刻が開始時刻より前であることで表す。終了時刻は翌日の時刻として扱う(#82)。Alt-1の誤りとは、勤務日・開始時刻・終了時刻の未入力と、終了時刻が開始時刻と同じ入力を指す(暫定)
6. シフトの状態は「下書き」「公開」の2値(#87の再起票)。下書きのシフトはアクターだけが参照でき、シフトを一覧表示する(UC-308)では公開するまで提示されない
7. シフト希望を承認する(UC-207)で承認して登録するシフトは状態「公開」で登録され、下書きにならない。シフトを公開する(UC-218)で公開する対象は、このユースケースで登録した下書きのシフトだけ(#87、2026-10-22の会話)
