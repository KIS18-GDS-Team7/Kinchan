# UC-204 シフト希望を一覧表示する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を一覧表示する(UC-204) |
| 目的 | アクターが管理先の従業員から送信されたシフト希望を一覧と詳細で表示し、シフト希望を承認・却下できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト希望の一覧表示を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109) |
| 事後条件 | ・アクターにシフト希望の一覧と、指定したシフト希望の詳細が提示されていること |
| 拡張点 | ・アクターが指定した「未処理」のシフト希望の承認を要求した場合(メインフロー4の後)<br>・アクターが指定した「未処理」のシフト希望の却下を要求した場合(メインフロー4の後) |
| 関連ユースケース | ・シフト希望を承認する(UC-205)≪extend≫<br>・シフト希望を却下する(UC-206)≪extend≫<br>・シフト希望の対象期間・受付期間を登録する(UC-215)<br>・シフト希望を送信する(UC-307)<br>・シフト希望を取り下げる(UC-315) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の一覧表示を要求する
2. システムはアクターに管理先の従業員から送信された「未処理」のシフト希望の一覧(従業員名、所属単位、希望日、希望開始時刻・希望終了時刻、送信日時)を提示する
3. アクターはシステムに詳細を提示するシフト希望を指定する
4. システムはアクターに指定されたシフト希望の詳細(従業員名、所属単位、対象期間、希望日、希望開始時刻、希望終了時刻、処理状態、却下理由(「却下」のとき)、送信日時)と、希望日に登録済みの同じ所属単位のシフトを提示する

### 代替フロー

#### Alt-1: メインフロー2で、「未処理」のシフト希望が存在しなかった場合

1. システムは「未処理」のシフト希望が存在しないことをアクターに提示する
2. Alt-2の1に進む

#### Alt-2: アクターが条件(期間、従業員、処理状態、管理先)を指定して探す場合

1. アクターはシステムに条件を指定する
2. システムは指定された条件を検証する
3. システムはアクターに条件に合うシフト希望の一覧を提示する
4. メインフロー3に戻る

#### Alt-3: Alt-2の2で、指定された期間の開始日が終了日より後だった場合

1. システムは期間の指定に誤りがあることをアクターに提示する
2. Alt-2の1に戻る

#### Alt-4: Alt-2の1で、アクターが削除済みユーザーを含めることを指定した場合

1. システムはアクターに削除済みユーザーのシフト希望を含めた一覧を提示する
2. メインフロー3に戻る

#### Alt-5: Alt-2の3で、条件に合うシフト希望が存在しなかった場合

1. システムは条件に合うシフト希望が存在しないことをアクターに提示する
2. Alt-2の1に戻る

### 例外フロー

なし

## 備考

1. 提示するのは管理先の従業員のシフト希望だけ(#84、2026-10-21の会話)。管理先が複数ある場合はすべての管理先の分を提示し、Alt-2の条件で管理先を絞れる(#84からの導出、暫定)
2. 処理状態が「下書き」のシフト希望は提示しない(#87)。初期の一覧は「未処理」のシフト希望を提示し、Alt-2で「承認済」「却下」「取り下げ」も提示できる(2026-10-22の会話)
3. Alt-2の期間は希望日で絞る(暫定)
4. 削除済みユーザーのシフト希望は削除せずに残し、通常は提示しない。Alt-4で提示できる(#86、A-19)。削除済みユーザーの「未処理」のシフト希望は却下だけできる。承認はできない(2026-10-22の会話)
5. 従業員がシフト希望を送信すると、その従業員の所属を管理先に持つ勤怠管理者に通知される(#96)。取り下げは通知されない(2026-10-22の会話)。一覧はこのユースケースで提示する
6. シフト希望の対象期間・受付期間は、シフト希望の対象期間・受付期間を登録する(UC-215)で登録する。シフト希望は、シフト希望を送信する(UC-307)で従業員が送信し、シフト希望を取り下げる(UC-315)で取り下げる
7. 承認・却下の結果は、シフト希望を一覧表示する(UC-311)で従業員に提示される
