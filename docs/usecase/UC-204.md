# UC-204 シフトを変更する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフトを変更する(UC-204) |
| 目的 | 勤怠管理者が登録済みのシフトの勤務日・開始時刻・終了時刻を変更し、公開済みのシフトであれば変更後の内容が従業員に表示される状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフトの変更を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象のシフトが登録されていること<br>・対象の従業員が管理先の従業員であること |
| 事後条件 | ・対象のシフトが変更後の内容に更新されていること<br>・変更前の内容が変更履歴として記録されていること<br>・対象のシフトが公開済みだった場合、対象の従業員にシフトが変更されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | シフトを登録する(UC-203)<br>シフトを公開する(UC-218)<br>勤怠を修正する(UC-212)<br>シフト日時変更申請を承認する(UC-215) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフトの変更を要求する
2. システムはアクターに変更するシフトの指定を求める
3. アクターはシステムに変更するシフトを指定する
4. システムはアクターに指定されたシフトの現在の内容(従業員、勤務日、開始時刻、終了時刻、状態)を提示し、変更後の内容(勤務日、開始時刻、終了時刻)の入力を求める
5. アクターはシステムに変更後の内容を入力する
6. システムは入力された変更後の内容を検証する
7. システムは変更後のシフトが同じ従業員の他のシフトと重複するかを判定する
8. システムはアクターに変更前と変更後の内容を提示し、変更の確認を求める
9. アクターはシステムに変更を指示する
10. システムは変更前の内容を変更履歴として記録する
11. システムはシフトを変更後の内容に更新する
12. システムは対象の従業員にシフトが変更されたことを通知する
13. システムはアクターに変更が完了したことを提示する

### 代替フロー

#### Alt-1: 指定されたシフトがすでに勤務済みだった場合

1. システムは勤務済みのシフトは変更できないことをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: 入力された変更後の内容に誤りがあった場合

1. システムは入力された変更後の内容に誤りがあることをアクターに提示する
2. メインフロー4に戻る

#### Alt-3: 入力された変更後の勤務日が過去日だった場合

1. システムは過去日にシフトを変更できないことをアクターに提示する
2. メインフロー4に戻る

#### Alt-4: 入力された変更後の内容が変更前と同じだった場合

1. システムは変更後の内容が変更前と同じであることをアクターに提示する
2. メインフロー4に戻る

#### Alt-5: 変更後のシフトが同じ従業員の他のシフトと重複していた場合

1. システムは重複しているシフトをアクターに提示する
2. メインフロー4に戻る

#### Alt-6: 対象のシフトの状態が「下書き」だった場合

1. システムは対象の従業員に通知しない
2. メインフロー13に進む

### 例外フロー

#### Ex-1: メインフロー9より前にアクターが変更のキャンセルを要求した場合

1. アクターはシステムに変更のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフトが変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフトの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー8に戻る

事後条件

- シフトが変更されていないこと
- 変更履歴が記録されていないこと

## 備考

1. 公開済みのシフトを変更しても、状態は「公開」のまま(#87の再起票)。公開済みのシフトを変更したときだけ対象の従業員に通知し、下書きのシフトの変更は通知しない(2026-10-21 の会話)
2. 勤務済みのシフトは変更できない。勤務中のシフトは変更できる(A-35)。勤務済みとは、シフトの終了日時(勤務日+終了時刻。日をまたぐ場合は翌日)を現在時刻が過ぎていること。勤務中とは、シフトの開始日時を過ぎ、終了日時を過ぎていないこと。いずれもシフトの時刻と現在時刻で判定し、打刻は見ない(暫定)
3. 勤務済みの記録を直す場合は勤怠を修正する(UC-212)を使う
4. 変更の期限は設けない(A-36)。変更後の勤務日は当日以降とする(A-77)
5. 変更後の内容が変更前と同じ場合は受け付けない。内容が同じ変更履歴・通知を作らないため(A-83)
6. 変更履歴は、変更前の内容・操作者・操作日時を記録したもので、削除できない。変更履歴を提示するユースケースは無く、扱いはTBD(要起票)
7. 日をまたぐシフトの表し方と、Alt-2の誤りの内容は、シフトを登録する(UC-203)と同じ
8. 従業員が自分のシフトの日時の変更を求める場合はシフト日時変更申請を送信する(UC-309)で送信し、勤怠管理者はシフト日時変更申請を承認する(UC-215)で承認する
