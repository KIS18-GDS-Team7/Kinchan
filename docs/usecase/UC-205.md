# UC-205 シフト希望を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を承認する(UC-205) |
| 目的 | アクターがシフト希望を承認し、希望の内容のシフトが状態「公開」で登録され、従業員に提示される状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト希望を一覧表示する(UC-204)で「未処理」のシフト希望を指定して承認を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109)<br>・対象の従業員が管理先の従業員であること<br>・対象のシフト希望の処理状態が「未処理」であること |
| 事後条件 | ・対象のシフト希望の処理状態が「承認済」になっていること<br>・シフト希望の内容(希望日、希望開始時刻、希望終了時刻)でシフトが状態「公開」で登録されていること<br>・希望を送信した従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフト希望を一覧表示する(UC-204)<br>・シフト希望を却下する(UC-206)<br>・シフトを公開する(UC-216)<br>・シフト希望の対象期間・受付期間を登録する(UC-215)<br>・シフト希望を送信する(UC-307)<br>・シフト希望を一覧表示する(UC-311)<br>・シフト希望を取り下げる(UC-315)<br>・シフトを一覧表示する(UC-308)<br>・シフト日時変更申請を承認する(UC-213)<br>・ユーザーの所属を編集する(UC-106) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の承認を要求する
2. システムはアクターに承認するシフト希望の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは対象のシフト希望の処理状態が「未処理」であること、対象の従業員が削除済みでないこと、希望日が当日以降であること、希望日が対象の従業員の所属に登録された対象期間に含まれることを検証する
5. システムは希望日時が同じ従業員の他のシフトと重複するかを判定する
6. システムはシフト希望の処理状態を「承認済」に更新する
7. システムはシフト希望の内容(希望日、希望開始時刻、希望終了時刻)でシフトを状態「公開」で登録する
8. システムは希望を送信した従業員に承認結果を通知する
9. システムはアクターに承認が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー5で、希望日時が登録済みのシフトと重複していた場合

1. システムは重複しているシフトをアクターに提示する
2. システムはそのシフト希望を承認できないことをアクターに提示する
3. シフト希望を一覧表示する(UC-204)に戻る

#### Alt-2: メインフロー4で、対象のシフト希望の処理状態が「未処理」でなくなっていた場合

1. システムは対象のシフト希望が承認できない状態であることをアクターに提示する
2. シフト希望を一覧表示する(UC-204)に戻る

#### Alt-3: メインフロー2で、対象のシフト希望がアクター自身のシフト希望だった場合

1. システムは対象がアクター自身のシフト希望であることをアクターに提示する
2. メインフロー3に進む

#### Alt-4: メインフロー4で、対象の従業員が削除済みユーザーだった場合

1. システムは削除済みユーザーのシフト希望は承認できないことをアクターに提示する
2. シフト希望を一覧表示する(UC-204)に戻る

#### Alt-5: メインフロー4で、希望日が当日より前だった場合

1. システムは希望日が当日より前のシフト希望は承認できないことをアクターに提示する
2. シフト希望を一覧表示する(UC-204)に戻る

#### Alt-6: メインフロー4で、希望日が対象の従業員の所属に登録された対象期間に含まれなかった場合

1. システムは希望日が対象期間に含まれないことをアクターに提示する
2. システムはそのシフト希望を承認できないことをアクターに提示する
3. シフト希望を一覧表示する(UC-204)に戻る

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが承認のキャンセルを要求した場合

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト希望の処理状態が変更されていないこと
- シフトが登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー2に戻る

事後条件

- シフト希望の処理状態が変更されていないこと
- シフトが登録されていないこと

## 備考

1. 承認で登録するシフトは状態「公開」であり、承認した時点で従業員に提示される。承認結果の通知が公開の通知を兼ね、公開の通知を別に出さない。シフトを公開する(UC-216)で公開する対象はシフトを登録する(UC-201)で登録した下書きのシフトだけであり、このユースケースで登録したシフトは対象でない(#87、2026-10-22の会話)
2. 承認時にアクターがシフト希望の内容(時間帯)を調整するステップは無い(#91からの導出、暫定)。調整が必要な場合はシフト希望を却下する(UC-206)で却下するか、シフトを登録する(UC-201)で登録する
3. シフト希望は1件ずつ承認する。複数のシフト希望をまとめて承認することはしない(2026-10-22の会話。A-45は不採用)。承認できなかったシフト希望の処理状態は「未処理」のまま残る
4. Alt-2は、シフト希望を一覧表示する(UC-204)で一覧を提示した後に、他の勤怠管理者が承認・却下した、または従業員が取り下げた場合に当たる。取り下げは従業員がシフト希望を取り下げる(UC-315)で行う。承認・却下するのは、承認(却下)を指示した時点のシフト希望の内容である。一覧を提示した後に従業員が内容を変更していても、処理状態が「未処理」のままであれば止めない(暫定)
5. 希望日が当日より前のシフト希望は承認できない(A-77からの導出、暫定)。シフトを登録する(UC-201)・シフトを変更する(UC-202)の勤務日の扱いに揃える
6. 希望日は、シフト希望の対象期間・受付期間を登録する(UC-215)で対象の従業員の所属に登録された対象期間に含まれる日に限る(2026-10-22の会話)
7. 削除済みユーザーの「未処理」のシフト希望は却下だけできる。承認はできない(2026-10-22の会話)。ユーザーを削除する(UC-103)で勤務日が翌日以降のシフトを削除するため(A-19)。却下はシフト希望を却下する(UC-206)で行う
8. アクターの所属がアクターの管理先に含まれる場合、アクター自身のシフト希望を承認できる(A-55)
9. 重複は時刻の重なりで判定する(A-33)。日をまたぐシフト希望は、希望終了時刻が希望開始時刻より前であることで表し、希望日の翌日の時刻として扱う(#82からの導出、暫定)
10. ユーザーの所属を編集する(UC-106)で所属を変更した後、および対象期間を変更・削除した後の、既存のシフトと「未処理」のシフト希望・シフト日時変更申請(変更前の対象期間に含まれる日を対象とするもの)の扱いはTBD(要起票)。対象になる操作は、シフトを公開する(UC-216)での下書きの公開、シフトを一覧表示する(UC-308)での提示、このユースケース・シフト日時変更申請を承認する(UC-213)での承認。対象期間の変更・削除はシフト希望の対象期間・受付期間を登録する(UC-215)でTBD
11. 承認結果は、シフト希望を一覧表示する(UC-311)で従業員に提示される。登録したシフトは、シフトを一覧表示する(UC-308)で従業員に提示される
