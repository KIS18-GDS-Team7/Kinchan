# UC-207 シフト希望を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を承認する(UC-207) |
| 目的 | 勤怠管理者がシフト希望を承認し、希望の内容のシフトが下書きとして登録された状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト希望を一覧表示する(UC-206)で未処理のシフト希望を指定して承認を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること<br>・対象のシフト希望の処理状態が「未処理」であること |
| 事後条件 | ・対象のシフト希望の処理状態が「承認済」になっていること<br>・シフト希望の内容(希望日、希望開始時刻、希望終了時刻)でシフトが状態「下書き」で登録されていること<br>・希望を送信した従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | シフト希望を一覧表示する(UC-206)<br>シフトを公開する(UC-218)<br>シフト希望を一覧表示する(UC-311) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望(1件以上)の承認を要求する
2. システムはアクターに承認するシフト希望の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは承認するシフト希望のそれぞれについて、希望日時が同じ従業員の他のシフトと重複するかを判定する
5. システムはシフト希望の処理状態を「承認済」に更新する
6. システムはシフト希望の内容(希望日、希望開始時刻、希望終了時刻)でシフトを状態「下書き」で登録する
7. システムは希望を送信した従業員に承認結果を通知する
8. システムはアクターに承認が完了したことを提示する

### 代替フロー

#### Alt-1: 希望日時が同じ従業員の他のシフトと重複していた場合

1. システムは重複しているシフトと、そのシフト希望を承認できないことをアクターに提示する
2. システムはそのシフト希望の処理状態を「未処理」のまま残す
3. 承認できるシフト希望が残っていれば、それらについてメインフロー5に進む
4. 承認できるシフト希望が残っていなければ、シフト希望を一覧表示する(UC-206)に戻る

#### Alt-2: 対象のシフト希望がすでに処理済みだった場合

1. システムは対象のシフト希望が承認できない状態であることをアクターに提示する
2. システムはそのシフト希望の処理状態を変更しない
3. 承認できるシフト希望が残っていれば、それらについてメインフロー5に進む
4. 承認できるシフト希望が残っていなければ、シフト希望を一覧表示する(UC-206)に戻る

#### Alt-3: 対象がアクター自身のシフト希望だった場合

1. システムは対象がアクター自身のものであることをアクターに提示する
2. メインフロー3に進む

#### Alt-4: 対象のシフト希望の種別が「休日希望」だった場合

1. システムは休日希望は承認の対象でないことをアクターに提示する
2. シフト希望を一覧表示する(UC-206)に戻る

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが承認のキャンセルを要求した場合

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト希望の処理状態が変わっていないこと
- シフトが登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー2に戻る

事後条件

- シフト希望の処理状態が変わっていないこと
- シフトが登録されていないこと

## 備考

1. 承認で登録したシフトは下書きであり、シフトを公開する(UC-218)で公開するまで従業員に提示されない(暫定)。承認結果の通知はこのユースケースで出し、シフトが公開されたことの通知はシフトを公開する(UC-218)で出す
2. 承認時にアクターがシフト希望の内容(時間帯)を調整するステップは無い(#91の理由をシフト希望にも適用、暫定)。調整が必要な場合はシフト希望を却下する(UC-208)で却下するか、シフトを登録する(UC-203)で登録する
3. 複数のシフト希望をまとめて承認できる(A-45、暫定)。1件ずつ判定し、承認できなかった件は理由を提示して処理状態を「未処理」のまま残す
4. 「処理済み」とは、処理状態が「承認済」「却下」「取り下げ」のいずれかであること。取り下げは従業員がシフト希望を取り下げる(UC-315)で行う
5. 種別が「休日希望」のシフト希望は承認・却下の対象にしない(A-41、暫定)。承認できるのは種別が「時間指定」のシフト希望だけ(#89)
6. アクターの所属がアクターの管理先に含まれる場合、アクター自身のシフト希望を承認できる(A-55)
7. 重複は時刻の重なりで判定する(A-33)。日をまたぐシフト希望は、希望終了時刻が希望開始時刻より前であることで表し、希望日の翌日の時刻として扱う(#82)
8. 承認結果は従業員のシフト希望を一覧表示する(UC-311)で提示される
