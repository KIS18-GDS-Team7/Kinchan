# UC-207 勤怠修正申請を一覧表示する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を一覧表示する(UC-207) |
| 目的 | アクターが管理先の従業員から送信された勤怠修正申請の一覧と詳細を表示できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターが勤怠修正申請の一覧表示を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109) |
| 事後条件 | ・アクターに勤怠修正申請の一覧と、指定した勤怠修正申請の詳細が提示されていること |
| 拡張点 | ・「未処理」の勤怠修正申請の承認・却下(メインフロー6の後。条件: アクターが指定した「未処理」の勤怠修正申請の承認または却下を要求した場合) |
| 関連ユースケース | ・勤怠修正申請を承認する(UC-208)≪extend≫<br>・勤怠修正申請を却下する(UC-209)≪extend≫ |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の一覧表示を要求する
2. システムはアクターに管理先の従業員の「未処理」の勤怠修正申請の一覧(従業員名、対象日、修正後の打刻の一覧、申請理由、送信日時)を提示する
3. アクターはシステムに詳細を提示する勤怠修正申請を指定する
4. システムはアクターに指定された勤怠修正申請の詳細(対象日の現在の勤怠記録、修正後の打刻の一覧、申請理由、処理状態、却下理由(「却下」のとき))を提示する
5. システムは修正後の打刻の一覧が対象日のシフトと矛盾しているかを判定する
6. システムはアクターに判定の結果(矛盾の有無。対象日にシフトがある場合は、シフトの開始時刻・終了時刻と修正後の打刻日時との差(分))を提示する

### 代替フロー

#### Alt-1: メインフロー2で、該当する勤怠修正申請が存在しなかった場合

1. システムは該当する勤怠修正申請が存在しないことをアクターに提示する
2. Alt-2の1に進む

#### Alt-2: アクターが条件(期間、従業員、処理状態、管理先)を指定して探す場合

1. アクターはシステムに条件を指定する
2. システムは指定された条件を検証する
3. システムはアクターに条件に合う勤怠修正申請の一覧を提示する
4. メインフロー3に戻る

#### Alt-3: Alt-2の2で、指定された期間の開始日が終了日より後だった場合

1. システムは期間の指定に誤りがあることをアクターに提示する
2. Alt-2の1に戻る

#### Alt-4: Alt-2の1で、アクターが削除済みユーザーを含めることを指定した場合

1. システムはアクターに削除済みユーザーの勤怠修正申請を含めた一覧を提示する
2. メインフロー3に戻る

#### Alt-5: メインフロー5で、修正後の打刻の一覧が対象日のシフトと矛盾していた場合

1. システムは矛盾の内容をアクターに提示する
2. メインフロー6に進む

#### Alt-6: Alt-2の3で、条件に合う勤怠修正申請が存在しなかった場合

1. システムは条件に合う勤怠修正申請が存在しないことをアクターに提示する
2. Alt-2の1に戻る

### 例外フロー

なし

## 備考

1. 対象日のシフトと修正後の内容の矛盾の判定は残す(#90)。対象日にシフトが無いのに修正後の打刻の一覧に勤務がある場合を「矛盾」として提示する(Alt-5)。対象日にシフトがある場合は、シフトの開始時刻・終了時刻と修正後の打刻日時との差を分で提示する(メインフロー6)。矛盾の有無によらず、メインフロー6の後に承認・却下に進める。いずれの場合も承認できる(A-52)。判定の対象は公開済みのシフトだけであり、下書きのシフトは見ない(#87の再起票からの導出、暫定)
2. 一覧には通常、削除済みユーザーの勤怠修正申請を含めない。削除済みユーザーの「未処理」の勤怠修正申請はAlt-4で提示し、承認・却下できる(#86、A-19)
3. 管理先が複数ある場合はすべての管理先の従業員の分を提示する。Alt-2の条件で管理先を絞れる(#84からの導出、暫定)
4. Alt-2の期間は対象日で絞る(暫定)
5. 従業員が勤怠修正申請を送信できる期限は勤怠修正申請を送信する(UC-306)で扱う(#85)。期限を過ぎた後に残っている「未処理」の勤怠修正申請も承認・却下できる(#85からの導出、暫定)
6. 打刻日時は秒まで記録し、秒まで提示する(#74、A-59)
7. 従業員が勤怠修正申請を送信すると、その従業員の所属を管理先に持つ勤怠管理者に通知される(#96)。取り下げは通知されない(2026-10-22の会話)。一覧はこのユースケースで提示する
8. 勤怠修正申請は従業員が勤怠修正申請を送信する(UC-306)で送信する。従業員が勤怠修正申請を取り下げる(UC-314)で取り下げた勤怠修正申請は処理状態「取り下げ」であり、Alt-2で処理状態を指定したときに提示する
