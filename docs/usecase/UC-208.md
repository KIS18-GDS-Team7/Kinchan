# UC-208 シフト希望を却下する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を却下する(UC-208) |
| 目的 | アクターがシフト希望を却下し、却下結果と却下理由が従業員に通知された状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト希望を一覧表示する(UC-206)で「未処理」のシフト希望を指定して却下を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること<br>・対象のシフト希望の処理状態が「未処理」であること |
| 事後条件 | ・対象のシフト希望の処理状態が「却下」になっていること<br>・却下理由が記録されていること<br>・シフトが登録されていないこと<br>・(希望を送信した従業員が削除済みユーザーでなければ)希望を送信した従業員に却下結果と却下理由が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフト希望を一覧表示する(UC-206)<br>・シフト希望を承認する(UC-207)<br>・シフト希望を送信する(UC-307)<br>・シフト希望を一覧表示する(UC-311)<br>・シフト希望を取り下げる(UC-315) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の却下を要求する
2. システムはアクターに却下するシフト希望の内容を提示し、却下理由の入力を求める
3. アクターはシステムに却下理由を入力する
4. システムはアクターに却下の確認を求める
5. アクターはシステムに却下を指示する
6. システムは却下理由が入力されていること、対象のシフト希望の処理状態が「未処理」であることを検証する
7. システムはシフト希望の処理状態を「却下」に更新する
8. システムは却下理由を記録する
9. システムは、希望を送信した従業員が削除済みユーザーでなければ、希望を送信した従業員に却下結果と却下理由を通知する
10. システムはアクターに却下が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー6で、却下理由が入力されていなかった場合

1. システムは却下理由の入力が必要であることをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: メインフロー6で、対象のシフト希望の処理状態が「未処理」でなくなっていた場合

1. システムは対象のシフト希望が却下できない状態であることをアクターに提示する
2. シフト希望を一覧表示する(UC-206)に戻る

#### Alt-3: メインフロー2で、対象のシフト希望がアクター自身のシフト希望だった場合

1. システムは対象がアクター自身のシフト希望であることをアクターに提示する
2. メインフロー3に進む

### 例外フロー

#### Ex-1: メインフロー5より前にアクターが却下のキャンセルを要求した場合

1. アクターはシステムに却下のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト希望の処理状態が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー4に戻る

事後条件

- シフト希望の処理状態が変更されていないこと
- 却下理由が記録されていないこと

## 備考

1. 事後条件の4項目は#87の3つ目のコメントのとおり。シフト希望の処理状態は「下書き」「未処理」「承認済」「却下」「取り下げ」の5値(#87、2026-10-21の会話)
2. 却下理由は必須の自由記述。定型文から選んで挿入できる(A-46)
3. Alt-2は、シフト希望を一覧表示する(UC-206)で一覧を提示した後に、他の勤怠管理者が承認・却下した、または従業員が取り下げた場合に当たる。取り下げは従業員がシフト希望を取り下げる(UC-315)で行う。承認・却下するのは、承認(却下)を指示した時点のシフト希望の内容である。一覧を提示した後に従業員が内容を変更していても、処理状態が「未処理」のままであれば止めない(暫定)
4. 削除済みユーザーのシフト希望は削除せずに残す(#86、A-19)。削除済みユーザーの「未処理」のシフト希望は却下だけできる。承認はできない(2026-10-22の会話)。削除済みユーザーには通知しない(#86、A-19からの導出、暫定)
5. アクターの所属がアクターの管理先に含まれる場合、アクター自身のシフト希望を却下できる(A-55)
6. 却下理由の文字数の上限はTBD(要起票)
7. 却下結果と却下理由は、シフト希望を一覧表示する(UC-311)で従業員に提示される。承認はシフト希望を承認する(UC-207)で行う
