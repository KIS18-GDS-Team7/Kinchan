# UC-209 勤怠修正申請を却下する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を却下する(UC-209) |
| 目的 | アクターが「未処理」の勤怠修正申請を却下理由とともに却下し、却下結果と却下理由が申請した従業員に通知された状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターが勤怠修正申請を一覧表示する(UC-207)で「未処理」の勤怠修正申請を指定して却下を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109)<br>・対象の従業員が管理先の従業員であること<br>・対象の勤怠修正申請の処理状態が「未処理」であること |
| 事後条件 | ・勤怠修正申請の処理状態が「却下」になっていること<br>・却下理由が記録されていること<br>・勤怠記録が修正されていないこと<br>・(申請した従業員が削除済みユーザーでなければ)申請した従業員に却下結果と却下理由が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・勤怠修正申請を一覧表示する(UC-207)<br>・勤怠修正申請内容を一覧表示する(UC-310) |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の却下を要求する
2. システムはアクターに却下する勤怠修正申請の内容を提示し、却下理由の入力を求める
3. アクターはシステムに却下理由を入力する
4. システムはアクターに却下の確認を求める
5. アクターはシステムに却下を指示する
6. システムは却下理由が入力されていること、対象の勤怠修正申請の処理状態が「未処理」であることを検証する
7. システムは勤怠修正申請の処理状態を「却下」に更新する
8. システムは却下理由を記録する
9. システムは、申請した従業員が削除済みユーザーでなければ、申請した従業員に却下結果と却下理由を通知する
10. システムはアクターに却下が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー6で、却下理由が入力されていなかった場合

1. システムは却下理由の入力が必要であることをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: メインフロー6で、対象の勤怠修正申請の処理状態が「未処理」でなくなっていた場合

1. システムは対象の勤怠修正申請が却下できない状態であることをアクターに提示する
2. 勤怠修正申請を一覧表示する(UC-207)に戻る

#### Alt-3: メインフロー2で、対象の勤怠修正申請がアクター自身の勤怠修正申請だった場合

1. システムは対象がアクター自身の勤怠修正申請であることをアクターに提示する
2. メインフロー3に進む

### 例外フロー

#### Ex-1: メインフロー5より前にアクターが却下のキャンセルを要求した場合

1. アクターはシステムに却下のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 勤怠修正申請の処理状態が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムが勤怠修正申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー4に戻る

事後条件

- 勤怠修正申請の処理状態が変更されていないこと
- 却下理由が記録されていないこと

## 備考

1. 却下理由は必須の自由記述とする。定型文から選んで挿入できる(A-46)
2. 承認時に申請内容を調整することはできないため、申請内容の調整が必要な場合は、却下するか、勤怠を修正する(UC-210)で直接修正する(#91、A-53)
3. 修正申請の期限(#85)を過ぎた後に残っている「未処理」の勤怠修正申請も却下できる(#85からの導出、暫定)
4. 削除済みユーザーの「未処理」の勤怠修正申請も却下できる(#86、A-19)。削除済みユーザーには通知しない(#86、A-19からの導出、暫定)
5. アクターの所属がアクターの管理先に含まれる場合、アクター自身の勤怠修正申請を却下できる(Alt-3、A-55)
6. 却下理由の文字数の上限はTBD(要起票)
7. 却下結果と却下理由は従業員側の勤怠修正申請内容を一覧表示する(UC-310)で提示される。Alt-2は、一覧を提示した後に、他の勤怠管理者が承認・却下した、または従業員が取り下げた場合に当たる。取り下げは従業員が勤怠修正申請を取り下げる(UC-314)で行う。承認・却下するのは、承認(却下)を指示した時点の申請の内容である。一覧を提示した後に従業員が内容を変更していても、処理状態が「未処理」のままであれば止めない(暫定)
