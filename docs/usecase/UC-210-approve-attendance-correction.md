# UC-210 勤怠修正申請を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を承認する(UC-210) |
| 目的（ゴール） | 勤怠修正申請を承認し、申請内容を勤怠記録に反映する |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者が勤怠修正申請の承認要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの担当する店舗の従業員から送信された未処理の勤怠修正申請が存在すること |
| 事後条件 | ・勤怠修正申請の処理状態が「承認済」になっていること<br>・申請内容が勤怠記録に反映されていること<br>・修正前の勤怠記録が修正履歴として記録されていること<br>・従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | 勤怠修正申請を表示する(UC-209) |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の承認を要求する
2. システムはアクターに承認する勤怠修正申請の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは修正後の内容が有効なものか確認する(出勤時刻が退勤時刻より前であることなど)
5. システムは勤怠修正申請の処理状態を「承認済」に更新する
6. システムは修正前の勤怠記録を修正履歴として記録する
7. システムは申請内容を勤怠記録に反映する
8. システムは従業員に承認結果を通知する
9. システムはアクターに承認が完了したことを提示する

### 代替フロー

**Alt-1：修正後の内容が無効だった場合**

1. システムは修正後の内容が無効である理由をアクターに提示する
2. 勤怠修正申請を表示する(UC-209)に戻る

**Alt-2：対象の勤怠修正申請がすでに処理済み、または従業員によって取り下げられていた場合**

1. システムは対象の勤怠修正申請が承認できない状態であることをアクターに提示する
2. 勤怠修正申請を表示する(UC-209)に戻る

### 例外フロー

**Ex-1：メインフロー3より前にアクターが承認のキャンセルを要求した場合**

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- 勤怠修正申請の処理状態が変わっていないこと
- システムが待機状態に戻っていること

## 備考

1. 給与計算の締め処理が終わった月の勤怠を修正する場合の扱いはTBD
2. 修正履歴は削除できないものとする(不正防止のため)
3. 従業員への通知方法(アプリ内通知、メールなど)はTBD
4. 勤怠の時刻は1分単位で記録し、15分単位などの丸めは行わない(労働基準法に基づく)
5. 承認結果は従業員側の「勤怠修正申請内容を確認する(UC-310)」で表示される
