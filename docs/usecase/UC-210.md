# UC-210 勤怠修正申請を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を承認する(UC-210) |
| 目的 | アクターが「未処理」の勤怠修正申請を承認し、申請内容を勤怠記録に反映できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターが勤怠修正申請を一覧表示する(UC-209)で指定した勤怠修正申請の承認を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること<br>・対象の勤怠修正申請の処理状態が「未処理」であること |
| 事後条件 | ・勤怠修正申請の処理状態が「承認済」になっていること<br>・修正前の勤怠記録が修正履歴として記録されていること<br>・申請内容が勤怠記録に反映されていること<br>・申請した従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・勤怠修正申請を一覧表示する(UC-209)<br>・勤怠を修正する(UC-212)<br>・勤怠修正申請内容を一覧表示する(UC-310) |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の承認を要求する
2. システムはアクターに承認する勤怠修正申請の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは修正後の打刻の一覧の整合を検証する
5. システムは勤怠修正申請の処理状態を「承認済」に更新する
6. システムは修正前の勤怠記録を修正履歴として記録する
7. システムは申請内容を対象日の勤怠記録に反映する
8. システムは申請した従業員に承認結果を通知する
9. システムはアクターに承認が完了したことを提示する

### 代替フロー

#### Alt-1: 修正後の打刻の一覧が整合していなかった場合

1. システムは修正後の打刻の一覧が整合していないため承認できないことをアクターに提示する
2. 勤怠修正申請を一覧表示する(UC-209)に戻る

#### Alt-2: 対象の勤怠修正申請の処理状態が「未処理」でなくなっていた場合

1. システムは対象の勤怠修正申請が承認できない状態であることをアクターに提示する
2. 勤怠修正申請を一覧表示する(UC-209)に戻る

#### Alt-3: メインフロー2で、対象の勤怠修正申請がアクター自身の勤怠修正申請だった場合

1. システムは対象がアクター自身の勤怠修正申請であることをアクターに提示する
2. メインフロー3に進む

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが承認のキャンセルを要求した場合

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- 勤怠修正申請の処理状態が変更されていないこと
- 勤怠記録が修正されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムが勤怠修正申請または勤怠記録の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー2に戻る

事後条件

- 勤怠修正申請の処理状態が変更されていないこと
- 勤怠記録が修正されていないこと

## 備考

1. 承認時にアクターが申請内容を調整するステップは設けない(#91、A-53)。申請内容の調整が必要な場合は、勤怠修正申請を却下する(UC-211)か、勤怠を修正する(UC-212)で直接修正する
2. 修正後の打刻の一覧が整合しているとは、打刻の種類が「出勤」、「休憩開始」と「休憩終了」の組(0回以上)、「退勤」の順に並び、打刻日時が昇順であることをいう。同じ日に2回以上の勤務があってよい(#78)
3. 修正履歴には修正前の勤怠記録・修正者・修正日時・修正理由・根拠(「勤怠修正申請に基づく」)を記録する。修正理由には申請理由を記録する(暫定)。修正履歴は削除できない(ドラフトUC-212、A-54)
4. 対象日に勤怠記録が無い場合は、メインフロー7で勤怠記録を新しく登録して申請内容を反映する(暫定)
5. 対象日の勤怠記録を勤怠を修正する(UC-212)ですでに修正していた場合も、承認すると申請内容で上書きされる(#93、A-84)
6. 修正申請の期限(#85)を過ぎた後に残っている「未処理」の勤怠修正申請も承認できる(#85からの導出、暫定)
7. 削除済みユーザーの「未処理」の勤怠修正申請も承認できる(#86、A-19)
8. アクターの所属がアクターの管理先に含まれる場合、アクター自身の勤怠修正申請を承認できる(Alt-3、A-55)
9. 打刻日時は秒まで記録し、秒まで提示する(#74、A-59)
10. 対象日が当日で、対象の従業員の勤務ステータスが「退勤中」でない場合の扱いはTBD(要起票)
11. 承認結果は従業員側の勤怠修正申請内容を一覧表示する(UC-310)で提示される。Alt-2は、一覧を提示した後に他のアクターが処理した、または従業員が勤怠修正申請を取り下げる(UC-314)で取り下げた場合に当たる
