# UC-215 シフト日時変更申請を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を承認する(UC-215) |
| 目的（ゴール） | シフト日時変更申請を承認し、登録済みのシフトに変更内容を反映する |
| アクター | 勤怠管理者 |
| 開始条件（起動トリガー） | 勤怠管理者がシフト日時変更申請の承認要求を出す |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの担当する店舗の従業員から送信された未処理のシフト日時変更申請が存在すること |
| 事後条件 | ・シフト日時変更申請の処理状態が「承認済」になっていること<br>・登録済みのシフトが変更後の日時に更新されていること<br>・変更前のシフトが変更履歴として記録されていること<br>・従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | シフト日時変更申請を表示する(UC-214) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の承認を要求する
2. システムはアクターに承認するシフト日時変更申請の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは変更後の日時が同じ従業員の他のシフトと重複していないか、従業員の勤務可能時間の範囲内か確認する
5. システムはシフト日時変更申請の処理状態を「承認済」に更新する
6. システムは変更前のシフトを変更履歴として記録する
7. システムは登録済みのシフトを変更後の日時に更新する
8. システムは従業員に承認結果を通知する
9. システムはアクターに承認が完了したことを提示する

### 代替フロー

**Alt-1：変更後の日時が同じ従業員の他のシフトと重複していた場合**

1. システムは重複しているシフトをアクターに提示する
2. シフト日時変更申請を表示する(UC-214)に戻る

**Alt-2：変更前のシフトがすでに勤務済み、または削除されていた場合**

1. システムは変更前のシフトが変更できない状態であることをアクターに提示する
2. シフト日時変更申請を表示する(UC-214)に戻る

**Alt-3：対象のシフト日時変更申請がすでに処理済み、または従業員によって取り下げられていた場合**

1. システムは対象のシフト日時変更申請が承認できない状態であることをアクターに提示する
2. シフト日時変更申請を表示する(UC-214)に戻る

**Alt-4：希望の日時が従業員の勤務可能時間の範囲外だった場合**

1. システムは範囲外であることと、従業員の勤務可能時間をアクターに提示する
2. シフト日時変更申請を表示する(UC-214)に戻る

### 例外フロー

**Ex-1：メインフロー3より前にアクターが承認のキャンセルを要求した場合**

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト日時変更申請の処理状態が変わっていないこと
- システムが待機状態に戻っていること
