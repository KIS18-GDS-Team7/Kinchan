# UC-215 シフト日時変更申請を承認する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を承認する(UC-215) |
| 目的 | アクターが未処理のシフト日時変更申請を承認し、変更後の日時をシフトに反映できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト日時変更申請を一覧表示する(UC-214)で指定したシフト日時変更申請の承認を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること<br>・対象のシフト日時変更申請の処理状態が「未処理」であること |
| 事後条件 | ・シフト日時変更申請の処理状態が「承認済」になっていること<br>・変更前のシフトの内容、操作者、操作日時が変更履歴として記録されていること<br>・シフトが変更後の勤務日・開始時刻・終了時刻に更新されていること<br>・申請した従業員に承認結果が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | シフト日時変更申請を一覧表示する(UC-214)<br>シフトを変更する(UC-204)<br>シフトを一覧表示する(UC-308) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の承認を要求する
2. システムはアクターに承認するシフト日時変更申請の内容を提示し、承認の確認を求める
3. アクターはシステムに承認を指示する
4. システムは変更前のシフトが勤務済み・削除済みでないことを検証する
5. システムは変更後の日時が同じ従業員の他のシフトと重複しないことを判定する
6. システムはシフト日時変更申請の処理状態を「承認済」に更新する
7. システムは変更前のシフトの内容、操作者、操作日時を変更履歴として記録する
8. システムはシフトを変更後の勤務日・開始時刻・終了時刻に更新する
9. システムは申請した従業員に承認結果を通知する
10. システムはアクターに承認が完了したことを提示する

### 代替フロー

#### Alt-1: 変更後の日時が同じ従業員の他のシフトと重複していた場合

1. システムは変更後の日時が同じ従業員の他のシフトと重複するため承認できないことをアクターに提示する
2. シフト日時変更申請を一覧表示する(UC-214)に戻る

#### Alt-2: 変更前のシフトが勤務済み、または削除済みだった場合

1. システムは変更前のシフトが変更できない状態であるため承認できないことをアクターに提示する
2. シフト日時変更申請を一覧表示する(UC-214)に戻る

#### Alt-3: 対象のシフト日時変更申請がすでに処理済みだった場合

1. システムは対象のシフト日時変更申請が承認できない状態であることをアクターに提示する
2. シフト日時変更申請を一覧表示する(UC-214)に戻る

#### Alt-4: 対象がアクター自身のシフト日時変更申請だった場合

1. システムは対象がアクター自身のシフト日時変更申請であることをアクターに提示する
2. メインフロー3に進む

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが承認のキャンセルを要求した場合

1. アクターはシステムに承認のキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト日時変更申請の処理状態が変更されていないこと
- シフトが変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト日時変更申請またはシフトの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー2に戻る

事後条件

- シフト日時変更申請の処理状態が変更されていないこと
- シフトが変更されていないこと

## 備考

1. 承認時にアクターが変更後の日時を調整するステップは設けない(#91の扱いを準用、暫定)。調整が必要な場合は、却下する(UC-216)か、シフトを変更する(UC-204)で変更する
2. 変更後のシフトの状態は「公開」のまま変えない(#87)。変更履歴は削除できない
3. 承認結果の通知はシフトが変更されたことの通知を兼ねる。シフトを変更する(UC-204)の通知は別に出さない
4. 重複は時刻の重なりで判定する(A-33)。重複がある場合は承認せず、申請は未処理のまま残る
5. 勤務済みのシフトとは、シフトの終了日時(勤務日+終了時刻。日をまたぐ場合は翌日)を現在時刻が過ぎていることをいう(暫定)。変更前のシフトが勤務中であっても承認できる(シフトを変更する(UC-204)と同じ扱い、暫定)
6. シフト日時変更申請の対象は、従業員自身の公開済みで勤務日が翌日以降のシフトである(UC-309、A-36)
7. 削除済みユーザーの未処理のシフト日時変更申請も処理できる(#86、A-19)。ユーザーの削除時に勤務日が翌日以降のシフトは削除されるため、変更前のシフトが削除済みであればAlt-2となる
8. アクターの所属がアクターの管理先に含まれる場合、アクター自身のシフト日時変更申請を承認できる(Alt-4、A-55)
9. 変更後のシフトは従業員側のシフトを一覧表示する(UC-308)で提示される。従業員が取り下げたシフト日時変更申請(UC-316)は処理済みとして扱う(Alt-3)
