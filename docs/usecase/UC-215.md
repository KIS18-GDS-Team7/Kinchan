# UC-215 シフト希望の対象期間・受付期間を登録する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望の対象期間・受付期間を登録する(UC-215) |
| 目的 | アクターが管理先ごとにシフト希望の対象期間と受付期間を登録し、管理先の従業員が受付期間中にシフト希望を送信できる状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト希望の対象期間・受付期間の登録を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-109) |
| 事後条件 | ・指定した管理先に対象期間と受付期間が登録されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフト希望を送信する(UC-307)<br>・シフト希望を一覧表示する(UC-204)<br>・シフトを公開する(UC-216)<br>・シフトを登録する(UC-201)<br>・シフトを変更する(UC-202)<br>・シフト希望を承認する(UC-205)<br>・シフト日時変更申請を承認する(UC-213)<br>・シフト日時変更申請を送信する(UC-309)<br>・ユーザーの所属を編集する(UC-106)<br>・シフトを一覧表示する(UC-308) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の対象期間・受付期間の登録を要求する
2. システムはアクターに管理先の指定を求める
3. アクターはシステムに管理先を指定する
4. システムはアクターに対象期間(開始日、終了日)と受付期間(開始日時、終了日時)の入力を求める
5. アクターはシステムに対象期間と受付期間を入力する
6. システムは入力された対象期間と受付期間を検証する
7. システムは入力された対象期間が同じ管理先の登録済みの対象期間と重なるかを判定する
8. システムはアクターに入力された対象期間と受付期間を提示し、登録の確認を求める
9. アクターはシステムに登録を指示する
10. システムは対象期間と受付期間を登録する
11. システムはアクターに登録が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー6で、入力された対象期間または受付期間に誤りがあった場合

1. システムは入力された対象期間または受付期間に誤りがあることをアクターに提示する
2. メインフロー4に戻る

#### Alt-2: メインフロー7で、入力された対象期間が同じ管理先の登録済みの対象期間と重なっていた場合

1. システムは重なっている対象期間をアクターに提示する
2. メインフロー4に戻る

### 例外フロー

#### Ex-1: メインフロー9より前にアクターが登録のキャンセルを要求した場合

1. アクターはシステムに登録のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 対象期間と受付期間が登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムが対象期間と受付期間の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー8に戻る

事後条件

- 対象期間と受付期間が登録されていないこと

## 備考

1. #88の結論により新設。シフト希望の対象期間と受付期間は勤怠管理者が登録する。対象期間はシフト希望が対象とする勤務日の範囲(開始日・終了日)、受付期間はその対象期間のシフト希望を送信できる期間(開始日時・終了日時)で、対で登録する
2. 対象期間・受付期間は管理先(所属単位)ごとに登録する(#84・#88からの導出、暫定)。管理先が複数ある場合は管理先ごとに登録する
3. Alt-1の誤りとは、未入力、対象期間の開始日が終了日より後または同じであること、受付期間の開始日時が終了日時より後または同じであることを指す(暫定)
4. 同じ管理先の登録済みの対象期間と重なる対象期間は登録できない(暫定)
5. シフトを登録する(UC-201)・シフトを変更する(UC-202)・シフト希望を承認する(UC-205)・シフト日時変更申請を承認する(UC-213)で登録・変更するシフトの勤務日と、シフト日時変更申請を送信する(UC-309)で送信する変更後の勤務日は、対象の従業員の所属に登録された対象期間に含まれる日に限る(2026-10-22の会話)。シフトは、登録・変更の時点で勤務日が所属の対象期間に含まれる
6. 受付期間と対象期間の前後関係の制約(受付期間の終了日時が対象期間の開始日より前でなければならないか)はTBD(要起票)
7. 対象期間・受付期間の変更・削除はTBD(要起票)。ユーザーの所属を編集する(UC-106)で所属を変更した後、および対象期間を変更・削除した後の、既存のシフトと「未処理」のシフト希望・シフト日時変更申請(変更前の対象期間に含まれる日を対象とするもの)の扱いはTBD(要起票)。対象になる操作は、シフトを公開する(UC-216)での下書きの公開、シフトを一覧表示する(UC-308)での提示、シフト希望を承認する(UC-205)・シフト日時変更申請を承認する(UC-213)での承認。対象期間の変更・削除はこのユースケースでTBD
8. 登録したことを管理先の従業員に通知するかはTBD(要起票)
9. 新設のユースケースであり、IDは仮。requirements.mdのUC一覧にも追記済み
10. 従業員は受付期間中にシフト希望を送信する(UC-307)でシフト希望を送信する。対象期間はシフトを公開する(UC-216)で公開する単位でもある(暫定)
