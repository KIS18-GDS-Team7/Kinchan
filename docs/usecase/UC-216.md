# UC-216 シフト日時変更申請を却下する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を却下する(UC-216) |
| 目的 | アクターが「未処理」のシフト日時変更申請を却下理由とともに却下し、却下結果と却下理由が申請した従業員に通知された状態にする |
| アクター | 勤怠管理者 |
| 開始条件 | アクターがシフト日時変更申請を一覧表示する(UC-214)で指定したシフト日時変更申請の却下を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターが勤怠管理者権限を持つこと<br>・アクターに管理先が割り当てられていること(UC-118)<br>・対象の従業員が管理先の従業員であること<br>・対象のシフト日時変更申請の処理状態が「未処理」であること |
| 事後条件 | ・シフト日時変更申請の処理状態が「却下」になっていること<br>・却下理由が記録されていること<br>・シフトが変更されていないこと<br>・申請した従業員に却下結果と却下理由が通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフト日時変更申請を一覧表示する(UC-214)<br>・シフト日時変更申請内容を一覧表示する(UC-318) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の却下を要求する
2. システムはアクターに却下するシフト日時変更申請の内容を提示し、却下理由の入力を求める
3. アクターはシステムに却下理由を入力する
4. システムはアクターに却下の確認を求める
5. アクターはシステムに却下を指示する
6. システムはシフト日時変更申請の処理状態を「却下」に更新する
7. システムは却下理由を記録する
8. システムは申請した従業員に却下結果と却下理由を通知する
9. システムはアクターに却下が完了したことを提示する

### 代替フロー

#### Alt-1: 却下理由が入力されていなかった場合

1. システムは却下理由の入力が必要であることをアクターに提示する
2. メインフロー2に戻る

#### Alt-2: 対象のシフト日時変更申請の処理状態が「未処理」でなくなっていた場合

1. システムは対象のシフト日時変更申請が却下できない状態であることをアクターに提示する
2. シフト日時変更申請を一覧表示する(UC-214)に戻る

#### Alt-3: メインフロー2で、対象のシフト日時変更申請がアクター自身のシフト日時変更申請だった場合

1. システムは対象がアクター自身のシフト日時変更申請であることをアクターに提示する
2. メインフロー3に進む

### 例外フロー

#### Ex-1: メインフロー5より前にアクターが却下のキャンセルを要求した場合

1. アクターはシステムに却下のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト日時変更申請の処理状態が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト日時変更申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー4に戻る

事後条件

- シフト日時変更申請の処理状態が変更されていないこと

## 備考

1. 却下理由は必須の自由記述とする。定型文から選んで挿入できる(A-46)
2. 削除済みユーザーの「未処理」のシフト日時変更申請も却下できる(#86、A-19)
3. アクターの所属がアクターの管理先に含まれる場合、アクター自身のシフト日時変更申請を却下できる(Alt-3、A-55)
4. 却下理由の文字数の上限はTBD(要起票)
5. 却下結果と却下理由は、従業員側ではシフト日時変更申請内容を一覧表示する(UC-318)と通知を表示する(UC-317)で提示される(2026-10-22の会話)。シフトを一覧表示する(UC-308)では変更前のシフトがそのまま提示される
6. Alt-2は、一覧を提示した後に他のアクターが処理した、または従業員がシフト日時変更申請を取り下げる(UC-316)で取り下げた場合に当たる
