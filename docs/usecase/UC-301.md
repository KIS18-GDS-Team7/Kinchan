# UC-301 ログインする

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ログインする(UC-301) |
| 目的 | アクターがユーザーIDとパスワードでシステムにログインし、権限に基づく操作を始められる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがログインを要求する |
| 事前条件 | ・アクターがログインしていないこと |
| 事後条件 | ・アクターがログインしていること<br>・アクターがホーム(UC-303)に進んでいること |
| 拡張点 | なし |
| 関連ユースケース | ・ユーザーを登録する(UC-101)<br>・ホームを表示する(UC-303)<br>・ログアウトする(UC-302) |

## イベントフロー

### メインフロー

1. アクターはシステムにログインを要求する
2. システムはアクターにユーザーIDとパスワードの入力を求める
3. アクターはシステムにユーザーIDとパスワードを入力する
4. アクターはシステムにログインを指示する
5. システムは入力されたユーザーIDとパスワードを検証する
6. システムはアクターをログインした状態にする
7. ホーム(UC-303)に進む

### 代替フロー

#### Alt-1: メインフロー5で、入力されたユーザーIDまたはパスワードが誤っていた場合

1. システムはログインできないことをアクターに提示する
2. メインフロー2に戻る

### 例外フロー

なし

## 備考

1. docxのログイン(管理者版)の流れを従業員に適用した(B-17、A-11)。全ユーザーが従業員として振る舞うため(#83)、権限の有無を問わずログインの流れは同じで、アクターは従業員とする(2026-10-22の会話)
2. 入力されたユーザーIDが登録されていない場合と、削除済みユーザーのユーザーIDだった場合もAlt-1と同じ扱いとする(docxのログイン(管理者版)のEx-1・Ex-2を統合。暫定)。削除済みユーザーはログインできない(#86、A-19)
3. ログインの試行回数の制限は設けない(A-14)
4. ログイン後は権限を問わずホーム(UC-303)に進む。権限によってログイン後に進む先を分けない(#83からの導出、暫定)
5. docxのログイン(管理者版)のAlt-1「ログイン情報を変更する」は対応するユースケースが無いため書かない。ユーザー本人によるパスワードの変更はTBD(要起票)。ユーザー情報の変更はシステム管理者がユーザーを編集する(UC-102)で行う
