# UC-303 ホームを表示する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | ホームを表示する(UC-303) |
| 目的 | 従業員がログイン後に、自分の現在の勤務ステータス・当日のシフト・当日の打刻・未処理の申請と希望の件数・通知の件数を一度に提示され、打刻・シフト希望の送信・通知の表示を始められる状態にする |
| アクター | 従業員 |
| 開始条件 | 従業員がホームの表示を要求する、またはログインする(UC-001)が完了する |
| 事前条件 | ・アクターがログインしていること(UC-001) |
| 事後条件 | ・アクターにホームが提示されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ログインする(UC-001)<br>・打刻をする(UC-304)<br>・休憩を打刻する(UC-312)<br>・シフト希望を送信する(UC-307)<br>・通知を表示する(UC-317) |

## イベントフロー

### メインフロー

1. アクターはシステムにホームの表示を要求する
2. システムはアクターにホーム(アクターの現在の勤務ステータス、当日を勤務日とするアクターの公開済みのシフト、当日の打刻(種類、打刻日時)、アクターの未処理の勤怠修正申請・シフト希望・シフト日時変更申請の件数、アクター宛ての通知の件数)を提示する

### 代替フロー

#### Alt-1: アクターの所属単位に受付期間中の対象期間があった場合

1. システムはメインフロー2の内容に加えて、その対象期間のシフト希望を送信できることをアクターに提示する
2. このユースケースを終了する

### 例外フロー

なし

## 備考

3. 当日のシフトは公開済みのシフトだけを提示し、下書きのシフトは提示しない(#87)。勤務ステータスは勤務ステータスを変更する(UC-305)で変わる
4. UC名と提示する内容はTBD(#61)
5. 通知の件数に、表示した通知を含めるか(既読の扱い)はTBD(要起票)
6. requirements.md では「マイページを表示する」。改名は別途(ADR-0003)
7. このユースケースは、打刻をする(UC-304)・休憩を打刻する(UC-312)・シフト希望を送信する(UC-307。受付期間中の対象期間がある場合)・通知を表示する(UC-317)の起点である
