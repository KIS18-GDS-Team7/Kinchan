# UC-304 打刻をする

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 打刻をする(UC-304) |
| 目的 | アクターが出勤・退勤の打刻を行い、勤務の区切りを勤怠記録に残せる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターが打刻の種類(「出勤」または「退勤」)を指定して打刻を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターの所属が設定されていること(UC-105) |
| 事後条件 | ・打刻(種類、打刻日時)が記録されていること<br>・アクターの勤務ステータスが打刻の種類に対応する値に変更されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ホームを表示する(UC-303)<br>・勤務ステータスを変更する(UC-305)<br>・勤怠修正申請を送信する(UC-306)<br>・休憩を打刻する(UC-312)<br>・勤怠記録を一覧表示する(UC-313) |

## イベントフロー

### メインフロー

1. アクターはシステムに打刻の種類(「出勤」または「退勤」)を指定して打刻を要求する
2. システムは指定された打刻の種類とアクターの現在の勤務ステータスの整合を判定する
3. システムは打刻の種類が「出勤」のとき、当日を勤務日とするアクターの公開済みのシフトの有無を判定する
4. システムは打刻(種類、打刻日時)を記録する
5. システムはアクターの勤務ステータスを変更する(UC-305)
6. システムはアクターに打刻の結果(打刻の種類、打刻日時、変更後の勤務ステータス)を提示する

### 代替フロー

#### Alt-1: メインフロー2で、指定された打刻の種類がアクターの現在の勤務ステータスと整合しなかった場合

1. システムは打刻できないことと、その理由をアクターに提示する
2. このユースケースを終了する

#### Alt-2: メインフロー3で、当日を勤務日とするアクターの公開済みのシフトが無かった場合

1. システムは当日を勤務日とする公開済みのシフトが無いため打刻できないことをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: システムが打刻の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムはこのユースケースを中断する

事後条件

- 打刻が記録されていないこと
- 勤務ステータスが変更されていないこと

## 備考

1. 打刻の種類は「出勤」「退勤」「休憩開始」「休憩終了」の4値であり、このユースケースでは「出勤」「退勤」を扱う。「休憩開始」「休憩終了」は休憩を打刻する(UC-312)で扱う(#78、A-67)
2. 打刻の種類と勤務ステータスの整合は、「出勤」は勤務ステータスが「退勤中」のとき、「退勤」は「出勤中」のときに整合するものとする。「休憩中」のときに退勤するには、先に「休憩終了」を打刻する(A-67)
3. 打刻日時は打刻を要求した時点の日時であり、秒まで記録し、秒まで提示する(#74、A-59)
4. 日をまたぐ勤務を認める。勤務は出勤打刻を行った日の勤怠記録に属する(#82)。日付が変わっても勤務ステータスを「退勤中」に戻さない
5. 出勤打刻とシフトの照合は、当日を勤務日とするアクターの公開済みのシフトの有無だけを判定し、時刻は照合しない。退勤打刻はシフトと照合しない(暫定)
6. 打刻場所の制限は扱わない(A-71)
7. 退勤打刻の後、同じ日に再び出勤打刻できる(#78)。勤務の間の空白時間の扱いは休憩を打刻する(UC-312)の備考を参照
8. 日をまたぐシフトについて、勤務日の前日に出勤打刻する場合の扱いはTBD(要起票)
9. 誤った打刻は、勤怠修正申請を送信する(UC-306)で勤怠修正申請を送信し、勤怠管理者の承認を得て修正する
