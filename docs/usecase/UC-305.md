# UC-305 勤務ステータスを変更する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤務ステータスを変更する(UC-305) |
| 目的 | システムが記録された打刻の種類に応じてアクターの勤務ステータスを変更し、アクターの現在の勤務ステータスが打刻と一致している状態にする |
| アクター | 従業員 |
| 開始条件 | 打刻をする(UC-304)または休憩を打刻する(UC-312)で打刻が記録されたこと |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・打刻をする(UC-304)または休憩を打刻する(UC-312)で記録された打刻の種類が渡されていること |
| 事後条件 | ・アクターの勤務ステータスが、記録された打刻の種類に対応する値に更新されていること |
| 拡張点 | なし |
| 関連ユースケース | ・打刻をする(UC-304)<br>・休憩を打刻する(UC-312)<br>・ホームを表示する(UC-303)<br>・勤怠修正申請を送信する(UC-306) |

## イベントフロー

### メインフロー

1. システムは記録された打刻の種類が「出勤」「退勤」「休憩開始」「休憩終了」のいずれであるかを判定する
2. システムはアクターの勤務ステータスを、打刻の種類に対応する値(「出勤」は「出勤中」、「退勤」は「退勤中」、「休憩開始」は「休憩中」、「休憩終了」は「出勤中」)に更新する

### 代替フロー

なし

### 例外フロー

#### Ex-1: 渡された打刻の種類が「出勤」「退勤」「休憩開始」「休憩終了」のいずれでもなかった場合

1. システムは勤務ステータスを変更しない
2. システムはこのユースケースを中断する

事後条件

- 勤務ステータスが変更されていないこと

## 備考

1. 勤務ステータスは「出勤中」「退勤中」「休憩中」の3値とする(A-61)。勤務ステータスは打刻によってのみ変わる
2. 一度も打刻していない従業員、および退勤した後の従業員の勤務ステータスは「退勤中」とする(A-72)
3. 日付が変わっても勤務ステータスを変えない。退勤打刻が無いまま日付が変わった勤務は、日をまたぐ勤務として出勤打刻を行った日の勤怠記録に属する(#82)
4. 従業員が勤務ステータスを直接変更することはできない。過去の勤務ステータスに対応する打刻を修正するには、勤怠修正申請を送信する(UC-306)で勤怠修正申請を送信し、勤怠管理者の承認を得る
5. 勤務ステータスは打刻によってのみ変わるため、勤怠修正申請を承認する(UC-210)・勤怠を修正する(UC-212)による勤怠記録の修正では勤務ステータスを変えない
6. 対象日が当日で、対象の従業員の勤務ステータスが「退勤中」でない場合の扱いはTBD(要起票)
7. アクターはrequirements.mdどおり「従業員」とする。ただしこのユースケースは打刻をする(UC-304)または休憩を打刻する(UC-312)から起動され、従業員が直接起動するユースケースではない
8. 勤務ステータスの保存の失敗は、打刻をする(UC-304)・休憩を打刻する(UC-312)の例外フロー「システムが打刻の保存に失敗した場合」で扱う。このため、このユースケースには保存に失敗した場合の例外フローを書かない
9. 変更後の勤務ステータスは、打刻をする(UC-304)・休憩を打刻する(UC-312)が打刻の結果としてアクターに提示する。ホームを表示する(UC-303)は現在の勤務ステータスを提示する
