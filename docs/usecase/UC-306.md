# UC-306 勤怠修正申請を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を送信する(UC-306) |
| 目的 | アクターがアクター自身の勤怠記録の誤りや打刻漏れについて、修正後の打刻の一覧と申請理由を勤怠管理者に送信し、承認を経て勤怠記録を修正できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターが勤怠記録を一覧表示する(UC-313)で対象日を指定して勤怠修正申請を要求する、または勤怠修正申請内容を一覧表示する(UC-310)で「未処理」の勤怠修正申請の変更を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110) |
| 事後条件 | ・勤怠修正申請(従業員、対象日、修正後の打刻の一覧、申請理由、送信日時)が処理状態「未処理」で登録されていること<br>・対象日の勤怠記録が修正されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・勤怠記録を一覧表示する(UC-313)<br>・勤怠修正申請内容を一覧表示する(UC-310)<br>・勤怠修正申請を取り下げる(UC-314)<br>・勤怠修正申請を一覧表示する(UC-209)<br>・勤怠修正申請を承認する(UC-210)<br>・勤怠修正申請を却下する(UC-211) |

## イベントフロー

### メインフロー

1. アクターはシステムに対象日を指定して勤怠修正申請を要求する
2. システムは対象日が当日以前で、修正申請の期限内であるかを判定する
3. システムは対象日に「未処理」の勤怠修正申請があるかを判定する
4. システムはアクターに対象日の現在の勤怠記録の打刻の一覧(種類、打刻日時)を提示し、修正後の打刻の一覧(種類、打刻日時)と申請理由の入力を求める
5. アクターはシステムに修正後の打刻の一覧と申請理由を入力する
6. システムは入力された修正後の打刻の一覧と申請理由を検証する
7. システムはアクターに勤怠修正申請の内容(対象日、現在の打刻の一覧、修正後の打刻の一覧、申請理由)を提示し、送信の確認を求める
8. アクターはシステムに送信を指示する
9. システムは勤怠修正申請を処理状態「未処理」で登録する
10. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー1で、アクターが勤怠修正申請内容を一覧表示する(UC-310)から「未処理」の勤怠修正申請の変更を要求した場合

1. システムは対象の勤怠修正申請の対象日が修正申請の期限内であるかを判定する
2. システムはアクターに対象の勤怠修正申請の内容(対象日、現在の打刻の一覧、修正後の打刻の一覧、申請理由)を提示し、修正後の打刻の一覧と申請理由の入力を求める
3. アクターはシステムに修正後の打刻の一覧と申請理由を入力する
4. システムは入力された修正後の打刻の一覧と申請理由を検証する
5. システムはアクターに勤怠修正申請の内容(対象日、現在の打刻の一覧、修正後の打刻の一覧、申請理由)を提示し、送信の確認を求める
6. アクターはシステムに送信を指示する
7. システムは対象の勤怠修正申請を入力された内容に更新する(処理状態は「未処理」のまま)
8. メインフロー10に進む

#### Alt-2: メインフロー2で、対象日が当日より後だった、または修正申請の期限を過ぎていた場合

1. システムは対象日の勤怠修正申請を送信できないことをアクターに提示する
2. このユースケースを終了する

#### Alt-3: メインフロー3で、対象日に「未処理」の勤怠修正申請がすでにあった場合

1. システムは対象日に「未処理」の勤怠修正申請がすでにあることをアクターに提示する
2. システムは、勤怠修正申請内容を一覧表示する(UC-310)からその勤怠修正申請を変更できることをアクターに提示する
3. このユースケースを終了する

#### Alt-4: メインフロー6で、入力された修正後の打刻の一覧または申請理由に誤りがあった場合

1. システムは誤りの内容(申請理由が未入力、打刻の一覧が整合しない、など)をアクターに提示する
2. メインフロー4に戻る

#### Alt-5: Alt-1の1で、対象日が修正申請の期限を過ぎていた場合

1. システムは修正申請の期限を過ぎているため対象の勤怠修正申請を変更できないことをアクターに提示する
2. このユースケースを終了する

#### Alt-6: Alt-1の4で、入力された修正後の打刻の一覧または申請理由に誤りがあった場合

1. システムは誤りの内容(申請理由が未入力、打刻の一覧が整合しない、など)をアクターに提示する
2. Alt-1の2に戻る

### 例外フロー

#### Ex-1: メインフロー8より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- 勤怠修正申請が登録・更新されていないこと
- システムが待機状態に戻っていること

#### Ex-2: メインフロー9で、システムが勤怠修正申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー8に戻る

事後条件

- 勤怠修正申請が登録されていないこと

#### Ex-3: Alt-1の7で、システムが勤怠修正申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、Alt-1の6に戻る

事後条件

- 勤怠修正申請が更新されていないこと

## 備考

1. 修正の対象は対象日の勤怠記録の打刻の一覧(種類、打刻日時)であり、休憩も「休憩開始」「休憩終了」の打刻として修正する(#78、#94)。修正後の打刻の一覧の初期値は現在の勤怠記録の打刻の一覧とする
2. 修正後の打刻の一覧の整合は、各勤務の打刻が「出勤」、0回以上の「休憩開始」と「休憩終了」の組、「退勤」の順に並び、打刻日時が昇順であることとする。同じ日に2回以上の勤務がある場合はこの組が繰り返される。勤怠修正申請を承認する(UC-210)の検証と同じ
3. 1日に2回以上の勤務がある日は、その日の打刻の一覧をまるごと修正後の内容として入力する(暫定)
4. 対象日は当日以前とする(A-50)。修正申請の期限は、当月分はいつでも送信でき、前月分は当月N日まで送信でき、前々月以前は送信できない(#85)。期限を過ぎた後は、「未処理」の勤怠修正申請の内容も変更できない(#85からの導出、暫定)。期限を過ぎた後も、勤怠管理者は勤怠を修正する(UC-212)で修正できる(#85)
5. 申請理由は、新規の送信でも変更でも必須とする
6. Nの値はTBD(#85)
7. 勤怠管理者への通知はTBD(#96)
8. 申請理由の文字数の上限はTBD(要起票)
9. 対象日が当日で、対象の従業員の勤務ステータスが「退勤中」でない場合の扱いはTBD(要起票)
10. 処理状態が「未処理」の間は、勤怠修正申請内容を一覧表示する(UC-310)から内容を変更して送信し直せる(Alt-1)。このとき勤怠修正申請は増えず、既存の勤怠修正申請が更新される。Alt-1の中で入力に誤りがあった場合(Alt-6)や保存に失敗した場合(Ex-3)もAlt-1に戻り、メインフロー9には進まない
11. 送信した勤怠修正申請は、勤怠管理者が勤怠修正申請を承認する(UC-210)で承認するまで勤怠記録には反映されない
12. 取り下げは勤怠修正申請を取り下げる(UC-314)で行う。取り下げた後は同じ対象日で再び送信できる(Alt-3は処理状態が「未処理」の勤怠修正申請だけを対象とする)
