# ユースケース名
勤怠修正申請を送信する（UC-306）

## 目的（ゴール）
従業員が打刻のし忘れや誤りに対して、正しい打刻日時や理由を記入して勤怠管理者に修正申請の送信する

## アクター
従業員

## 開始条件（起動トリガー)
従業員が勤怠記録一覧画面から勤怠修正申請ボタンを押下する
または、「UC-310の勤怠修正申請内容を一覧表示する」の画面上で編集ボタンを押下する

## 事前条件
- システムが正常に動作すること
- 従業員がシステムにログインしていること

## 事後条件
- 勤怠修正申請が正しく記入され、勤怠管理者に申請が正しく送信されること
- 送信された勤怠修正申請が「UC-310の勤怠修正申請内容を一覧表示する」で表示されること
- 勤怠管理者側の「UC-209の勤怠修正申請を一覧表示する」に表示されること

## 拡張点
なし

## 関連ユースケース
- マイページを表示する（UC-303）
- 勤怠修正申請を確認する（UC-310）
- 勤怠修正申請を一覧表示する（UC-209）※勤怠管理者
- 勤怠修正申請を承認する（UC-210）※勤怠管理者
- 勤怠修正申請を却下する（UC-211）※勤怠管理者

## イベントフロ｜
### メインフロー
1. アクターは勤怠記録一覧画面で修正したい対象日の「勤怠修正申請ボタン」を押下する
2. システムは該当日の現在の勤怠記録を表示、修正後の打刻日時および、申請理由が入力できるフォームを提示する
3. アクターは修正後の打刻情報（打刻時間など）を入力し、送信ボタンを押下する
4. システムは入力された項目（日時や、理由など必須入力等）に不足がないか確認する
5. システムは申請データを保存し「UC-310の勤怠修正申請内容を一覧表示する」に表示され、ステータスが申請中と表示される
6. システムはアクターに申請の送信が完了した旨のメッセージを表示する

### 代替フロー
Alt-1：「UC-310の勤怠修正申請内容を一覧表示する」から「編集」ボタンが押下された場合（申請内容の編集）
1. システムは対象の申請データ（申請理由など）を読み込み、編集用フォームにセットして表示する
2. アクターは内容を修正し、送信ボタンを押下する
3. システムは入力項目の不備をチェック（メインフロー）する
4. システムは新規作成ではなく、既存の申請データを上書き保存し、ステータスは「申請中」を維持する
5. メインフロー6へ進む

事後条件
- 新しい申請データは増えずに、既存の「申請中」のデータ
  の内容が最新に更新されていること

### 例外フロー
Ex-l：入力項目に未入力、不備がある場合
（申請理由が空欄など）
1. システムが入力内容の不足、不備を検知する
2. システムはアクターに「入力内容に不備があります」とエラーメッセージを表示する
3. システムは申請データを保存、送信せず、元の入力フォーム（入力された情報は保持された状態）に戻る

事後条件
- 申請データは保存されず、入力されたデータを保持したまま入力フォームが再操作可能な状態であること

Ex-2：勤怠修正申請内容を一覧表示する（UC-310）にすでに「申請中」のデータが存在する場合
1. システムは同じ対象日で「申請中」のデータが存在することを検知する
2. システムは「該当日の修正申請はすでに送信されています。内容を修正する場合は『勤怠修正申請内容を一覧表示する（UC-310）」から編集してください」というメッセージを表示する
3. システムは申請を送信せず、勤怠記録一覧画面に戻る

事後条件
- 申請データは送信されず、勤怠記録一覧画面に戻る

## 備考
送信（編集して送信）された申請は、勤怠管理者が「UC-210の勤怠修正精申請を承認する」を行うまで実際の打刻情報には反映されない
勤怠管理者の確認作業を円滑にするために、新規申請、編集して申請のいずれにおいても申請理由の入力は必須項目とする
ステータスが「申請中」である限り、従業員は「UC-310の勤怠修正申請内容を一覧表示する」から編集して上書き送信することができる
送信した内容の削除は「UC-310の勤怠修正内容を一覧表示する」の画面上から行える
