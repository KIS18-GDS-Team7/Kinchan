# UC-307 シフト希望を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を送信する(UC-307) |
| 目的 | 従業員が対象期間の各日の勤務の希望をシフト希望として勤怠管理者に送信し、勤怠管理者がシフトを組むときに参照できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがホームを表示する(UC-303)またはシフト希望を一覧表示する(UC-311)で、受付期間中の対象期間を指定してシフト希望の送信を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・アクターの所属単位に受付期間中の対象期間が登録されていること(UC-217) |
| 事後条件 | ・入力された各日について、1日分ずつのシフト希望が登録されていること<br>・登録されたシフト希望の処理状態が「未処理」になっていること<br>・シフトが登録されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・ホームを表示する(UC-303)<br>・シフト希望を一覧表示する(UC-311)<br>・シフト希望を取り下げる(UC-315)<br>・シフト希望の対象期間・受付期間を登録する(UC-217)<br>・シフト希望を一覧表示する(UC-206)<br>・シフト希望を承認する(UC-207)<br>・シフト希望を却下する(UC-208) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の送信を要求する
2. システムはアクターに対象期間の各日の希望の入力を求める
3. アクターはシステムに希望を出す日の種別(「時間指定」または「休日希望」)を入力する
4. アクターはシステムに種別が「時間指定」の日の希望開始時刻・希望終了時刻を入力する
5. システムは入力されたシフト希望を検証する
6. システムはアクターに入力されたシフト希望の内容を提示し、送信の確認を求める
7. アクターはシステムに送信を指示する
8. システムは入力された各日をそれぞれ1件のシフト希望として処理状態「未処理」で登録する(既存のシフト希望がある日は、そのシフト希望を入力された内容に更新し、処理状態を「未処理」にする)
9. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: 指定した対象期間にアクターのシフト希望がすでにあった場合

1. システムはアクターに対象期間の各日の既存のシフト希望(種別、希望開始時刻・希望終了時刻、処理状態)を提示し、希望の入力を求める
2. システムは処理状態が「承認済」「却下」「取り下げ」の日は変更できないことをアクターに提示する
3. アクターはシステムに処理状態が「下書き」「未処理」の日とシフト希望が無い日について、種別(「時間指定」または「休日希望」)を入力する(「下書き」の日は種別を外すこともできる)
4. アクターはシステムに種別が「時間指定」の日の希望開始時刻・希望終了時刻を入力する
5. メインフロー5に進む

#### Alt-2: 入力されたシフト希望に誤りがあった場合

1. システムは誤りの内容(希望を出す日が1日も無い、「時間指定」の日に希望開始時刻・希望終了時刻の一方または両方が無い、希望終了時刻が希望開始時刻と同じ)をアクターに提示する
2. メインフロー2に戻る

#### Alt-3: アクターが送信ではなく下書きとしての保存を指示した場合

1. アクターはシステムに入力したシフト希望を下書きとして保存することを指示する
2. システムは入力された各日をそれぞれ1件のシフト希望として処理状態「下書き」で保存する(既存の「下書き」のシフト希望がある日は、そのシフト希望を入力された内容に更新する)
3. システムはアクターに下書きとしての保存が完了したことを提示する
4. このユースケースを終了する

#### Alt-4: 対象期間の受付期間を過ぎていた場合

1. システムは受付期間を過ぎているためシフト希望を送信できないことをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー7より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト希望が登録・更新されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー6に戻る

事後条件

- シフト希望が登録・更新されていないこと

## 備考

1. 種別は「時間指定」「休日希望」の2つ。「出勤可能」の希望は無い(#89)
2. 1件のシフト希望は1日分。対象期間の入力された各日をそれぞれ1件のシフト希望として登録し、勤怠管理者は1件ずつ承認・却下する(A-41)
3. 送信したシフト希望の処理状態は「未処理」(#87)。「未処理」のシフト希望は勤怠管理者がシフトを組むときに参照する。シフト希望を承認する(UC-207)で承認されるまでシフトは登録されない
4. 「休日希望」は承認・却下の対象にならず、勤怠管理者に参照情報として提示される(A-41、暫定)
5. 下書きとして保存したシフト希望(処理状態「下書き」)は勤怠管理者に提示されない(#87)
6. 既存のシフト希望の変更はこのユースケースの Alt-1 で行い、別のユースケースにしない(A-43、A-82)。処理状態が「承認済」「却下」「取り下げ」の日は変更できない。「未処理」の日は内容を上書きできるだけで、種別を外すことはできない(無効にするにはシフト希望を取り下げる(UC-315)を使う)
7. 日をまたぐ希望は、希望終了時刻が希望開始時刻より前であることで表す(希望終了時刻は翌日の時刻として扱う)。希望終了時刻が希望開始時刻と同じ入力は誤りとする(#82 を準用、暫定)
8. 勤怠管理者への通知はTBD(#96)
9. Alt-1 で「下書き」の日の種別を外して送信または保存した場合に、その日のシフト希望をどう扱うかはTBD(要起票)
10. Alt-1 で「未処理」の日の内容を変更して下書きとして保存した場合の扱いはTBD(要起票)
11. 対象期間と受付期間は、勤怠管理者がシフト希望の対象期間・受付期間を登録する(UC-217)で登録する(#88)
12. 送信した「未処理」のシフト希望を無効にするには、シフト希望を取り下げる(UC-315)を使う
13. 送信したシフト希望の処理状態と却下理由は、シフト希望を一覧表示する(UC-311)で提示される
