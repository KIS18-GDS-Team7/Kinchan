# UC-307 シフト希望を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を送信する(UC-307) |
| 目的 | アクターが対象期間の各日の勤務の希望をシフト希望として勤怠管理者に送信し、勤怠管理者がシフトを組むときに参照できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがホームを表示する(UC-303)またはシフト希望を一覧表示する(UC-311)で、受付期間中の対象期間を指定してシフト希望の送信を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・アクターの所属単位に受付期間中の対象期間が登録されていること(UC-217) |
| 事後条件 | ・入力された各日について、1日分ずつのシフト希望が登録されていること<br>・登録された種別「時間指定」のシフト希望の処理状態が「未処理」になっていること<br>・登録された種別「休日希望」のシフト希望の処理状態が「送信済」になっていること<br>・シフトが登録されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・ホームを表示する(UC-303)<br>・シフト希望を一覧表示する(UC-311)<br>・シフト希望を取り下げる(UC-315)<br>・シフト希望の対象期間・受付期間を登録する(UC-217)<br>・シフト希望を一覧表示する(UC-206)<br>・シフト希望を承認する(UC-207)<br>・シフト希望を却下する(UC-208) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の送信を要求する
2. システムはアクターに対象期間の各日の希望の入力を求める
3. アクターはシステムに希望を出す日の種別(「時間指定」または「休日希望」)を入力する
4. アクターはシステムに種別が「時間指定」の日の希望開始時刻・希望終了時刻を入力する
5. システムは入力されたシフト希望を検証する
6. システムはアクターに入力されたシフト希望の内容を提示し、送信の確認を求める
7. アクターはシステムに送信を指示する
8. システムは入力された種別が「時間指定」の各日をそれぞれ1件のシフト希望として処理状態「未処理」で登録する
9. システムは入力された種別が「休日希望」の各日をそれぞれ1件のシフト希望として処理状態「送信済」で登録する
10. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー2で、指定した対象期間にアクターのシフト希望がすでにあった場合

1. システムはアクターに対象期間の各日の既存のシフト希望(種別、希望開始時刻・希望終了時刻、処理状態)を提示し、希望の入力を求める
2. システムは処理状態が「承認済」「却下」の日は変更できないことをアクターに提示する
3. アクターはシステムに処理状態が「下書き」「未処理」「送信済」の日、処理状態が「取り下げ」の日、シフト希望が無い日について、種別(「時間指定」または「休日希望」)を入力する
4. アクターはシステムに種別が「時間指定」の日の希望開始時刻・希望終了時刻を入力する
5. システムは入力されたシフト希望を検証する
6. システムはアクターに入力されたシフト希望の内容を提示し、送信の確認を求める
7. アクターはシステムに送信を指示する
8. システムは処理状態が「下書き」「未処理」「送信済」の既存のシフト希望を入力された内容に更新する
9. システムは更新したシフト希望のうち種別が「時間指定」のものの処理状態を「未処理」に更新する
10. システムは更新したシフト希望のうち種別が「休日希望」のものの処理状態を「送信済」に更新する
11. システムは処理状態が「取り下げ」の日とシフト希望が無い日のうち、種別が「時間指定」の各日をそれぞれ1件のシフト希望として処理状態「未処理」で登録する
12. システムは処理状態が「取り下げ」の日とシフト希望が無い日のうち、種別が「休日希望」の各日をそれぞれ1件のシフト希望として処理状態「送信済」で登録する
13. メインフロー10に進む

#### Alt-2: メインフロー5で、入力されたシフト希望に誤りがあった場合

1. システムは誤りの内容(希望を出す日が1日も無い、「時間指定」の日に希望開始時刻・希望終了時刻の一方または両方が無い、希望終了時刻が希望開始時刻と同じ)をアクターに提示する
2. メインフロー3に戻る

#### Alt-3: Alt-1の5で、入力されたシフト希望に誤りがあった場合

1. システムは誤りの内容(希望を出す日が1日も無い、「時間指定」の日に希望開始時刻・希望終了時刻の一方または両方が無い、希望終了時刻が希望開始時刻と同じ)をアクターに提示する
2. Alt-1の3に戻る

#### Alt-4: メインフロー7またはAlt-1の7で、アクターが送信ではなく下書きとしての保存を指示した場合

1. アクターはシステムに入力したシフト希望を下書きとして保存することを指示する
2. システムは処理状態が「下書き」の既存のシフト希望を入力された内容に更新する
3. システムは処理状態が「取り下げ」の日とシフト希望が無い日の入力をそれぞれ1件のシフト希望として処理状態「下書き」で登録する
4. システムはアクターに下書きとしての保存が完了したことを提示する
5. このユースケースを終了する

#### Alt-5: 対象期間の受付期間を過ぎていた場合

1. システムは受付期間を過ぎているためシフト希望を送信できないことをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー7より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト希望が登録・更新されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー6に戻る

事後条件

- シフト希望が登録・更新されていないこと

## 備考

1. 種別は「時間指定」「休日希望」の2つ(#89)
2. 1件のシフト希望は1日分。対象期間の入力された各日をそれぞれ1件のシフト希望として登録する(A-41)。種別「時間指定」のシフト希望は勤怠管理者が1件ずつ承認・却下する(2026-10-22の会話)
3. 送信した種別「時間指定」のシフト希望の処理状態は「未処理」(#87)。「未処理」のシフト希望は勤怠管理者がシフトを組むときに参照する。シフト希望を承認する(UC-207)で承認されるまでシフトは登録されない
4. 種別「休日希望」のシフト希望は承認・却下の対象にならず、勤怠管理者がシフトを組むときの参考情報として提示される。送信した「休日希望」の処理状態は「送信済」であり、「休日希望」の処理状態は「下書き」「送信済」「取り下げ」の3値を取る(A-41、2026-10-22の会話)
5. 下書きとして保存したシフト希望(処理状態「下書き」)は勤怠管理者に提示されない(#87)
6. 既存のシフト希望の変更はこのユースケースのAlt-1で行い、別のユースケースにしない(A-43、A-82)。処理状態が「承認済」「却下」の日は変更できない。処理状態が「未処理」「送信済」の日は内容を上書きできるだけで、種別を外すことはできない
7. 処理状態が「取り下げ」の日は、シフト希望が無い日と同じく入力できる。入力すると新しいシフト希望を1件登録し、取り下げたシフト希望はそのまま残す。受付期間中であれば、取り下げた希望日について再び送信できる(2026-10-22の会話)
8. 日をまたぐ希望は、希望終了時刻が希望開始時刻より前であることで表す(希望終了時刻は翌日の時刻として扱う)。希望終了時刻が希望開始時刻と同じ入力は誤りとする(#82からの導出、暫定)
9. 勤怠管理者への通知はTBD(#96)
10. 処理状態が「下書き」の日は、Alt-1で種別を外すこともできる。種別を外して送信または下書きとして保存した場合に、その日のシフト希望をどう扱うかはTBD(要起票)
11. Alt-1で「未処理」「送信済」の日の内容を変更して下書きとして保存した場合の扱いはTBD(要起票)
12. 対象期間と受付期間は、勤怠管理者がシフト希望の対象期間・受付期間を登録する(UC-217)で登録する(#88)
13. 送信した「未処理」の「時間指定」のシフト希望と「送信済」の「休日希望」のシフト希望を無効にするには、シフト希望を取り下げる(UC-315)を使う
14. 送信したシフト希望の処理状態と却下理由は、シフト希望を一覧表示する(UC-311)で提示される
