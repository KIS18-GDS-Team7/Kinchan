# UC-307 シフト希望を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を送信する(UC-307) |
| 目的 | アクターが対象期間の各日の勤務の希望をシフト希望として勤怠管理者に送信し、勤怠管理者がシフトを組むときに参照できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがホームを表示する(UC-303)またはシフト希望を一覧表示する(UC-311)で、受付期間中の対象期間を指定してシフト希望の送信を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターの所属が設定されていること(UC-105)<br>・アクターの所属に受付期間中の対象期間が登録されていること(UC-215) |
| 事後条件 | ・入力された各日について、1日分ずつのシフト希望が登録されていること<br>・登録されたシフト希望の処理状態が「未処理」になっていること<br>・シフトが登録されていないこと<br>・アクターの所属を管理先に持つ勤怠管理者にシフト希望が送信されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・ホームを表示する(UC-303)<br>・シフト希望を一覧表示する(UC-311)<br>・シフト希望を取り下げる(UC-315)<br>・シフト希望の対象期間・受付期間を登録する(UC-215)<br>・シフト希望を一覧表示する(UC-204)<br>・シフト希望を承認する(UC-205)<br>・シフト希望を却下する(UC-206) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の送信を要求する
2. システムはアクターに対象期間の各日の希望の入力を求める
3. アクターはシステムに希望を出す日の希望開始時刻・希望終了時刻を入力する
4. システムは入力されたシフト希望を検証する
5. システムはアクターに入力されたシフト希望の内容を提示し、送信の確認を求める
6. アクターはシステムに送信を指示する
7. システムは対象期間の受付期間内であるかを判定する
8. システムは希望開始時刻・希望終了時刻が入力された各日をそれぞれ1件のシフト希望として処理状態「未処理」で登録する
9. システムは、アクターの所属を管理先に持つ勤怠管理者に、シフト希望が送信されたことを通知する
10. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー2で、指定した対象期間にアクターの「取り下げ」以外のシフト希望がすでにあった場合

1. システムはアクターに対象期間の各日の「取り下げ」以外の既存のシフト希望(希望開始時刻・希望終了時刻、処理状態)を提示し、希望の入力を求める
2. システムは「承認済」「却下」のシフト希望がある日は変更できないことをアクターに提示する
3. アクターはシステムに「下書き」「未処理」のシフト希望がある日と「取り下げ」以外のシフト希望が無い日のうち、希望を出す日の希望開始時刻・希望終了時刻を入力する
4. システムは入力されたシフト希望を検証する
5. システムはアクターに入力されたシフト希望の内容を提示し、送信の確認を求める
6. アクターはシステムに送信を指示する
7. システムは入力された日の既存のシフト希望の処理状態が「下書き」「未処理」のままであることを検証する
8. システムは対象期間の受付期間内であるかを判定する
9. システムは「下書き」「未処理」の既存のシフト希望を入力された内容に更新する
10. システムは更新したシフト希望の処理状態を「未処理」に更新する
11. システムは「取り下げ」以外のシフト希望が無い日の入力をそれぞれ1件のシフト希望として処理状態「未処理」で登録する
12. システムは、アクターの所属を管理先に持つ勤怠管理者に、シフト希望が送信されたことを通知する
13. メインフロー10に進む

#### Alt-2: メインフロー4で、入力されたシフト希望に誤りがあった場合

1. システムは誤りの内容(希望を出す日が1日も無い、希望開始時刻・希望終了時刻の一方だけが入力されている、希望終了時刻が希望開始時刻と同じ)をアクターに提示する
2. メインフロー2に戻る

#### Alt-3: Alt-1の4で、入力されたシフト希望に誤りがあった場合

1. システムは誤りの内容(希望を出す日が1日も無い、希望開始時刻・希望終了時刻の一方だけが入力されている、「未処理」のシフト希望がある日の希望開始時刻・希望終了時刻が両方とも無い、希望終了時刻が希望開始時刻と同じ)をアクターに提示する
2. Alt-1の1に戻る

#### Alt-4: メインフロー6またはAlt-1の6で、アクターが送信ではなく下書きとしての保存を指示した場合

1. アクターはシステムに入力したシフト希望を下書きとして保存することを指示する
2. システムは「下書き」の既存のシフト希望を入力された内容に更新する
3. システムは「取り下げ」以外のシフト希望が無い日の入力をそれぞれ1件のシフト希望として処理状態「下書き」で登録する
4. システムはアクターに下書きとしての保存が完了したことを提示する
5. このユースケースを終了する

#### Alt-5: メインフロー7またはAlt-1の8で、対象期間の受付期間を過ぎていた場合

1. システムは受付期間を過ぎているためシフト希望を送信できないことをアクターに提示する
2. このユースケースを終了する

#### Alt-6: Alt-1の7で、入力された日の既存のシフト希望の処理状態が「下書き」「未処理」でなくなっていた場合

1. システムは既存のシフト希望の処理状態が変わったため変更できないことをアクターに提示する
2. Alt-1の1に戻る

### 例外フロー

#### Ex-1: メインフロー6またはAlt-1の6より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト希望が登録・更新されていないこと
- システムが待機状態に戻っていること

#### Ex-2: メインフロー8、Alt-1の9〜11、またはAlt-4の2・3で、システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、確認を求めるステップ(メインフロー5またはAlt-1の5)に戻る

事後条件

- シフト希望が登録・更新されていないこと
- 勤怠管理者に通知されていないこと

## 備考

1. シフト希望は希望日と希望開始時刻・希望終了時刻からなり、1件は1日分(2026-10-22の会話)。希望開始時刻・希望終了時刻の両方が無い日は希望を出さない日とし、一方だけが入力されている日は誤りとする。希望を外すとは、既存のシフト希望がある日の希望開始時刻・希望終了時刻を両方とも消すことを指す(2026-10-22の会話からの導出、暫定)
2. 対象期間の入力された各日をそれぞれ1件のシフト希望として登録する(A-41)。シフト希望は勤怠管理者が1件ずつ承認・却下する(2026-10-22の会話)
3. 送信したシフト希望の処理状態は「未処理」(#87)。「未処理」のシフト希望は勤怠管理者がシフトを組むときに参照する。シフト希望を承認する(UC-205)で承認されるまでシフトは登録されない
4. 下書きとして保存したシフト希望(処理状態「下書き」)は勤怠管理者に提示されない(#87)
5. 既存のシフト希望の変更はこのユースケースのAlt-1で行い、別のユースケースにしない(A-43、A-82)。「承認済」「却下」のシフト希望がある日は変更できない。「未処理」のシフト希望がある日は内容を上書きできるだけで、希望を外すことはできない(暫定)
6. 1日に、処理状態が「取り下げ」以外のシフト希望は1件まで。「取り下げ」のシフト希望は何件あってもよい(データとして残る)。Alt-1の判定はその日の「取り下げ」以外のシフト希望で行い、「取り下げ」以外のシフト希望がある日はその処理状態で変更できるかを分ける。「取り下げ」のシフト希望しか無い日は、シフト希望が無い日と同じに扱い、入力すると新しいシフト希望を1件登録する。取り下げたシフト希望はそのまま残す(2026-10-22の会話からの導出、暫定)。Alt-1で既存のシフト希望を提示した後に、勤怠管理者が承認・却下した、またはアクターがシフト希望を取り下げる(UC-315)で取り下げた場合はAlt-6に当たる
7. 受付期間中であれば、取り下げた希望日について再び送信できる(2026-10-22の会話)
8. 日をまたぐ希望は、希望終了時刻が希望開始時刻より前であることで表す(希望終了時刻は翌日の時刻として扱う)。希望終了時刻が希望開始時刻と同じ入力は誤りとする(#82からの導出、暫定)
9. 受付期間内であるかは、送信を指示した時点で判定する(Alt-5)
10. 送信したとき、アクターの所属を管理先に持つ勤怠管理者に通知する(#96、#84からの導出、暫定)。通知は通知を表示する(UC-317)で提示される
11. 下書きとして保存する場合(Alt-4)にも受付期間を判定するかはTBD(要起票)
12. 「下書き」のシフト希望がある日は、Alt-1で希望を外すこともできる。希望を外して送信または下書きとして保存した場合に、その日のシフト希望をどう扱うかはTBD(要起票)
13. Alt-1で「未処理」の日の内容を変更して下書きとして保存した場合の扱いはTBD(要起票)
14. 対象期間と受付期間は、勤怠管理者がシフト希望の対象期間・受付期間を登録する(UC-215)で登録する(#88)
15. シフト希望を取り下げる(UC-315)で、送信した「未処理」のシフト希望を無効にできる
16. 送信したシフト希望の処理状態と却下理由は、シフト希望を一覧表示する(UC-311)で提示される
