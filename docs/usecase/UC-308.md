# UC-308 シフトを一覧表示する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフトを一覧表示する(UC-308) |
| 目的 | アクターが、アクター自身を含む所属単位の従業員の公開済みのシフトを表示できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフトの一覧表示を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターの所属が設定されていること(UC-105) |
| 事後条件 | ・アクターにアクターの所属単位の従業員の公開済みのシフトが提示されていること |
| 拡張点 | ・アクターが指定したアクター自身の公開済みのシフトについてシフト日時変更申請の送信を要求した場合(メインフロー4の後) |
| 関連ユースケース | ・シフト日時変更申請を送信する(UC-309)≪extend≫<br>・シフトを公開する(UC-216)<br>・シフト希望を承認する(UC-205)<br>・シフトを変更する(UC-202)<br>・シフトを削除する(UC-203) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフトの一覧表示を要求する
2. システムはアクターに、アクターの所属単位の従業員の公開済みのシフトの一覧(従業員名、勤務日、開始時刻、終了時刻)を対象期間ごとに提示する
3. アクターはシステムに一覧からシフトを1件指定する
4. システムはアクターに指定されたシフトの詳細(従業員名、勤務日、開始時刻、終了時刻)を提示する

### 代替フロー

#### Alt-1: アクターが提示する対象期間を切り替えた場合

1. アクターはシステムに提示する対象期間を指定する
2. システムはアクターに指定された対象期間の公開済みのシフトの一覧(従業員名、勤務日、開始時刻、終了時刻)を提示する
3. メインフロー3に戻る

#### Alt-2: メインフロー2またはAlt-1の2で、提示する対象期間はあるが、その対象期間に公開済みのシフトが存在しなかった場合

1. システムは該当する公開済みのシフトが存在しないことをアクターに提示する
2. Alt-1の1に進む

#### Alt-3: メインフロー2で、アクターの所属に対象期間が登録されていなかった場合

1. システムは対象期間が登録されていないことをアクターに提示する
2. このユースケースを終了する

### 例外フロー

なし

## 備考

1. 提示するのは公開済みのシフトだけであり、下書きのシフトは提示しない(#87の再起票)。シフトを登録する(UC-201)で登録した下書きのシフトは、シフトを公開する(UC-216)で公開されるまで従業員に提示されない
2. シフト希望を承認する(UC-205)で登録したシフトは状態「公開」で登録され、承認した時点で提示される(#87、2026-10-22の会話)
3. 提示する範囲はアクターの所属単位の従業員(アクター自身を含む)のシフト(A-74を所属単位に読み替え)
4. 公開後にシフトを変更する(UC-202)・シフトを削除する(UC-203)で変更・削除されたシフトは、変更後の内容を提示する(#87の再起票)
5. シフトは、登録・変更の時点で勤務日が所属の対象期間に含まれる(2026-10-22の会話)
6. 一覧の単位は対象期間ごと(暫定)。最初に提示する対象期間はTBD(要起票)。公開済みのシフトが無い対象期間でも、別の対象期間に切り替えられる(Alt-2からAlt-1)
7. ユーザーの所属を編集する(UC-106)で所属を変更した後、および対象期間を変更・削除した後の、既存のシフトと「未処理」のシフト希望・シフト日時変更申請(変更前の対象期間に含まれる日を対象とするもの)の扱いはTBD(要起票)。対象になる操作は、シフトを公開する(UC-216)での下書きの公開、このユースケースでの提示、シフト希望を承認する(UC-205)・シフト日時変更申請を承認する(UC-213)での承認。対象期間の変更・削除はシフト希望の対象期間・受付期間を登録する(UC-215)でTBD
8. UC名は暫定名(旧「登録シフトを一覧表示する」。requirements.mdも改名済み)
9. シフト日時変更申請を送信する(UC-309)は、アクター自身のシフトを指定して要求する。承認された変更は、このユースケースで変更後のシフトとして提示される
