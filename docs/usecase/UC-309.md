# UC-309 シフト日時変更申請を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を送信する(UC-309) |
| 目的 | アクターがアクター自身の公開済みのシフトの勤務日・開始時刻・終了時刻の変更を、シフト日時変更申請として勤怠管理者に送信できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフトを一覧表示する(UC-308)でアクター自身のシフトを指定してシフト日時変更申請の送信を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・対象のシフトがアクター自身の公開済みのシフトであること |
| 事後条件 | ・シフト日時変更申請が登録されていること<br>・登録されたシフト日時変更申請の処理状態が「未処理」になっていること<br>・対象のシフトが変更されていないこと<br>・アクターの所属を管理先に持つ勤怠管理者にシフト日時変更申請が送信されたことが通知されていること |
| 拡張点 | なし |
| 関連ユースケース | ・シフトを一覧表示する(UC-308)<br>・シフト日時変更申請内容を一覧表示する(UC-318)<br>・シフト日時変更申請を取り下げる(UC-316)<br>・シフト日時変更申請を一覧表示する(UC-214)<br>・シフト日時変更申請を承認する(UC-215)<br>・シフト日時変更申請を却下する(UC-216) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の送信を要求する
2. システムは対象のシフトの勤務日が翌日以降かを判定する
3. システムは対象のシフトに「未処理」のシフト日時変更申請があるかを判定する
4. システムはアクターに変更前のシフト(勤務日、開始時刻、終了時刻)を提示し、変更後の勤務日・開始時刻・終了時刻と申請理由の入力を求める
5. アクターはシステムに変更後の勤務日・開始時刻・終了時刻と申請理由を入力する
6. システムは入力された内容を検証する
7. システムは変更後の勤務日が当日以降であるかを判定する
8. システムは変更後の勤務日がアクターの所属に登録された対象期間に含まれるかを判定する
9. システムは変更後の日時がアクターの他の公開済みのシフトと重複するかを判定する
10. システムはアクターに申請の内容(変更前のシフト、変更後の勤務日・開始時刻・終了時刻、申請理由)を提示し、送信の確認を求める
11. アクターはシステムに送信を指示する
12. システムはシフト日時変更申請を処理状態「未処理」で登録する
13. システムは、アクターの所属を管理先に持つ勤怠管理者に、シフト日時変更申請が送信されたことを通知する
14. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー2で、対象のシフトの勤務日が翌日以降でなかった場合

1. システムは勤務日が翌日以降のシフトだけを対象にできることをアクターに提示する
2. このユースケースを終了する

#### Alt-2: メインフロー3で、対象のシフトに「未処理」のシフト日時変更申請がすでにあった場合

1. システムは「未処理」のシフト日時変更申請があるため送信できないことをアクターに提示する
2. このユースケースを終了する

#### Alt-3: メインフロー6で、入力された内容に誤りがあった場合

1. システムは誤りの内容(申請理由が入力されていない、変更後の勤務日・開始時刻・終了時刻のいずれかが入力されていない、変更後の終了時刻が開始時刻と同じ)をアクターに提示する
2. メインフロー4に戻る

#### Alt-4: メインフロー6で、変更後の勤務日・開始時刻・終了時刻が変更前のシフトと同じだった場合

1. システムは変更前と同じ日時であるため送信できないことをアクターに提示する
2. メインフロー4に戻る

#### Alt-5: メインフロー7で、変更後の勤務日が当日より前だった場合

1. システムは変更後の勤務日が当日より前であるため送信できないことをアクターに提示する
2. メインフロー4に戻る

#### Alt-6: メインフロー8で、変更後の勤務日がアクターの所属に登録された対象期間に含まれなかった場合

1. システムは変更後の勤務日が対象期間に含まれないことをアクターに提示する
2. メインフロー4に戻る

#### Alt-7: メインフロー9で、変更後の日時がアクターの他の公開済みのシフトと重複していた場合

1. システムは重複する公開済みのシフトをアクターに提示する
2. メインフロー10に進む

### 例外フロー

#### Ex-1: メインフロー11より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト日時変更申請が登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト日時変更申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー10に戻る

事後条件

- シフト日時変更申請が登録されていないこと
- 勤怠管理者に通知されていないこと

## 備考

1. このユースケースの記述はdocxに無く、シフト日時変更申請を一覧表示する(UC-214)・シフト日時変更申請を承認する(UC-215)・シフト日時変更申請を却下する(UC-216)の項目(変更前のシフト、変更後の勤務日・開始時刻・終了時刻、申請理由)から定めた
2. 対象はアクター自身の公開済みで、勤務日が翌日以降のシフト(A-36)。勤怠管理者がシフトを変更する(UC-204)には期限が無い
3. 申請理由は必須(A-62)。変更前と同じ日時への変更は受け付けない(A-83)
4. 変更後の勤務日は、アクターの所属に登録された対象期間に含まれる日に限る(Alt-6。2026-10-22の会話)
5. 変更後の勤務日が当日より前の場合は送信できない(Alt-5。A-77からの導出、暫定)。シフト日時変更申請を承認する(UC-215)でも、変更後の勤務日が当日より前の申請は承認されない
6. 変更後の日時がアクターの他の公開済みのシフトと重複していても送信できる(A-62)。重複の判定は公開済みのシフトだけを対象にし(#87の再起票からの導出、暫定)、下書きのシフトは提示しない(#87の再起票)。重複は勤怠管理者がシフト日時変更申請を一覧表示する(UC-214)・シフト日時変更申請を承認する(UC-215)でも判定する
7. 同じシフトに「未処理」のシフト日時変更申請がある間は送信できない(A-62)。取り下げた後は同じシフトについて再び送信できる
8. 日をまたぐ変更後の日時は、終了時刻が開始時刻より前であることで表す(終了時刻は翌日の時刻として扱う)(#82からの導出、暫定)
9. 送信したとき、アクターの所属を管理先に持つ勤怠管理者に通知する(#96、#84からの導出、暫定)。通知の方式はアプリ内通知(#81)
10. 承認されるまでシフトは変更されない。承認された変更後のシフトはシフトを一覧表示する(UC-308)で提示される
11. 送信したシフト日時変更申請の処理状態と却下理由は、シフト日時変更申請内容を一覧表示する(UC-318)で提示される(2026-10-22の会話)
12. シフト日時変更申請を取り下げる(UC-316)で、送信した「未処理」のシフト日時変更申請を無効にできる。取り下げは、シフト日時変更申請内容を一覧表示する(UC-318)から要求する
