# UC-309 シフト日時変更申請を送信する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を送信する(UC-309) |
| 目的 | 従業員がアクター自身の公開済みのシフトの勤務日・開始時刻・終了時刻の変更を、シフト日時変更申請として勤怠管理者に送信できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフトを一覧表示する(UC-308)でアクター自身のシフトを指定してシフト日時変更申請の送信を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・対象のシフトがアクター自身の公開済みのシフトであること |
| 事後条件 | ・シフト日時変更申請が登録されていること<br>・登録されたシフト日時変更申請の処理状態が「未処理」になっていること<br>・対象のシフトが変更されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・シフトを一覧表示する(UC-308)<br>・シフト日時変更申請を取り下げる(UC-316)<br>・シフト日時変更申請を一覧表示する(UC-214)<br>・シフト日時変更申請を承認する(UC-215)<br>・シフト日時変更申請を却下する(UC-216) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の送信を要求する
2. システムはアクターにアクターの送信済みのシフト日時変更申請の一覧(変更前のシフト、変更後の勤務日・開始時刻・終了時刻、処理状態、却下理由(「却下」のとき)、送信日時)を提示する
3. システムはアクターに変更前のシフト(勤務日、開始時刻、終了時刻)を提示し、変更後の勤務日・開始時刻・終了時刻と申請理由の入力を求める
4. アクターはシステムに変更後の勤務日・開始時刻・終了時刻と申請理由を入力する
5. システムは入力された内容を検証する
6. システムは変更後の日時がアクターの他のシフトと重複するかを判定する
7. システムはアクターに申請の内容(変更前のシフト、変更後の勤務日・開始時刻・終了時刻、申請理由)を提示し、送信の確認を求める
8. アクターはシステムに送信を指示する
9. システムはシフト日時変更申請を処理状態「未処理」で登録する
10. システムはアクターに送信が完了したことを提示する

### 代替フロー

#### Alt-1: 対象のシフトの勤務日が翌日以降でなかった場合

1. システムは勤務日が翌日以降のシフトだけを対象にできることをアクターに提示する
2. このユースケースを終了する

#### Alt-2: 対象のシフトに「未処理」のシフト日時変更申請がすでにあった場合

1. システムは「未処理」の申請があるため送信できないことと、その申請の内容をアクターに提示する
2. このユースケースを終了する

#### Alt-3: 入力された内容に誤りがあった場合

1. システムは誤りの内容(申請理由が入力されていない、変更後の勤務日・開始時刻・終了時刻のいずれかが入力されていない、変更後の終了時刻が開始時刻と同じ)をアクターに提示する
2. メインフロー3に戻る

#### Alt-4: 変更後の勤務日・開始時刻・終了時刻が変更前のシフトと同じだった場合

1. システムは変更前と同じ日時であるため送信できないことをアクターに提示する
2. メインフロー3に戻る

#### Alt-5: 変更後の日時がアクターの他のシフトと重複していた場合

1. システムは重複するシフトをアクターに提示する
2. メインフロー7に進む

### 例外フロー

#### Ex-1: メインフロー8より前にアクターが送信のキャンセルを要求した場合

1. アクターはシステムに送信のキャンセルを要求する
2. システムは入力された内容を破棄する
3. システムはアクターにキャンセルが完了したことを提示する
4. システムは待機状態に戻る

事後条件

- 入力された内容が破棄されていること
- シフト日時変更申請が登録されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト日時変更申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムは入力された内容を保持したまま、メインフロー7に戻る

事後条件

- シフト日時変更申請が登録されていないこと

## 備考

1. このユースケースの記述は docx に無く、シフト日時変更申請を一覧表示する(UC-214)・承認する(UC-215)・却下する(UC-216)の項目(変更前のシフト、変更後の勤務日・開始時刻・終了時刻、申請理由)から定めた
2. 対象はアクター自身の公開済みで、勤務日が翌日以降のシフト(A-36)。勤怠管理者によるシフトの変更(UC-204)には期限が無い
3. 申請理由は必須(A-62)。変更前と同じ日時への変更は受け付けない(A-83)
4. 変更後の日時がアクターの他のシフトと重複していても送信できる。重複は勤怠管理者がシフト日時変更申請を一覧表示する(UC-214)・承認する(UC-215)で判定する(A-62)
5. 同じシフトに「未処理」のシフト日時変更申請がある間は送信できない(A-62)。取り下げた後は同じシフトについて再び送信できる
6. 日をまたぐ変更後の日時は、終了時刻が開始時刻より前であることで表す(終了時刻は翌日の時刻として扱う。#82)
7. 承認されるまでシフトは変更されない。承認された変更後のシフトはシフトを一覧表示する(UC-308)で提示される
8. 勤怠管理者への通知はTBD(#96)
9. 変更後の勤務日を当日以前にできるかはTBD(要起票)
10. 従業員が自分のシフト日時変更申請を一覧表示するユースケースは無い。暫定でこのユースケースのメインフロー2で送信済みの申請の一覧(処理状態、却下理由を含む)を提示し、シフト日時変更申請を取り下げる(UC-316)の起点とする(A-63)
11. 送信した「未処理」のシフト日時変更申請を無効にするには、シフト日時変更申請を取り下げる(UC-316)を使う
