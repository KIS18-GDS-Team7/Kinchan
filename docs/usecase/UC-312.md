# UC-312 休憩を打刻する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 休憩を打刻する(UC-312) |
| 目的 | アクターが休憩開始・休憩終了の打刻を行い、休憩の区切りを勤怠記録に残せる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターが打刻の種類(「休憩開始」または「休憩終了」)を指定して打刻を要求する |
| 事前条件 | ・アクターがログインしていること(UC-301)<br>・アクターの所属が設定されていること(UC-105) |
| 事後条件 | ・打刻(種類、打刻日時)が記録されていること<br>・アクターの勤務ステータスが、打刻の種類が「休憩開始」のとき「休憩中」、「休憩終了」のとき「出勤中」になっていること |
| 拡張点 | なし |
| 関連ユースケース | ・出退勤を打刻する(UC-304)<br>・勤怠修正申請を送信する(UC-306)<br>・勤怠記録を一覧表示する(UC-313) |

## イベントフロー

### メインフロー

1. アクターはシステムに打刻の種類(「休憩開始」または「休憩終了」)を指定して打刻を要求する
2. システムは指定された打刻の種類とアクターの現在の勤務ステータスの整合を判定する
3. システムは打刻(種類、打刻日時)を記録する
4. システムはアクターの勤務ステータスを、打刻の種類が「休憩開始」のとき「休憩中」に、「休憩終了」のとき「出勤中」に更新する
5. システムはアクターに打刻の結果(打刻の種類、打刻日時、更新後の勤務ステータス)を提示する

### 代替フロー

#### Alt-1: メインフロー2で、指定された打刻の種類がアクターの現在の勤務ステータスと整合しなかった場合

1. システムは打刻できないことと、その理由をアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー3・4で、システムが打刻または勤務ステータスの保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムはこのユースケースを中断する

事後条件

- 打刻が記録されていないこと
- 勤務ステータスが変更されていないこと

## 備考

1. 打刻の種類は「出勤」「退勤」「休憩開始」「休憩終了」の4値であり、このユースケースでは「休憩開始」「休憩終了」を扱う。「出勤」「退勤」は出退勤を打刻する(UC-304)で扱う(#78、A-67)
2. 打刻の種類と勤務ステータスの整合は、「休憩開始」は勤務ステータスが「出勤中」のとき、「休憩終了」は「休憩中」のときに整合するものとする(A-67)
3. 勤務ステータスの更新は独立したユースケースにせず、このユースケースと出退勤を打刻する(UC-304)のメインフローのステップとして書く(2026-10-22の会話)。勤務ステータスの3値と、打刻によってのみ変わることなどの規則は出退勤を打刻する(UC-304)の備考を参照
4. 打刻日時は打刻を要求した時点の日時であり、秒まで記録し、秒まで提示する(#74、A-59)
5. 休憩時間は、休憩開始から休憩終了までの時間の合計と、同じ日の勤務と勤務の間の空白時間の合計である。勤務時間は、各勤務(出勤打刻から退勤打刻まで)の時間の合計から勤務の中の休憩の時間を引いたものであり、空白時間は引かない。いずれも各打刻の秒を切り捨てて分単位で計算する(#78からの導出、暫定。A-59)。空白時間の上限はTBD(要起票)
6. 休憩は打刻で記録する(#78)
7. 日をまたぐ勤務の休憩も、出勤打刻を行った日の勤怠記録に属する(#82)
8. 新設のユースケースであり、IDは仮。requirements.mdのUC一覧にも追記済み
9. 誤った打刻は、勤怠修正申請を送信する(UC-306)で勤怠修正申請を送信し、勤怠管理者の承認を得て修正する
