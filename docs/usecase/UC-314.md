# UC-314 勤怠修正申請を取り下げる

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | 勤怠修正申請を取り下げる(UC-314) |
| 目的 | アクターが送信した「未処理」の勤怠修正申請を無効にし、勤怠管理者の処理の対象から外せる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターが勤怠修正申請内容を一覧表示する(UC-310)で「未処理」の勤怠修正申請を指定して取り下げを要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・対象の勤怠修正申請がアクター自身のものであること<br>・対象の勤怠修正申請の処理状態が「未処理」であること |
| 事後条件 | ・勤怠修正申請の処理状態が「取り下げ」になっていること<br>・勤怠修正申請のデータが残っていること<br>・勤怠記録が修正されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・勤怠修正申請内容を一覧表示する(UC-310)<br>・勤怠修正申請を送信する(UC-306)<br>・勤怠修正申請を承認する(UC-210)<br>・勤怠修正申請を却下する(UC-211) |

## イベントフロー

### メインフロー

1. アクターはシステムに勤怠修正申請の取り下げを要求する
2. システムはアクターに取り下げる勤怠修正申請の内容を提示し、取り下げの確認を求める
3. アクターはシステムに取り下げを指示する
4. システムは勤怠修正申請の処理状態を「取り下げ」に更新する
5. システムはアクターに取り下げが完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー2で、対象の勤怠修正申請の処理状態が「未処理」でなくなっていた場合

1. システムは対象の勤怠修正申請を取り下げできないことをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが取り下げのキャンセルを要求した場合

1. アクターはシステムに取り下げのキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- 勤怠修正申請の処理状態が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムが勤怠修正申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー3に戻る

事後条件

- 勤怠修正申請の処理状態が変更されていないこと

## 備考

1. 取り下げられるのは処理状態が「未処理」の勤怠修正申請だけとする
2. データは消さず、処理状態を「取り下げ」に更新する(A-6)。勤怠修正申請内容を一覧表示する(UC-310)では、取り下げた勤怠修正申請を処理状態「取り下げ」で提示する
3. Alt-1は、一覧を提示した後に、勤怠管理者が承認・却下した、またはアクターがすでに取り下げていた場合に当たる
4. 勤怠管理者への通知はTBD(#96)
5. 新設のユースケースであり、IDは仮。requirements.mdには無く、追記は別途
6. 勤怠修正申請を承認する(UC-210)・勤怠修正申請を却下する(UC-211)の、対象の処理状態が「未処理」でなくなっていた場合の代替フローは取り下げられた勤怠修正申請を前提にしており、その取り下げをこのユースケースで扱う
7. 取り下げた後は、勤怠修正申請を送信する(UC-306)で同じ対象日の勤怠修正申請を再び送信できる
