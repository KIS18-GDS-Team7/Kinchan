# UC-315 シフト希望を取り下げる

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト希望を取り下げる(UC-315) |
| 目的 | 従業員が送信した「未処理」のシフト希望を、勤怠管理者が処理する前に自分で無効にできる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフト希望を一覧表示する(UC-311)で「未処理」のシフト希望を指定して取り下げを要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・対象のシフト希望がアクター自身のものであること<br>・対象のシフト希望の処理状態が「未処理」であること |
| 事後条件 | ・対象のシフト希望の処理状態が「取り下げ」になっていること<br>・対象のシフト希望が削除されていないこと<br>・シフトが登録されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・シフト希望を一覧表示する(UC-311)<br>・シフト希望を送信する(UC-307)<br>・シフト希望を一覧表示する(UC-206)<br>・シフト希望を承認する(UC-207)<br>・シフト希望を却下する(UC-208) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト希望の取り下げを要求する
2. システムはアクターに取り下げるシフト希望の内容を提示し、取り下げの確認を求める
3. アクターはシステムに取り下げを指示する
4. システムはシフト希望の処理状態を「取り下げ」に更新する
5. システムはアクターに取り下げが完了したことを提示する

### 代替フロー

#### Alt-1: 対象のシフト希望がすでに処理済み(「承認済」「却下」)だった場合

1. システムは対象のシフト希望が取り下げできない状態であることをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが取り下げのキャンセルを要求した場合

1. アクターはシステムに取り下げのキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト希望の処理状態が変わっていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト希望の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. システムはメインフロー2に戻る

事後条件

- シフト希望の処理状態が変わっていないこと

## 備考

1. シフト希望を承認する(UC-207)・却下する(UC-208)の代替フローが取り下げられた状態を前提にしているのに取り下げるユースケースが無い、という #87 の指摘により新設した。ID は仮であり、確定は別途
2. 取り下げられるのは処理状態が「未処理」のシフト希望だけ。取り下げたシフト希望は削除せず、処理状態を「取り下げ」にする(A-6)
3. 取り下げの単位は1日分(シフト希望1件)ずつ(暫定)
4. 「下書き」のシフト希望は取り下げの対象外。シフト希望を送信する(UC-307)の Alt-1 で種別を外す
5. 勤怠管理者への通知はTBD(#96)
6. 取り下げたシフト希望は、シフト希望を一覧表示する(UC-311)に処理状態「取り下げ」で提示される。勤怠管理者のシフト希望を承認する(UC-207)・却下する(UC-208)では処理済みとして扱われ、承認・却下できない
7. 取り下げた後、受付期間中であれば同じ希望日についてシフト希望を送信する(UC-307)で再び送信できる
