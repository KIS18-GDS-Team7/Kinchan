# UC-316 シフト日時変更申請を取り下げる

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請を取り下げる(UC-316) |
| 目的 | アクターが送信した「未処理」のシフト日時変更申請を、勤怠管理者が処理する前に無効にできる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフト日時変更申請内容を一覧表示する(UC-318)で「未処理」のシフト日時変更申請を指定して取り下げを要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110)<br>・対象のシフト日時変更申請がアクター自身のものであること<br>・対象のシフト日時変更申請の処理状態が「未処理」であること |
| 事後条件 | ・対象のシフト日時変更申請の処理状態が「取り下げ」になっていること<br>・対象のシフト日時変更申請が削除されていないこと<br>・シフトが変更されていないこと |
| 拡張点 | なし |
| 関連ユースケース | ・シフト日時変更申請内容を一覧表示する(UC-318)<br>・シフト日時変更申請を送信する(UC-309)<br>・シフトを一覧表示する(UC-308)<br>・シフト日時変更申請を一覧表示する(UC-214)<br>・シフト日時変更申請を承認する(UC-215)<br>・シフト日時変更申請を却下する(UC-216) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の取り下げを要求する
2. システムはアクターに取り下げるシフト日時変更申請の内容を提示し、取り下げの確認を求める
3. アクターはシステムに取り下げを指示する
4. システムはシフト日時変更申請の処理状態を「取り下げ」に更新する
5. システムはアクターに取り下げが完了したことを提示する

### 代替フロー

#### Alt-1: メインフロー2で、対象のシフト日時変更申請の処理状態が「未処理」でなくなっていた場合

1. システムは対象のシフト日時変更申請が取り下げできない状態であることをアクターに提示する
2. このユースケースを終了する

### 例外フロー

#### Ex-1: メインフロー3より前にアクターが取り下げのキャンセルを要求した場合

1. アクターはシステムに取り下げのキャンセルを要求する
2. システムはアクターにキャンセルが完了したことを提示する
3. システムは待機状態に戻る

事後条件

- シフト日時変更申請の処理状態が変更されていないこと
- システムが待機状態に戻っていること

#### Ex-2: システムがシフト日時変更申請の保存に失敗した場合

1. システムはアクターに保存に失敗したことを提示する
2. メインフロー3に戻る

事後条件

- シフト日時変更申請の処理状態が変更されていないこと

## 備考

1. シフト日時変更申請を承認する(UC-215)・シフト日時変更申請を却下する(UC-216)の代替フローが取り下げられた状態を前提にしているのに取り下げるユースケースが無いため新設した(2026-10-21の会話)
2. 取り下げられるのは処理状態が「未処理」のシフト日時変更申請だけ。取り下げた申請は削除せず、処理状態を「取り下げ」にする(A-6)
3. 起点はシフト日時変更申請内容を一覧表示する(UC-318)とする(A-63、2026-10-22の会話)
4. Alt-1は、一覧を提示した後に、勤怠管理者が承認・却下した、またはアクターがすでに取り下げていた場合に当たる
5. 勤怠管理者への通知はTBD(#96)
6. 新設のユースケースであり、IDは仮。requirements.mdには無く、追記は別途
7. 取り下げたシフト日時変更申請は、シフト日時変更申請内容を一覧表示する(UC-318)に処理状態「取り下げ」で提示される。勤怠管理者はシフト日時変更申請を承認する(UC-215)・シフト日時変更申請を却下する(UC-216)で取り下げた申請を承認・却下できない
8. 取り下げた後、同じシフトについてシフト日時変更申請を送信する(UC-309)で再び送信できる
