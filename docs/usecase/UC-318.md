# UC-318 シフト日時変更申請内容を一覧表示する

| 項目 | 内容 |
| --- | --- |
| ユースケース名 | シフト日時変更申請内容を一覧表示する(UC-318) |
| 目的 | アクターがアクター自身の送信したシフト日時変更申請の一覧と詳細(処理状態、却下理由を含む)を表示し、取り下げの対象を指定できる状態にする |
| アクター | 従業員 |
| 開始条件 | アクターがシフト日時変更申請の一覧の表示を要求する |
| 事前条件 | ・アクターがログインしていること(UC-001)<br>・アクターの所属が設定されていること(UC-110) |
| 事後条件 | ・アクターにアクター自身のシフト日時変更申請の一覧と、指定したシフト日時変更申請の詳細が提示されていること |
| 拡張点 | ・シフト日時変更申請の取り下げ(メインフロー4の後) |
| 関連ユースケース | ・シフト日時変更申請を取り下げる(UC-316)≪extend≫<br>・シフト日時変更申請を送信する(UC-309)<br>・シフトを一覧表示する(UC-308)<br>・通知を表示する(UC-317)<br>・シフト日時変更申請を承認する(UC-215)<br>・シフト日時変更申請を却下する(UC-216) |

## イベントフロー

### メインフロー

1. アクターはシステムにシフト日時変更申請の一覧の表示を要求する
2. システムはアクターにアクター自身のシフト日時変更申請の一覧(変更前のシフト(勤務日、開始時刻、終了時刻)、変更後の勤務日・開始時刻・終了時刻、処理状態、送信日時)を提示する
3. アクターはシステムに一覧からシフト日時変更申請を1件指定する
4. システムはアクターに指定されたシフト日時変更申請の詳細(変更前のシフト(勤務日、開始時刻、終了時刻)、変更後の勤務日・開始時刻・終了時刻、申請理由、処理状態、却下理由(「却下」のとき)、送信日時)を提示する

### 代替フロー

#### Alt-1: メインフロー2で、該当するシフト日時変更申請が存在しなかった場合

1. システムは該当するシフト日時変更申請が存在しないことをアクターに提示する
2. このユースケースを終了する

#### Alt-2: アクターが条件(期間、処理状態)を指定して探す場合

1. アクターはシステムに条件を指定する
2. システムは指定された条件を検証する
3. システムはアクターに条件に合うシフト日時変更申請の一覧を提示する
4. メインフロー3に戻る

#### Alt-3: Alt-2の2で、指定された期間の開始日が終了日より後だった場合

1. システムは期間の指定に誤りがあることをアクターに提示する
2. Alt-2の1に戻る

### 例外フロー

なし

## 備考

1. 一覧は処理状態にかかわらず、アクター自身のすべてのシフト日時変更申請(「未処理」「承認済」「却下」「取り下げ」)を提示する
2. 却下理由は処理状態が「却下」のときに提示する(A-63)
3. 取り下げたシフト日時変更申請はデータを消さず、処理状態「取り下げ」で提示する(A-6)
4. 条件の期間は変更前のシフトの勤務日で絞る(暫定)
5. アクターがアクター自身の送信したシフト日時変更申請の処理状態と却下理由を表示するユースケースとして、勤怠修正申請内容を一覧表示する(UC-310)と対称に新設した(A-63、2026-10-22の会話)
6. 新設のユースケースであり、IDは仮。requirements.mdには無く、追記は別途
7. このユースケースはシフト日時変更申請を取り下げる(UC-316)の起点である。取り下げられるのは処理状態が「未処理」のシフト日時変更申請だけ
8. シフト日時変更申請を送信する(UC-309)は、シフトを一覧表示する(UC-308)から要求する。このユースケースからは送信・変更できない
9. 承認結果・却下結果は通知としても作られ、通知を表示する(UC-317)で提示される
