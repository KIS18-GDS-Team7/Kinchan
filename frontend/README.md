# Kinchan フロントエンドモック

機能と処理条件は GitHub の `main` にある要件定義・ユースケースを基準とした静的モックです。画面遷移は [mock/generic-kintai](https://github.com/KIS18-GDS-Team7/Kinchan/tree/fc15979a4ad222ae3c15399a6f2b9526a6c6514a/mock) に寄せ、従業員・勤怠管理者・マスタ管理者のホームとメニューを分けています。

[公開フロントエンドモックを開く](https://kis18-gds-team7.github.io/Kinchan/frontend/)（GitHub ログイン・ローカル起動不要）

## デモ用ログイン

| 画面に表示される名前 | ユーザーID | パスワード | 権限・用途 |
| --- | --- | --- | --- |
| 田中 陽菜 | `emp01` | `password` | 従業員：打刻、シフト、申請、勤怠記録 |
| 鈴木 大輔 | `emp02` | `password` | 従業員：本日の公開済みシフトがない場合の打刻不可表示 |
| 佐藤 健一 | `manager01` | `password` | 従業員＋勤怠管理者：管理先のシフト、申請、勤務実態 |
| 山本 恵子 | `admin01` | `password` | 従業員＋マスタ管理者：ユーザー管理 |

ログイン画面の「モック用デモアカウント」で名前を押すと、ユーザーIDとパスワードが自動で入力されます。その後「ログイン」を押してください。表のIDとパスワードはモック専用です。

ログイン直後は、勤怠管理者（`manager01`）・マスタ管理者（`admin01`）を含め、全員が自分の打刻画面を開きます。管理操作を行うときは「表示する画面」のボタンで、本人の権限に対応する管理画面に切り替えます。同じアカウントのまま表示を切り替え、権限や操作範囲は変更しません。

勤怠管理者は「シフト管理」から登録・変更・削除、対象期間・受付期間の登録、下書きの公開を試せます。「シフト希望」「勤怠修正申請」「シフト日時変更申請」はそれぞれ独立した一覧から1件ずつ承認・却下できます。

従業員は「シフト」で対象期間を選ぶと、月カレンダーに日ごとの人数・シフト件数を表示します。日付を押すと、その日の全員の公開済みシフトを人ごとにまとめて表示します。同じ人が1日に複数のシフトに入る場合も、すべての勤務時間を表示します。自分のシフトは「自分」のラベルで区別します。対象期間が複数月にまたがる場合は、その範囲内で前後の月に切り替えられます。

勤怠管理者の「シフト管理」は、縦が従業員、横が選択した対象期間の日付の表です。従業員名と日付を固定し、表の中を横・縦にスクロールできます。1人・1日の複数シフトも省略せず、「公開」「下書き」を文字と色で表示します。勤務時間を押すと既存の詳細・変更・削除へ進めます。日付を選択すると、その日を入力済みにして既存の登録画面へ進めます。「—」はシフトなしを表し、休日の判定はしません。従業員・勤怠管理者とも「一覧」への切り替えができます。

重複するシフトは、エラーや変更申請の確認・詳細に勤務日・開始時刻・終了時刻を表示します。従業員には自分の公開済みシフトだけを表示します。管理者のシフト希望一覧には所属単位、勤怠修正・シフト日時変更申請一覧には申請理由を表示します。勤怠修正申請の時刻差は、各公開済みシフトと各勤務を明示し、重ならない勤務についても分で表示します。

却下理由は、[GitHubの参照モック](https://github.com/KIS18-GDS-Team7/Kinchan/blob/fc15979a4ad222ae3c15399a6f2b9526a6c6514a/mock/js/store.js#L996) にある「申請内容とシフト・打刻記録が一致しないため」を定型文として挿入でき、その後も自由に編集できます。未決の期限や削除された規則に依存する文面は使用しません。キャンセルすると入力を破棄し、キャンセル完了を表示します。詳細を閉じるだけの場合はキャンセル完了を表示しません。根拠と表示の判断は [ADR-0030](https://github.com/KIS18-GDS-Team7/Kinchan/blob/feat/frontend-mock/docs/ADR/0030-usecase-feedback-in-mock.md) に記録しています。

従業員の下部メニューは「ホーム・勤怠・シフト・申請・メニュー」です。「申請」から各申請一覧とシフト希望提出へ進みます。マスタ管理者は「ホーム・ユーザー一覧・ユーザー登録」を使い、登録完了後はユーザー詳細へ進みます。

デモ日時は 2026-10-14 10:30 から始まります。たとえば、佐藤さんで10月の下書きシフトを公開し、同じタブでログアウトして鈴木さんに切り替えると、鈴木さん宛ての通知から公開されたシフトを開けます。操作データはタブ内だけに保持され、再読み込みで初期状態に戻ります。実在するユーザーID・パスワードや勤怠情報を入力しないでください。

## ローカルで起動

リポジトリのルートで実行します。

```sh
python3 -m http.server 8001 --bind 127.0.0.1 --directory mock
```

ブラウザで [http://127.0.0.1:8001/](http://127.0.0.1:8001/) を開きます。ビルドやパッケージのインストールは不要です。

## 反映したGitHub上の決定

- 画面遷移は利用者指定の `mock/generic-kintai` を参照し、権限に対応した画面だけを選択・表示する
- すべてのユーザーは従業員として振る舞い、勤怠管理者・マスタ管理者は追加権限とする
- 従業員は下部タブバー、勤怠管理者・マスタ管理者はPCで左サイドバー、狭い画面では画面選択を表示する
- 状態に合う打刻操作だけを表示し、打刻時刻は秒まで表示する
- 従業員用の勤怠記録・申請と、勤怠管理者用の勤務実態・各申請一覧を別の画面に分ける
- シフト希望は複数日を選び、同じ時間をまとめて入力できる
- 申請履歴は変更前と変更後、処理状態を並べる
- 申請の取り下げ、宛先別の通知、勤務実態の集計と36協定の警告を画面に含める
- Noto Sans JP、44px以上の操作領域、状態色と文字ラベルを併用する

## モックで扱わないもの

GitHub上で未決または対象外と明記されたため、次は実装していません。

- PWAインストール
- 位置情報取得・打刻場所の制限
- Webプッシュ通知
- 申請の一括承認
- シフト希望のパターン登録・前月コピー
- バックエンド通信、永続化、認証・認可の実処理
- 前月分の勤怠修正申請の締切日、打刻漏れの自動判定時点、通知の既読、削除済みシフトへの通知リンクなど、ユースケースで TBD とされた条件

参照先にある自己パスワード変更、勤務可能時間・休憩時間の設定、人員不足の独自判定、通知の既読処理などは取り込んでいません。画面遷移を参照しても、`main` のユースケースにない機能やTBDの値は追加しません。
