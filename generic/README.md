# Kinchan UC モック(パターンA: 一般的な勤怠アプリの慣行で補完)

requirements.md 5 章の UC を画面化した静的モック。曖昧・未定義な箇所は一般的な勤怠 SaaS(ジョブカン勤怠、KING OF TIME、freee 勤怠、Airシフト等)の慣行に寄せて埋め、その判断を「判断ログ」に記録した。画面上の「補完 #n」バッジは判断ログ #n に対応する。

## 起動方法

- `mock/index.html` をブラウザで直接開く(`file://`)。ビルド・サーバー・外部 CDN は不要
- サーバー経由で開く場合: `cd mock && python3 -m http.server 8000` → <http://localhost:8000/>
- ログイン画面の「デモアカウント」で 3 ロールを選べる。画面上部の黄色いデモ操作バー(製品の画面ではない)からもワンクリックで切り替えられる

| ロール | 氏名 | ユーザーID / パスワード | 備考 |
| --- | --- | --- | --- |
| 従業員 | 田中 陽菜 | `tanaka` / `staff1234` | 駅前店。スマホ幅で表示 |
| 勤怠管理者 | 佐藤 美咲 | `sato` / `kintai1234` | 駅前店の店長。従業員権限も保持(判断ログ #1) |
| 管理者 | 山本 健一 | `yamamoto` / `admin1234` | 本部 |

その他のユーザー: 鈴木・高橋・伊藤(駅前店 従業員)、渡辺(北口店 勤怠管理者)、中村・小林(北口店 従業員)、加藤(所属店舗・勤務可能時間・休憩時間が未設定)。パスワードは従業員 `staff1234`、勤怠管理者 `kintai1234`。

- デモ日時は 2026/10/14(水) 13:20 を起点に実時間で進む(当月 = 2026 年 10 月、シフト希望は 11 月分を受付中)
- データはページ内メモリのみで全ロール共有。リロードまたはデモ操作バーの「データ初期化」で初期状態に戻る
- デモ操作バー: ロール切替 / シフト希望を受付期間外にする(UC-307 のボタン非表示の確認用)/ 通信エラーを発生させる(各 UC の通信エラー系の例外フローの確認用)/ 判断ログ一覧 / データ初期化
- 「補完 #n」バッジ: ホバーまたはクリックで判断ログ #n(曖昧点・採用した扱い・根拠)を表示。エラー表示の右の小さなタグ(例: `UC-304 Ex-1`)は、どの代替・例外フローに当たるかの注記
- 動作確認用: `index.html?as=<ユーザーID>#/<画面>` で自動ログイン(例: `index.html?as=sato#/mgr/hopes`)

### ロール横断フローのデモ手順

1. 勤怠修正申請: 田中でログイン →「勤怠」タブ → 10/7(打刻漏れ)の「修正申請」→ 退勤時刻と申請理由を入力して送信 → デモ操作バーで「勤怠管理者(佐藤)」→「勤怠修正申請」→ 田中の申請を選んで承認 →「従業員(田中)」に戻すと、通知(ベル)・勤怠修正申請一覧の状態「承認済」・勤怠記録一覧の 10/7「修正済み」に反映
2. シフト希望: 田中 → ホームの「シフト希望を提出」で 11 月分を編集・送信 → 佐藤 →「シフト希望」で承認(シフトに登録)/ 却下(理由必須)→ 田中のシフト希望一覧・登録シフト一覧(11 月)に反映
3. シフト日時変更申請: 田中 →「シフト」タブで自分の翌日以降のシフトを選び申請 → 佐藤 →「シフト日時変更申請」で承認 → シフト表と田中の登録シフト一覧が変更後の日時になる
4. 打刻: 田中 → ホームで「出勤」→ 佐藤 → ホーム・勤務実態一覧で田中が「出勤中」になる
