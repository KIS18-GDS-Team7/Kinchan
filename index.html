Kinchan UC モック

UC の洗い出しと認識合わせのための、見た目だけ動作するモック 2 種。同じドキュメントから異なる方針で作成し、差分で曖昧な箇所を炙り出す。

A一般的な勤怠アプリに寄せる

ドキュメントに明記された振る舞いには従い、曖昧・未定義な箇所だけを一般的な勤怠 SaaS の慣行で補完。

  • 補完箇所にはバッジ 補完 #n(ホバー / クリックで理由)
  • #/decisions に判断ログ一覧
  • ?as=<ユーザーID> で自動ログイン
モックを開く README・判断ログ

Bドキュメントに忠実

requirements.md / ADR / UC 詳細に書かれていることだけを画面化。書かれていないものは補完せず、未定義として残す。

  • 未定義箇所は破線枠 TBD #n、矛盾箇所は 矛盾 #n
  • 記載のない分岐に到達すると「未定義」ダイアログ
  • 画面上部「デモ操作」で例外フロー・受付期間を切替
モックを開く README・判断ログ

見方

  1. ログイン画面でロール(従業員 / 管理者 / 勤怠管理者)のデモアカウントを選ぶ。従業員画面はスマホ幅、他は PC 幅を想定
  2. 同じ UC を A と B で開き、A の「補完」と B の「TBD / 矛盾」が付いている箇所を比べる。そこがドキュメントで決まっていない箇所
  3. 各 README の「判断ログ」の # と画面上のバッジ番号は対応している
